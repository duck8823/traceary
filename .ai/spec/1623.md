## Structure-Behavior Design Note

### Requirement summary
- Purpose: produce strict, sanitized evidence that legacy literal-search membership and the additive tiered continuation chain agree at one repository revision.
- Current state: the capacity benchmark measures representative queries, while tiered-search correctness is covered only by tests and has no operator artifact.
- Expected behavior: accept private criteria only from stdin or a mode-0600 manifest; exhaust every legacy offset page and authenticated tiered continuation; compare membership sets after both chains complete; reject duplicates, stalled progress, revision/dirty mismatches, unknown artifact fields, and unsanitized diagnostics.
- Non-goals: changing either search implementation, making tiered search authoritative, changing the existing benchmark/baseline schemas, or publishing queries, IDs, paths, cursors, or raw errors.

### Conceptual model
| Concept | State | Behavior | Constraint / invariant |
|---|---|---|---|
| Private parity manifest | criteria, page/budget limits, expected Git state | validates input before store access | stdin or regular 0600 file; unknown fields rejected; never copied to output |
| Search chain | page count, item count, opaque next position | exhausts legacy offsets or authenticated continuations | every page makes strict progress; no duplicate member in a chain |
| Comparison | two completed membership sets | reports equality without identifiers | `comparison_contract=membership_set/v1`; equality only after both chains complete |
| Censored outcome | passed, mismatch, timeout, failed | preserves diagnostic precedence | `failed > timeout > mismatch > passed`; incomplete timings are lower bounds |
| Evidence artifact | revision state and aggregate metrics | supports CI/operator validation | fixed schema; unknown/forbidden fields rejected; no self-reference to an artifact path |

### Responsibility assignment
| Responsibility | Owner | Reason to change | Not owner / reason |
|---|---|---|---|
| CLI selection and legacy benchmark compatibility | `main.go` | command composition only | parity traversal stays out of the legacy report model |
| Manifest, traversal, comparison, artifact validation | `search_parity.go` | one privacy and evidence contract | SQLite search implementations remain unchanged |
| Synthetic parity characterization | `search_parity_test.go` | observable end-to-end behavior | no private call-order assertions |
| Operator workflow and privacy warnings | capacity benchmark docs | operational contract | code comments are not operator guidance |

### Boundaries / interfaces
| Boundary or interface | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| `runSearchParity` | command entrypoint/tests | query, IDs, paths and cursors | returns only fixed error classes to the artifact |
| private manifest decoder | parity runner | raw criteria and expected repository state | strict JSON and fixed validation errors |
| parity artifact validator | CI/operator | no private inputs | strict single JSON value, unknown/forbidden fields fail closed |
| legacy/tiered collectors | comparison coordinator | page mechanics | aggregate metrics plus in-memory membership only |

### Behavior tests
| Behavior | Given | When | Then | Level |
|---|---|---|---|---|
| exhaustive equality | synthetic matches span multiple page sizes | both chains run | passed, equal counts, no identifiers/cursors/query/path | integration |
| strict progress | repeated tiered continuation or empty nonterminal legacy page | collector advances | failed with fixed `progress` class | unit |
| duplicate rejection | a chain returns the same member twice | collector records membership | failed with fixed `duplicate` class | unit |
| right censoring | deadline expires before both chains finish | runner stops | timeout wins over mismatch and exposes only lower-bound latency |
| same-head binding | revision or dirty expectation differs | preflight runs | no search is performed and fixed revision class is emitted |
| artifact strictness | unknown, forbidden, inconsistent, or trailing JSON | validator runs | rejected | unit |

### TDD plan
| Behavior | Red | Green | Refactor target |
|---|---|---|---|
| manifest/artifact contract | strict decoder and privacy tests | minimal structs/validators | central allowed schema |
| traversal/parity | synthetic multi-page integration | collectors over production datasources | shared progress ledger only if duplication is real |
| timeout/failure precedence | status table tests | explicit rank function | keep status independent of traversal errors |
| CLI/docs | command-level tests | additive flags and workflow | preserve old benchmark path verbatim |

### Risks / rollback
- Procedural risk: traversal, timing, privacy mapping, and validation could become one script-like function. Keep manifest decoding, each collector, comparison, and artifact validation as explicit boundaries.
- Premature abstraction risk: only two concrete chains exist; use small functions rather than a paging framework.
- Migration / compatibility: no database migration and no modification to the existing `traceary.store-benchmark/v1` or baseline validator. Search parity is an additive command mode.
- Rollback trigger: any identifier/query/path/cursor/raw-error disclosure, inability to prove chain completion, schema ambiguity, or impact on the legacy benchmark. Remove the additive mode and retain existing search authority/tests.
- Split plan: (1) design checkpoint, (2) contract/validator and TDD, (3) production traversal plus synthetic integration, (4) CLI/docs and full validation.

### Implementation checkpoint
- Adopt `membership_set/v1`, exhaustive legacy offsets, exhaustive authenticated continuations, strict progress/duplicate checks, and status precedence `failed > timeout > mismatch > passed`.
- Keep the evidence artifact untracked/CI-generated; validate repository revision and dirty state from the private manifest instead of embedding an artifact path that could make the revision self-referential.
- Reject unknown fields at every JSON object boundary and explicitly reject privacy-forbidden field names recursively.
