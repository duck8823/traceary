# P2 Structure-Behavior Design Note

## HIGH checkpoint and requirements
Approved merged ADR/plan and main P2 checkpoint specify supervisor ownership, not ordinary lifecycle removal. Preserve dedicated SID, raw compatibility fields, process/usage outcomes and fixed store route. No schema, identity, provenance stamp or verified-result projection is introduced. Raw historical reason/mode/CLI attribution/fingerprint is not actor proof; reconciliation proves only matching stored metadata.

## Current writer map / conceptual model
| Writer | Existing risk | Required invariant |
| --- | --- | --- |
| Session.End / Terminate | Ordinary writers terminalize one-shot | Domain ordinary transitions reject one-shot; FinalizeOneShot owns outcome. |
| SaveBoundary / stable hook retry | Caller mode may be forged; duplicate bypass skips callback | Stored-mode guard runs inside event transaction before delivery decision, including duplicate deliveries. |
| FinalizeOneShot | Generic repository path; generated refinement | Narrow optional supervisor repository port; first stored result immutable; no generated refinement. |
| GC / doctor / cascade | Close one-shot as unknown/success | Selection excludes stored one-shot; domain/repository guard is backstop. |
| Bundle import Replace | Rebind or terminalize existing open wrapper | Atomic UPSERT WHERE compares binding/result for existing one-shot, absent legacy restore retains raw metadata. |
| Host/replay end | Refusal could poison spool | Only ownership refusal drains harmlessly after useful flush; direct CLI remains actionable error. |

## Responsibility and boundaries
Domain owns runtime-mode transition eligibility. SessionUsecase keeps its existing aggregate-oriented methods (Start/End/Finalize), not separate procedural orchestration classes. `OneShotSessionRepository.SaveOneShotBoundary` is a narrow supervisor-only port implemented by SQLite; generic repository callers cannot switch authority by forging proposed mode. SQLite owns stored-mode CAS and transaction ordering; import trust is compatibility only. Existing event logger has no outcome guard and remains usable after results. Presentation owns benign host retry policy, not outcome synthesis.

## Atomicity / migration / rollback
Stored-mode validation runs in the same transaction before event idempotency; transaction retry handles SQLite write races. Zero-row CAS checks mode/existence/reason; ownership refusal never reconciles as success. Import UPSERT protects the stored row under the write lock; concurrent supervisor finalize cannot be overwritten. No compatibility-field migration/backfill. Revert only with explicit acceptance that ordinary writers can again overwrite wrapper results. P3 lifecycle producer cutover remains separate; uncertain actor provenance stays unknown rather than fabricated.

## Implementation checkpoint refinement
A targeted concurrent different-reason test exposed deferred SQLite read-to-write upgrade contention (max existing three retries returned SQLITE_BUSY instead of a reason contradiction). The ownership guard now obtains a writer reservation using a value-preserving session-id UPDATE in the same transaction before reading stored mode. No schema, recorded value, per-test budget, retry count, or process timeout changes; refusal rolls back the reservation and event together. Exact import UPSERT guards retain existing rows and all result/binding fields under the write lock. The subagent-start refusal catch was removed after main self-review: only end/replay drains supervisor ownership refusal.

Trigger audit: session triggers in migration 024 target INSERT or UPDATE OF ended_at/terminal_reason, and migration 069 targets INSERT or UPDATE OF started_at. The reservation updates session_id to itself, activating none of those triggers. There is no session-wide UPDATE audit trigger in the shipped migrations. The stored-mode refusal test compares all restored session fields before/after and confirms no event was inserted; rollback has no observable mutation. Concurrent same/different finalizers and finalization/import races are repeated with bounded count 10 under unchanged assertions.
