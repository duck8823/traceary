# Issue 2403: Isolate bounded metadata-only doctor fixtures

## Structure-Behavior Design Note (Low)

- Requirement: Give both bounded large-store doctor tests their own temporary
  HOME, explicit project directory, and hook-state directory. Align the injected
  home resolver with HOME; restore it through existing cleanup helpers.
- Cause confirmed by static audit: config inspection uses os.UserHomeDir directly,
  bypassing TestMain's fake resolver; omitted --project-dir uses the working
  directory, and package-level hook state can contain other tests' residue.
- Ownership: Test fixtures only, in presentation/cli/doctor_test.go. Production
  doctor, normal environment checks, schema, guard, and scheduler code are unchanged.
- Behavior tests: Existing <= 1s assertions remain literal and measure the same
  Execute boundary. Preserve healthy PATH fixture, sparse 2 GiB invalid SQLite
  fixture, rollback cleanup, panic capacity inspector, stubs, no initialization,
  no event/payload reads, and O(1) page signals.
- TDD plan: After the shared validation lane is free, run original and isolated
  target tests under controlled temporary HOME and explicit Go caches; note that
  these caller environments differ from an uncontrolled baseline. Then run the
  affected CLI suite and normal commit hook, without weakening any test budget.
- Self-review: A test helper owns only environment fixture setup; callers keep
  normal doctor checks and pass the resulting project directory explicitly.
- Risk / rollback: Isolation does not demonstrate a production performance fix.
  If the unchanged 1s assertions still fail, record evidence and stop rather than
  increasing budgets or skipping environment checks. Reverting this test-only
  commit restores the prior fixtures; no migration is needed.
