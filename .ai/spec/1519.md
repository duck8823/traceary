## Structure-Behavior Design Note

### Requirement summary
- Purpose: report Codex interactive and direct headless hook coverage without treating the installed manifest as proof that a final-turn boundary was emitted.
- Current behavior: one dogfood `codex exec --ephemeral` run persisted only `SessionStart` and `UserPromptSubmit`; doctor could report `capture_observed` after those partial events because it did not require runtime Stop evidence. A current isolated re-probe does emit Stop and supplies the stable inline final message.
- Expected behavior: doctor requires runtime Stop evidence instead of assuming configured coverage, versioned fixtures distinguish ephemeral and non-ephemeral headless payloads, and the stable inline `Stop.last_assistant_message` persists the marker without reading a rollout.
- Non-goals: scraping `CODEX_HOME` for assistant text, selecting a recent unrelated rollout, changing Codex hook trust, or claiming every configured hook fires in every host mode.

### Conceptual model
| Concept | State | Behavior | Constraint / invariant |
|---|---|---|---|
| Host mode coverage | interactive, headless, headless ephemeral | states which boundaries the host actually emits | manifest presence is configuration evidence only |
| Direct headless run | start/prompt/Stop observed or final boundary absent | reports observed or partial final-turn coverage from runtime evidence | ephemeral and persisted modes do not borrow another session's history |
| Headless Stop payload | session identity and inline final message | persists the current turn through the existing transcript hook | `last_assistant_message` is authoritative; `transcript_path` is not opened for assistant text |
| Capture diagnostic | body-free stored/pending aggregate plus mode contract | correlates `user_prompt_submit` turns to an in-window Stop and counts finalized `headless_stream` usage separately | never includes session IDs or event bodies |

### Responsibility assignment
| Responsibility | Owner | Reason to change | Not owner / reason |
|---|---|---|---|
| Mode-specific coverage contract | `presentation/cli` doctor check | operator-facing host capability diagnosis | hook manifest only declares configuration |
| Final-turn extraction | existing Codex transcript hook | Codex Stop payload detail | doctor must not parse or persist bodies |
| Transcript persistence and redaction | existing `EventUsecase` path | usecase owns redaction and storage | diagnostic code must remain body-free |
| Reproduction evidence | versioned test fixture and bilingual integration docs | host-version evidence changes independently | production code must not read test evidence |

### Boundaries / interfaces
| Boundary or interface | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| Codex Stop transcript extractor | hook runtime | inline `last_assistant_message` | empty message fails soft; no rollout fallback |
| `codex-capture` doctor check | operator / automation | body-free stored/pending evidence | deterministic status; missing direct final boundary is explicit |
| SQLite diagnostic projection | doctor check | session-local prompt/Stop ordering and headless usage source counts | only `user_prompt_submit` prompts form turns; `created_at,id` defines a stable half-open turn interval |
| `EventUsecase.Log` | transcript hook | transcript redaction and storage | persistence failure remains visible to hook delivery |

### Behavior tests
| Behavior | Given | When | Then | Level |
|---|---|---|---|---|
| Ephemeral direct mode persists inline final turn | v0.145.0 Stop evidence without `transcript_path` | transcript hook runs | marker persists from `last_assistant_message` | fixture/CLI |
| Non-ephemeral direct mode avoids history scraping | v0.145.0 Stop evidence with `transcript_path` | transcript hook runs | inline marker persists without opening the rollout | fixture/CLI |
| Interactive mode remains distinct | interactive hook evidence | doctor renders coverage | Stop/transcript are described as host-emitted runtime evidence | fixture/CLI |
| Headless marker persists | Stop fixture contains `last_assistant_message` | transcript hook runs | one transcript event is recorded for that exact session | integration |
| Non-ephemeral history is not scraped | Stop also contains an unrelated `transcript_path` | transcript hook runs | inline marker persists without opening the path | integration |
| Missing runtime Stop is explicit | only start/prompt or headless usage exists | doctor classifies coverage | warning reason is `final_turn_not_observed` | unit |
| Prompt/Stop correlation is session-safe | prompt, Stops, and next prompt share a workspace window | diagnostic loads evidence | each hook-origin prompt has a Stop only before the next hook-origin prompt in the same session; equal timestamps use event ID as tie-breaker | datasource |
| Headless usage is workspace-scoped | two workspaces share a database | diagnostic loads evidence | only finalized in-window `headless_stream` observations whose session is present in the target workspace count | datasource |

### Risks / rollback
- Procedural risk: introducing a rollout fallback would mix unrelated history selection with current-turn attribution; do not add one while the host supplies an inline final message.
- Premature abstraction: do not add a cross-host transcript framework until another host needs the same inline Stop contract.
- Migration / compatibility: no schema migration; the new doctor reason is additive and transcript events use the existing event schema.
- Rollback trigger: unrelated-session reads, transcript persistence without a Stop boundary, or doctor claiming complete direct-headless coverage without runtime evidence.
- Rollback: revert the additive diagnostic reason and fixture/docs updates; existing transcript and usage paths remain unchanged.

### Design checkpoint after live probe
- Codex CLI 0.145.0 emitted `SessionStart`, `UserPromptSubmit`, and `Stop` for text and `--json` output in both ephemeral and non-ephemeral headless runs.
- The ephemeral Stop omitted `transcript_path` but included `last_assistant_message`; the non-ephemeral Stop included both. Therefore the existing inline transcript extractor is the stable, session-bound source and no history or supervised-stream fallback is added.
- The product defect is the diagnostic classification: stored activity without Stop evidence must not pass merely because the manifest declares Stop.
