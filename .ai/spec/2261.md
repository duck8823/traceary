## 1. Requirement summary

### 1.1 The defect (verified in this tree)

Derived rows are written per source batch into six tables keyed by `generation_id`. When a generation becomes terminal the rows stay resident:

- `MarkFailed` (`infrastructure/sqlite/search_projection_rebuild.go:1015-1041`) flips `search_projection_state` and `search_projection_generation_lifecycle.state` only.
- `AbandonSearchProjection` (`infrastructure/sqlite/search_projection_rebuild.go:1294-1342`) additionally deletes `search_projection_exclusions` (`:1338`) and nothing else.
- The cleanup-no-progress park (`infrastructure/sqlite/search_projection_cleanup.go:194-207`) flips state only.
- Old-generation deletion exists **only** as the cleanup phase of a *later* generation (`search_projection_cleanup.go:126-139` builds `generation_id<?` / `generation_id>?` pages relative to the generation under construction; `deleteProjectionCleanupRow`, `search_projection_rebuild.go:907-934`).
- A failed generation is parked, never retried (`application/usecase/search_projection_usecase.go:500-516`; "Resume rejects a failed generation … Only an explicit start replaces it").
- Status counts are scoped to `active_generation_id` (`search_projection_rebuild.go:1400-1414`), so an empty active id reports zero keyword/fingerprint rows while millions remain resident.

Live evidence (issue, read-only 2026-08-27, v0.47.1 store): 12 generations (`failed=7`, `abandoned=4`, `drifted=1`, `complete=0`), 6.31M `search_projection_session_keywords` rows, 4.14M `literal_search_fingerprints` rows, `active_generation_id=''`.

## 2. Conceptual model

Four concepts. Keep them distinct in code and in names.

1. **Generation** — one identity (`generationID()`, random 16-byte hex, `search_projection_rebuild.go:174-180`) under which derived rows are written. Its authoritative record is one row in `search_projection_generation_lifecycle` (migration `000041`).
2. **Lifecycle state** — `rebuilding | complete | failed | drifted | abandoned` (CHECK in `000041`). *Terminal* means `failed` or `abandoned`: the machine will never advance it again.
3. **Authority** — which generation answers reads. Only `search_projection_state.active_generation_id` is ever consulted by the read path (`infrastructure/sqlite/event_search_authority.go:134-165`, `event_search_query.go:53`, `search_projection_session_query.go:133-145`). During a rebuild `active_generation_id` still names the *previous complete* generation; that is the "previous complete generation still serving reads" the AC protects.
4. **Residency** — rows physically present in the six derived tables. Residency is orthogonal to authority: a terminal generation is resident but never authoritative.

The invariant this issue restores:

> **Residency ⊆ {authority} ∪ {generation under construction}.** Any other resident family is garbage and must be removable in bounded steps, from an operator command, without raw SQLite.

"Reclaimed" is **evidence, not a state**: the lifecycle `state` CHECK is untouched, and reclaim is recorded in additive columns. This keeps older binaries working on a reclaimed store (they ignore the columns) and keeps rollback to the previous release trivial (§11).

## 4. Boundaries, interfaces, and the eligibility predicate

### 4.1 Eligibility predicate (the safety core)

A generation is **eligible for reclaim** iff, observed in one snapshot:

1. `search_projection_generation_lifecycle.state IN ('failed','abandoned')`, **and**
2. `generation_id <> COALESCE(search_projection_state.active_generation_id,'')`, **and**
3. it is not the generation currently under construction: NOT (`generation_id = search_projection_state.generation_id` AND `search_projection_state.state IN ('rebuilding','drifted')`), **and**
4. `reclaimed_at = ''` (not already finished).

Why (2) alone is sufficient for read safety, and (3) is belt-and-braces: the read path consults *only* `active_generation_id`. `usableLiteralFingerprintGeneration` (`event_search_authority.go:134-165`) returns either `literalGeneration` when it equals `activeGeneration` (`:144`) or `activeGeneration` itself (`:164`); it never returns a non-active generation. `search_projection_session_query.go:133-145` and `event_search_query.go:53` scope on `active_generation_id`. A `complete` generation can never satisfy (1). Condition (3) covers a lifecycle row that lags behind the state row after a crash.

Listing SQL (`listTerminalGenerationsOn`):

```sql
SELECT l.generation_id, l.state, l.failure_class, l.terminal_at, l.reclaimed_at, l.reclaimed_rows
  FROM search_projection_generation_lifecycle l
  JOIN search_projection_state s ON s.singleton = 1
 WHERE l.state IN ('failed','abandoned')
   AND l.generation_id <> COALESCE(s.active_generation_id, '')
   AND NOT (l.generation_id = COALESCE(s.generation_id, '')
            AND s.state IN ('rebuilding','drifted'))
   AND l.reclaimed_at = ''
 ORDER BY l.terminal_at, l.generation_id
```

### 4.2 In-transaction guard (re-checked on every page)

Inside the page's `BEGIN IMMEDIATE`, before any delete:

```sql
SELECT COUNT(*)
  FROM search_projection_generation_lifecycle l
  JOIN search_projection_state s ON s.singleton = 1
 WHERE l.generation_id = ?
   AND l.state IN ('failed','abandoned')
   AND l.generation_id <> COALESCE(s.active_generation_id, '')
   AND NOT (l.generation_id = COALESCE(s.generation_id, '')
            AND s.state IN ('rebuilding','drifted'))
   AND NOT EXISTS (SELECT 1 FROM search_projection_generation_lifecycle
                    WHERE generation_id = ? AND state = 'complete')
```

`!= 1` ⇒ return `*apptypes.SearchProjectionDriftError` (`application/types/search_projection.go:357-361`) and delete nothing. This mirrors the `RowsAffected()==1` fencing style used throughout the projection adapter (`search_projection_rebuild.go:1030-1032`, `:1037-1039`, `:929-932`).

### 4.3 Three fences (AC4)

1. **Eligibility SQL** (§4.1) — what the loop is even offered.
2. **In-transaction re-check** (§4.2) plus `RowsAffected()==1` on the lifecycle counter update — what the delete is allowed to touch, re-observed under the write lock.
3. **`verifySearchProjectionGenerations` in `VerifyPair`** (§5.8) — what the compact candidate is allowed to be missing, checked on a file that has not yet replaced anything.

A failure-injection test covers fence 2 (`TestTerminalReclaimRefusesActiveAndCompleteGenerations`) and fence 3 (`TestVerifyPairRejectsCandidateMissingActiveGenerationRows`).

### 5.2 Migration 000074 and the manifest

`schema/sqlite/migrations/000074_add_search_projection_generation_reclaim_columns.sql`:

```sql
-- Terminal (failed / abandoned) generations keep their derived rows until a
-- later generation reaches cleanup (#2261). Record why and when a generation
-- became terminal on the lifecycle row itself -- search_projection_state only
-- holds the *current* generation's failure_class, so it is lost when the next
-- generation replaces it -- and record bounded reclaim progress so status and
-- doctor can prove the resident rows are gone.
--
-- Additive only: ALTER TABLE ADD COLUMN with constant defaults is a metadata
-- operation, and the backfill below touches one row per generation (12 on the
-- reference store), never an event. The lifecycle state CHECK is untouched:
-- "reclaimed" is evidence (reclaimed_at <> ''), not a state, so older binaries
-- keep working and simply ignore the columns.
ALTER TABLE search_projection_generation_lifecycle ADD COLUMN failure_class TEXT NOT NULL DEFAULT '';
ALTER TABLE search_projection_generation_lifecycle ADD COLUMN terminal_at TEXT NOT NULL DEFAULT '';
ALTER TABLE search_projection_generation_lifecycle ADD COLUMN reclaimed_at TEXT NOT NULL DEFAULT '';
ALTER TABLE search_projection_generation_lifecycle ADD COLUMN reclaimed_rows INTEGER NOT NULL DEFAULT 0;
ALTER TABLE search_projection_generation_lifecycle ADD COLUMN reclaimed_logical_bytes INTEGER NOT NULL DEFAULT 0;

-- Best-effort backfill for the generation the singleton state row still describes.
UPDATE search_projection_generation_lifecycle
   SET failure_class = COALESCE((SELECT failure_class FROM search_projection_state WHERE singleton=1), ''),
       terminal_at   = COALESCE((SELECT updated_at    FROM search_projection_state WHERE singleton=1), '')
 WHERE state IN ('failed','abandoned')
   AND generation_id = COALESCE((SELECT generation_id FROM search_projection_state WHERE singleton=1), '');

-- Abandoned generations already carry their own timestamp.
UPDATE search_projection_generation_lifecycle
   SET terminal_at = abandoned_at
 WHERE state = 'abandoned' AND terminal_at = '' AND abandoned_at <> '';
```

- Cleanup park (`search_projection_cleanup.go:201`):

**Page function.** One `beginImmediate` transaction (`infrastructure/sqlite/search_projection_lock.go:16`) on a reserved connection, bounded by `context.WithTimeout(ctx, b.LockTime)` exactly as `applyProjectionPlan` bounds its hold (`search_projection_rebuild.go:1051-1073`). -- 1. measure the exact page about to be deleted
```sql
SELECT COUNT(*), COALESCE(SUM(<tableCleanupLogicalBytesSQL>), 0)
  FROM search_projection_session_keywords
 WHERE rowid IN (SELECT rowid FROM search_projection_session_keywords
                  WHERE generation_id = ? LIMIT ?);

-- 2. delete exactly that page, in the same transaction
DELETE FROM search_projection_session_keywords
 WHERE rowid IN (SELECT rowid FROM search_projection_session_keywords
                  WHERE generation_id = ? LIMIT ?);
```

Assert `RowsAffected()` of (2) equals `COUNT(*)` of (1); otherwise `*apptypes.SearchProjectionDriftError`. **Do not use `RETURNING`**: it appears nowhere in this repository (zero hits across `infrastructure/`, `schema/`, `application/`), so its behaviour through `database/sql` `ExecContext` with this driver is unverified here, and I was not able to run a probe in this session. The two-statement form is deterministic and needs no verification.

Then, in the same transaction:

```sql
UPDATE search_projection_generation_lifecycle
   SET reclaimed_rows = reclaimed_rows + ?,
       reclaimed_logical_bytes = reclaimed_logical_bytes + ?,
       reclaimed_at = CASE WHEN ? = 1 THEN ? ELSE reclaimed_at END
 WHERE generation_id = ?
   AND state IN ('failed','abandoned')
```

with `RowsAffected()==1` asserted (else `SearchProjectionDriftError`). The third parameter is 1 only when every table reported 0 rows in this page (i.e. the generation is done); the fourth is `formatTimestamp(now.UTC())`.

`Done` is returned true in that same case. Because the deletes and the counter advance commit together, an interrupted page leaves the store exactly at a page boundary: either the rows are gone and the counters reflect them, or neither happened. `reclaimed_rows` therefore never double-counts.

### 5.4 Usecase loop

```
ReclaimTerminalGenerations(ctx, b, opts, now):
  runCtx = WithTimeout(ctx, opts.TotalWallTime)
  gens = store.ListTerminalGenerations(runCtx)
  if len(gens) == 0 -> {Complete: true, StopReason: "complete"}
  page = apptypes.SearchProjectionTerminalReclaimPageRows
  for each g in gens:
      loop:
        if ctx.Err()    -> StopReason "cancelled", return partial
        if runCtx.Err() -> StopReason "wall_time", return partial
        progress, err = store.ReclaimTerminalGenerationPage(runCtx, g.GenerationID, b, page, now)
        on SearchProjectionNoProgressError{LockDurationCap}:
            if page <= 1 -> return the error
            page /= 2; continue                       // same halving as ResumeUntil (:283-298)
        on *SearchProjectionDriftError:
            skip this generation, record it, continue with the next  // never abort the run
        on other err -> return err
        accumulate Deleted / LogicalBytes
        if progress.Done -> break
  StopReason "complete", Complete = true
```

`SearchProjectionDriftError` on a generation means the world changed under us (someone made it active or complete). Skipping is correct and safe; aborting the whole run would let one racing generation strand the rest. Record skipped generation ids in `Generations` so the caller can report them.


`verifySearchProjectionGenerations(ctx, sourceDB, candidateDB) error`:

1. No-op when the six tables or the lifecycle table are absent on both sides; error if present on one side only.
2. Read from the **source**: the lifecycle rows and `active_generation_id`. Partition the lifecycle generation ids into `Eligible` (§4.1 predicate, evaluated on the source) and `Protected` (everything else, plus `active_generation_id` when non-empty).
3. For each of the six tables:
   - for every `g ∈ Protected`: `digestRows(… WHERE generation_id = ?)` on both sides must return identical `(count, digest)`; on mismatch fail with a message naming the table and the generation.
   - for every `g ∈ Eligible`: candidate `SELECT EXISTS(SELECT 1 FROM t WHERE generation_id = ?)` must be 0.
   - totals: `candidateCount(t) == sourceCount(t) − Σ_{g ∈ Eligible} sourceCount(t, g)`. This catches both invented rows and rows deleted from a generation that is not in the lifecycle table at all, without a `SELECT DISTINCT generation_id` scan.
4. Lifecycle table: every source `generation_id` must exist on the candidate with an identical `(state, config_hash, source_revision, high_water, abandoned_at, failure_class, terminal_at)` tuple, and the candidate must invent no generation id. **The reclaim columns (`reclaimed_at`, `reclaimed_rows`, `reclaimed_logical_bytes`) are deliberately excluded from this comparison** — the work copy advances them and the source does not. See §12.11.
5. `search_projection_state`: not compared here (it is untouched by this step and already unverified in the events branch).

Wire it at the end of `verifyFilteredCandidate` (`compaction_sqlite.go:181-252`), after the existing event checks.

## 6. Behaviour contract (what the tests must pin, in prose)

1. Two consecutive `start → write derived rows → fail/abort` cycles, each followed by bounded reclaim runs, leave zero resident rows for both terminal generations, and total resident derived rows after cycle 2 are ≤ after cycle 1 (not linear in generation count).
2. Reclaim of the active generation id, or of a generation whose lifecycle says `complete`, deletes nothing and returns `*apptypes.SearchProjectionDriftError`; row counts and lifecycle counters are unchanged.
3. A page cancelled mid-flight leaves the store at a page boundary; a subsequent call finishes, and `reclaimed_rows` equals the number of rows actually deleted (no double counting).
4. Every per-table page seeks on a generation-prefixed index; no full table scan, no temp b-tree.
5. With `active_generation_id = ''` and two terminal generations, status reports `TerminalGenerations = 2` with non-zero terminal keyword/fingerprint rows and logical bytes, while the active-scoped `KeywordRows` / `FingerprintRows` stay 0; the evidence carries `failure_class` and `terminal_at`.
6. A pre-000074 store with a failed generation gets `failure_class` / `terminal_at` backfilled by the migration.
7. Default compact removes terminal rows on the work copy, keeps the complete/active generation's rows byte-identical, and reports `steps.projection_reclaim.rows` equal to the seeded terminal row count.
8. A hand-built candidate missing active-generation keyword rows fails `VerifyPair` with a message naming the generation.
9. `CompactInPlace` produces the same step.
10. The usecase stops with `stop_reason = "wall_time"` and partial progress when the wall budget expires, and reports `complete` when nothing is terminal.
11. `doctor` warns while terminal rows exist and passes after `--fix`; the fix log names `search-projection-terminal-reclaim` and the action text contains the row count.
12. `store compact --json` output contains `steps.projection_reclaim` and still contains every pre-existing key.

## 11. Risks and rollback

| Risk | Mitigation |
|---|---|
| Deleting rows of the wrong generation (the only irreversible risk) | Three independent fences (§4.3), each with a test. The eligibility predicate is re-evaluated under the write lock, not carried from the listing. |
| Crash mid-reclaim | Every page is one transaction that commits deletes and counters together (§5.3). An interrupted run leaves a page boundary; the next `doctor --fix` or compact resumes. `reclaimed_at` is stamped only when the generation is fully done. |
| Unbounded delete transaction | Page size is per table per transaction, default 2000, halved on lock-duration overrun down to 1 (§5.4), and the whole run is bounded by `TotalWallTime` with a resumable `wall_time` stop reason. |
| Migration cannot be undone | 000074 is additive `ALTER … ADD COLUMN` with constant defaults plus a generation-count-bounded backfill. Older binaries ignore the columns and the `state` CHECK is untouched, so **rollback = ship the previous binary**; no down migration is needed. The copy protocol (§10) keeps the migration off the live store before release. |
| Verification false negative | `verifySearchProjectionGenerations` compares protected generations exactly and asserts a per-table total identity, so both invented and over-deleted rows fail (§5.8). |
| Status cost on ~10.4M terminal rows | Measured on the copy and recorded in the PR (§5.5). Exact counts are kept; a >5 s result is a follow-up under #2148, not a scope change here. |
| Compact returning an error after the rewrite | `finishSearchProjection` errors propagate out of `Compact` (`store_compaction.go:146-148`, `:173-175`). Running reclaim *before* `CompleteGeneration` (§5.7, §12.7) means the reclaim has already committed if the rebuild then fails. |

Independent review of the **eligibility predicate** (§4.1 + §4.2) is required before merge, per the issue's High-risk instruction. Multi-AI review is required for the PR as a whole.
