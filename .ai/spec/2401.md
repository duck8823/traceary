# #2401: ordinary log-only Session cutover

## Structure-Behavior Design Note (HIGH)

### Requirement summary
Session is a recorded grouping identity, not running/ended state. Ordinary Start registers immutable attribution; End records a boundary and optional covered refinement. Legacy lifecycle storage/history and supervisor ownership remain unchanged. No schema, retention, monitoring, invocation identity or supported-host callback expansion.

### Conceptual model
| Concept | Behavior | Invariant |
|---|---|---|
| Session | Register and group logs | Immutable ID/client/agent/workspace/parent/spawn lineage (and explicit mode); historical end does not gate capture/retrieval |
| Boundary event | Recorded start/end fact | Explicit ends are distinct; genuine delivery retries use existing receipts |
| Refinement | Supplied summary and event coverage | Covers real persisted end event |
| Supervisor result | Dedicated acquired SID and guarded finalization | Ordinary paths cannot acquire or overwrite owned outcomes |
| Routing/receipt state | Fixed capture routing and replay reliability | Cleanup is not semantic closure; SID is not occurrence evidence |

### Responsibility assignment
| Owner | Responsibility | Not responsible for |
|---|---|---|
| Session usecase (existing Start/StartChild/End methods) | Register immutable identity, append boundary, refine | SQL, terminal cascade, runtime status |
| SQLite boundary port | Atomic registration and supervisor guards | Inferred parent or host callbacks |
| Query services | Existing scope/order/latest selection and aggregates | Lifecycle eligibility/status projection |
| Host adapters | Proven callbacks, flush/extract/routing cleanup and actual receipts | Runtime availability or guessed latest parent |
| Doctor/GC | Existing safe housekeeping/diagnostics | Synthetic stale close or expanded retention |

### Boundaries / interfaces and checkpoint
- Preserve existing Start/End Event return type and CLI ID/JSON outputs. Same ordinary ID plus equal client/agent/workspace/parent/spawn lineage (and explicit mode) returns its original persisted session_started event via existing scoped persistence query; no nil result or invented event ID. Imported grouping lacking a start event records its first truthful start boundary once without replacing metadata/history. One-shot StartWithRuntimeMode remains fresh acquisition only (existing SID refused). Nested native SessionStart is capture, not acquisition: purpose-specific OneShotCaptureUsecase validates fixed inherited absolute store/SID, stored one_shot and known wrapper parent, returning real acquired start in stored attribution scope without re-registration. Legitimate native actor/cwd differences do not rebind wrapper metadata; model observation/cleanup remain.
- Immutable metadata mismatch fails closed with actionable error and ErrInvalidSessionState; hook must not swallow it as already-started success.
- Ordinary End appends EventKindSessionEnded without updating legacy fields or cascading. Existing SaveBoundary transaction receives unchanged aggregate with boundary kind, and its supervisor ownership guard remains mandatory. Supplied summary uses returned actual event ID for coverage.
- Native stable receipt allowlists and reliable spool receipts remain. Remove SID fallback for start/end; absent actual occurrence evidence means distinct callback occurrences, not inferred idempotency. Start registration itself is idempotent independent of receipt identity.
- Parent inference must start from explicit payload/routing root identity and proven spawn state, never from Active/Latest DB selection. No evidence means unknown.
- Active compatibility aliases Latest with unchanged matching/start ordering. ActiveOnly compatibility flag is no-op; generated SessionSummary status removed after caller audit. Historical raw lifecycle fields remain.

### Risks / rollback
The change spans public interfaces and host replay; partial producer-only rollout/rollback is unsafe. No migration/backfill/drop. Revert the consolidated commit only on an isolated recovery copy or after explicitly approved old-writer freeze; old GC/doctor can synthesize closes and old readers reject records. Trigger rollback on wrong routing/lineage, lost flush, coverage/output mismatch or supervisor guard regression. Empty-session deletion keeps existing ended predicate; nonempty retention is unchanged. Avoid unused facade/DTO/actor stamp; retain existing operation-unit usecase structure (compare SessionRefinementUsecase Refine and current SessionUsecase Start/StartChild/End).

### Self-review (to complete after validation)

Atomic registration compares stored immutable metadata before any delivery short-circuit and returns scoped earliest canonical start with PersistInserted=false; imported missing-start races are serialized by the existing writer reservation. Public Start preserves supported ordinary recorded modes; declared StartWithRuntimeMode remains strict. No lifecycle/schema/retention migration is performed. Existing summary/coverage, parent lineage, native ledger attempts and workspace observations remain. Callback completion clears its own diagnostics; historical ended rows do not prove completion. Receiptless explicit callbacks are not collapsed by SID/body. Raw host payload receipt fields are ignored. Seven-host fixture verification is required; no live certification is claimed. ### Final checkpoint refinements
Public ordinary Start preserves supported non-one_shot mode metadata without rewriting it; explicit StartWithRuntimeMode declarations stay strict. legacy_unknown is a terminal reason, never a newly supported mode. Fresh one-shot acquisition and nested native capture are distinct: OneShotCaptureUsecase returns a real, unambiguous persisted acquired boundary using a bounded stored-attribution lookup; native actor/cwd differences do not become re-registration metadata. Fixed inherited absolute DB/SID and known wrapper parent contradictions fail closed before wrong-store initialization. Nested capture preserves model/routing cleanup and creates no extra start or supervisor result. Default actor/custom workspace-label subprocess fixtures, contradictory store/SID/parent and missing-capability fixtures validate these boundaries. No actor authentication/provenance inference is claimed.

Process friction: legacy-semantic assertions and exact-line probe inventory required deliberate updates; first nested subprocess fixtures needed the existing TestMain test-owned DB/state overrides. Failed logs remain evidence, not passes. P2 race test now recognizes numeric SQLITE_BUSY base code (including BUSY_SNAPSHOT) while preserving all outcome/rollback assertions and retry/time budgets. Private lint cache avoids advisory host-cache permission warnings. Existing fresh CI and integrated wave/live P4 gates remain the parent's responsibility.
