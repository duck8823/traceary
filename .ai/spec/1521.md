## Structure-Behavior Design Note

### Requirement summary
- Purpose: make packaged Antigravity hooks executable in sandboxed, non-interactive plan mode using only the four Traceary hook command prefixes they require.
- Current behavior: hook files can be installed and pass doctor route checks while Antigravity's default command permission remains `ask`; headless mode cannot answer the prompt, so the hook never executes.
- Expected behavior: the plugin ships an explicit least-privilege permission fragment, documentation explains how to merge it into Antigravity settings, and doctor distinguishes hook registration from headless executable coverage.
- Non-goals: `command(*)`, `unsandboxed(...)`, `--dangerously-skip-permissions`, disabling the terminal sandbox, changing Antigravity's global permission defaults, or granting model-initiated Traceary commands.

### Conceptual model
| Concept | State | Behavior | Constraint / invariant |
|---|---|---|---|
| Hook route | absent / installed / malformed | registers Antigravity lifecycle handlers | installation alone does not imply executable coverage |
| Scoped hook permission | absent / partial / complete / shadowed | auto-approves only packaged hook command prefixes | no wildcard command or unsandboxed grant |
| Headless coverage | unavailable / executable | combines one healthy route with an effective complete permission | fail closed when deny/ask precedence shadows allow |
| Marker probe | lifecycle boundaries emitted by host | records body-free start, prompt, final turn, Stop boundary, and true session end when available | never requires transcript bodies to prove boundary delivery |

### Responsibility assignment
| Responsibility | Owner | Reason to change | Not owner / reason |
|---|---|---|---|
| Declare required command resources | Antigravity plugin permission fragment | package and hook commands must stay versioned together | doctor must not invent a broader permission |
| Explain settings merge and precedence | bilingual Antigravity integration docs | host settings are operator-owned and cannot be overwritten safely | plugin installation must not mutate global settings |
| Parse effective permission lists | doctor Antigravity permission inspector | doctor needs deterministic installed-vs-executable evidence | hook runtime does not decide host authorization |
| Aggregate route and permission readiness | doctor Antigravity headless coverage check | readiness spans two independent observations | per-route checks remain sibling-independent |
| Record lifecycle markers | existing Antigravity hook runtime | host events already map to session start, prompt, final turn, and Stop turn boundary | permission probing must not write private user content |

### Boundaries / interfaces
| Boundary or interface | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| `permissions.example.json` package fragment | operator / installer tooling | four exact `command(traceary hook antigravity <event>)` resources | declarative example only; no automatic global mutation |
| Antigravity `settings.json` `permissions` object | host permission engine | deny > ask > allow precedence and exact token-prefix matching | absent, malformed, partial, or shadowed rules produce doctor WARN |
| Antigravity headless coverage check | doctor report | plugin/workspace/user route probing and settings file reads | unreadable settings produce WARN without credential reads |
| hook stdin/stdout JSON | Antigravity host | lifecycle payload normalization and durable spool fallback | best-effort hook failure does not block the host loop |

### Behavior tests
| Behavior | Given | When | Then | Level |
|---|---|---|---|---|
| complete scoped allow | a healthy hook route and all four exact allow rules | doctor runs | headless coverage passes |
| permission absent | hook files exist but settings have no required allow rules | doctor runs | installed route remains visible and headless coverage warns |
| partial permission | only some required rules are allowed | doctor runs | warning lists the missing resources |
| precedence fail closed | required command is covered by deny or ask | doctor runs | allow is treated as ineffective and coverage warns |
| broad rule rejected | settings contain only `command(*)` | doctor runs | coverage does not pass and warns against the broad grant |
| no duplicate registration | plugin and direct hook route both exist | doctor runs / docs are followed | operator is told to retain exactly one active route |
| marker probe | host emits PreInvocation and Stop around a completed turn | sandboxed headless probe runs | start, prompt, final turn, Stop boundary, and true session end when available are observable without bodies |

### TDD plan
| Behavior | Red | Green | Refactor target |
|---|---|---|---|
| exact permission classification | table tests for absent/partial/complete/shadowed/broad inputs | pure settings parser and classifier | keep matching limited to the published four resources |
| doctor coverage | report tests show installed but non-executable warning | compose route health with permission state | avoid adding permission fields to route model |
| package contract | manifest test requires the permission fragment and exact rules | add fragment and package metadata | one canonical required-resource list in tests/docs |
| marker probe | existing hook tests assert body-free lifecycle markers | add a deterministic probe/test if coverage is missing | reuse runtime entrypoints rather than a second hook path |

### Risks / rollback
- Procedural risk: treating a syntactically present allow rule as effective would miss Antigravity's deny > ask > allow precedence. Classification checks all three lists and fails closed.
- Premature abstraction: this change models only the four Antigravity Traceary hook commands; it does not introduce a generic host permission engine.
- Migration / compatibility: plugin installation remains non-mutating. Existing users add the documented fragment to Antigravity's `permissions.allow`; interactive users can keep approval prompts, but doctor reports headless coverage separately.
- Rollback trigger: Antigravity rejects the packaged fragment, exact rules fail to match the hook command quoting, or doctor reports PASS while a sandboxed plan-mode probe cannot run.
- Rollback: remove the declarative fragment and headless coverage check; existing hook registration and event storage formats remain unchanged.
