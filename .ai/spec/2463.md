## Concrete checkpoint proposal after native investigation
Native watcher design: allocate Darwin kqueue before spawn, register NOTE_EXIT with receipt against the actual just-started owned child before transferring control capability. A sole watcher awaits exit without reaping, then closes an exit-observed channel; the sole exec.Cmd.Wait and native control/FD close share the child mutex. Mark controls permanently closed under that mutex before reap; release it after Wait. On watcher error, disable controls permanently BEFORE any fallback owned Wait (which may then block outside the control mutex). No signal/control fallback to PID checks. Linux uses an independently opened CLOEXEC pidfd and Poll readability as a non-reaping witness; no /proc traversal. Registration ESRCH for a fast already-exited owned child disables controls and reconciles owned Wait, never adopts another process. Normal control support must work on certified native platforms, not remain fake-only/always unsupported.

Darwin scoped probe /private/tmp/traceary-2463-probes/kqueue.go executed300 synthetic isolated-session sleep children:100 normal NOTE_EXIT then successful owned Wait,100 already-exited registration ESRCH then successful owned Wait,100 original-group SIGTERM then NOTE_EXIT and actual SIGTERM Wait status. It used no real host, credentials or unrelated PID discovery. This proves these observed paths, not arbitrary kernel races or Linux behavior.

Primary-source basis (inference plus native evidence, not just successful fixtures):
- Apple kevent manual: https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/kevent.2.html . Exit notification is distinct from wait/reap.
- Apple XNU kern_event.c filt_procattach: https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_event.c . Registration takes a process reference, attaches the note before releasing it; already-unfindable processes yield ESRCH. This filter is edge-triggered, so registration races need the reference/exit ordering, not a generic claim that kqueue replays all old exits.
- Apple XNU kern_exit.c: https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_exit.c . Exit drains references before later lifecycle notifications; group membership is removed in reap. Inference: the register/reference ordering plus sole unreaped owner prevents the original PGID being reassigned before serialized reap. Recheck this reasoning independently.
- Linux pidfd_open manual: https://man7.org/linux/man-pages/man2/pidfd_open.2.html . Poll observes zombie exit without consuming status; the post-fork PID pin assumes no ignored SIGCHLD/SA_NOCLDWAIT/other reaper. Linux waitid WNOWAIT is another non-reaping primitive, but unnecessary if pidfd Poll suffices.
- Local installed Go1.26.7 runtime signal_unix.go/signal_darwin.go and os/wait_unimp.go/wait_waitid.go inspected. Standalone Go installs SIGCHLD handling; generic Darwin os.Process.Signal/Wait is not accepted as an atomic group-signal solution. Explicitly refuse launch/control if SIGCHLD has been ignored in-process; no foreign c-archive/third-party reaper support or process-global signal rewrite. Verify native stop/continue and fast-exit cases; do not confuse stopped with exited.
