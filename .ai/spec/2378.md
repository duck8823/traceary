## Structure-Behavior Design Note

### Requirement summary
- Purpose: prevent `hooks install` from registering manual Codex hooks when Codex has already proved that the current Traceary plugin owns every effective hook.
- Current behavior: only the Claude plugin short-circuits installation; Codex always writes or upgrades `~/.codex/hooks.json`.
- Expected behavior: Codex install and upgrade short-circuit only for the doctor-equivalent `trusted` result. `--force` does not override that ownership. All other results retain the usable manual route.
- Out of scope: changing plugin packages, feature-flag-only detection, deleting pre-existing manual hooks, or changing #2379 behavior.

### Conceptual model
| Concept | State | Behavior | Constraint / Invariant |
|---|---|---|---|
| Effective plugin contract | trusted, missing, disabled, incomplete, untrusted, modified, undetectable | decides whether plugin owns registration | only `trusted` means all current enabled trusted commands were observed |
| Manual config | absent, existing, mixed, unknown | remains fallback when contract is not trusted | no cleanup happens during install/upgrade |
| Reconciliation | explicit doctor --fix | removes only identified managed duplicates | never inferred from flags or an unknown probe |

### Responsibility assignment
| Responsibility | Owner | Reason to change | Not owner / reason |
|---|---|---|---|
| Effective-contract decision | `codexPluginHookTrustResult` | already defines doctor trust semantics | CLI must not reimplement probe classification |
| Install/upgrade ownership branch | `runHooksInstall` | owns command side effects and notices | hook orchestrator only writes config |
| Duplicate cleanup | existing doctor `--fix` | already preserves unrelated/manual entries | install/upgrade must not silently reconcile |
| Operator explanation | paired hooks docs | distinguishes reload/effective state from on-disk fallback | does not alter host configuration |

### Boundaries / interfaces
| Boundary or interface | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| `codexPluginHookTrustProbeFunc` | install and doctor | app-server protocol and timeout | undetectable is a non-owning result, not an error or pass |
| `codexPluginHookTrustResult.Status` | ownership decision | hook cardinality/trust details | only `trusted` suppresses disk writes |

### Behavior tests
| Behavior | Given | When | Then | Level |
|---|---|---|---|---|
| plugin ownership | complete trusted response and absent/present manual file | install or upgrade, including `--force` | no manual file is created or rewritten; notice explains plugin reload controls effective state |
| fallback safety | missing, disabled, incomplete, untrusted, or probe failure response | install or upgrade | normal manual write/merge proceeds |
| current contract | one trusted command missing (usage included) | install | manual fallback proceeds | black-box CLI |
| preservation | mixed/unrelated manual content | non-trusted upgrade | existing merge preservation remains | existing CLI tests/docs |

### Risks / rollback
- Procedural risk: a stale app-server result could suppress manual fallback; the existing complete-current trusted contract and bounded probe limit this, while any non-pass falls back.
- Premature abstraction: keep the decision Codex-specific and reuse the existing trust result instead of creating cross-host plugin detection.
- Migration / compatibility: no config schema change and no automatic removal; existing duplicate configs converge only through explicit doctor reconciliation.
- Rollback trigger: a trusted result is shown not to correspond to all current package commands; revert the short-circuit and retain manual fallback.

### Orchestrator regression repair
- Red: isolated DoctorFix trusted-plugin cleanup fails because its app-server fixture omits command metadata. The staged CLI suite also fails; a tee pipeline masked its exit, so the worker pass claim is rejected.
- Independent read-only inspection found existing currentCodexHooks documents the actual command-bearing protocol. Update the existing black-box fixture to emit that same ten-command contract; truncated responses remain incomplete. Keep exact-contract production validation unchanged.
- Green plan: rerun DoctorFix and ownership/classifier tests, then selected staged packages with preserved exit status and normal commit hooks. No hook bypass, host mutation, or unverified worker-session refinement.
