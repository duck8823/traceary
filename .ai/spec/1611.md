# #1611 bounded search projection design

## Structure-Behavior Design Note

### Requirement summary

- Add rebuildable recent-text and all-history aggregate projections while legacy search remains the sole authoritative read path.
- Recent text is constrained by an age cutoff and an exact UTF-8 byte ceiling; eviction is oldest timestamp then event ID.
- Rebuild consumes codec-aware canonical plaintext, is deterministic/idempotent, and checkpoints only committed prefixes.
- Non-goals are candidate verification (#1622), dual-run parity (#1623), and cutover/deletion (#1612).

### Conceptual model

| Concept | State | Behavior | Invariant |
|---|---|---|---|
| Projection generation | rebuilding/complete | freezes an event-ID high water and advances a durable keyset | checkpoint and rows commit atomically |
| Recent document | event, visible canonical text, byte count | upsert then evict | total bytes never exceed the configured ceiling; rows older than cutoff never remain |
| Session aggregate | counts and deterministic summary | replace from canonical event/audit facts | same source prefix produces byte-identical rows |
| Keyword | session/token/count | select high-information tokens from canonical plaintext | normalized token order and counts are deterministic |
| Provenance | version, design, budgets, counters | metadata-only inspection | no payload, event ID, session ID, or keyword value is exposed |

### Responsibility assignment

| Responsibility | Owner | Not owner |
|---|---|---|
| Projection schema and external-content FTS maintenance | migration 38 | legacy search query |
| Pure batch, budget-ledger, and retention decisions | application planner/types | SQLite adapter and CLI |
| Bounded selection/hydration and exact plan persistence | SQLite adapter (`SelectSnapshot` / `ApplyBatch` / `CleanupBatch`) | CLI |
| Metadata-only reporting | existing capacity inspection plus projection state | search response |

### Boundaries / interfaces

The application planner accepts an immutable snapshot and produces a pure `ProjectionBatchPlan`, `BudgetLedger`, and `ProjectionRetentionPlan`. SQLite exposes only bounded selection/hydration and apply/cleanup persistence operations. Source, eviction, cleanup, and complete phases are durable; a crash can repeat only the last uncommitted phase. Wall time covers every read and hydration call. Lock time starts immediately before `Start`/apply transactions. Logical bytes plus conservative WAL reservation share the write hard cap. Errors name a payload class, never payload contents.

### Behavior tests

| Behavior | Given | When | Then | Level |
|---|---|---|---|---|
| deterministic eviction | equal-age rows over byte cap | rebuild | oldest timestamp then ID is removed | SQLite integration |
| resumable bounded rebuild | more rows than every cap | repeated rebuild | checkpoint advances by committed prefixes and final state is idempotent | SQLite integration |
| canonical hydration | identity/zstd canonical fields | rebuild | equal projections result | SQLite integration |
| aggregate/keywords | repeated session commands and failures | rebuild twice | identical counts, summary, and normalized keywords | SQLite integration |
| FTS capability | bundled modernc SQLite | semantic insert/update/delete probe | result is recorded; schema still declares external-content design | migration test |
| authority | existing search suite | migration/rebuild present | legacy query results remain unchanged | integration |

### TDD plan

Migration/schema probe -> bounded prefix/checkpoint -> canonical hydration -> deterministic aggregate/keywords -> age/byte eviction -> metadata-only status -> full legacy search regression.

### Risks / rollback

- Procedural risk is contained in one infrastructure projection builder; SQL schema owns storage/index synchronization and application search is untouched.
- Migration is additive. Rollback is to stop rebuilding and ignore/drop derived objects in a later reviewed migration; canonical rows are never mutated.
- A corrupt/oversize payload aborts without advancing the checkpoint and without payload evidence.
- Design checkpoint: external-content FTS is selected even when `contentless_delete` works because deterministic capacity attribution requires a materialized content table and older-reader portability matters more than saving its pages.


### Corrective design checkpoint

The application use case now owns the explicit `StartGeneration` / `Resume` / `Inspect` state machine and immutable budget configuration. SQLite freezes source membership by monotonic `rowid`; later inserts are deferred, while updates/deletes and command-audit changes increment a mutation revision and fail resume with a typed drift error. Selection and codec hydration occur outside the short apply/checkpoint transaction. The transaction compares the frozen revision, writes one bounded prefix, performs bounded eviction, and advances its checkpoint atomically. Generations coexist, avoiding unbounded reset deletes.

Retention uses fixed UTC `created_at_norm`; unavailable event bodies are never hydrated. Stored-byte reservations use physical column lengths, decoded reservations use codec metadata, and write reservations include content, FTS duplication, summaries, aggregates, and versioned keywords. A row that cannot fit produces a typed oversize error rather than a successful zero-progress result. Status is payload-free and reports logical classes, dbstat-attributed physical bytes when available, latency, state, version, and source provenance.
