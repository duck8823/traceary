# Issue 2448: provenance boundary characterization

## Requirements and model
Characterize the existing extraction → candidate → explicit review/distill → export boundary without changing production trust policy. Source labels and evidence references are lineage, not authenticated authorship or action authorization. Unknown trust must stay unknown. Synthetic fixtures only.

## Responsibilities and boundaries
Existing MemoryUsecase owns lifecycle operations; no new usecase, schema, hash/receipt or authority classifier. New external-package tests exercise its public methods using existing repository/query fakes; extraction uses actual extraction logic with synthetic event query inputs. Existing SQLite tests remain responsible for query enforcement; export tests pin the criteria sent to that consumer. Bilingual guide owns limitations and operator responsibilities, not a new automatic gate.

## Behavior tests / TDD
Add characterization tests for direct preference, quoted/tool-like authority, assistant summary, imported/stale text and secret-like payloads. Require all extraction/proposal paths to remain candidates; legitimate examples must not disappear. Trace sanitized exact fact, source, evidence, scope and validity through explicit Accept and Distill; assert export accepted-only/scoped/current criteria and document output's intentionally reduced lineage. Characterization tests may start green; they pin current behavior, not claim a discovered vulnerability was fixed.

## Risks / rollback
Medium tests/docs-only; production authorization and persistence semantics unchanged. No inference that accepted memory is permission. No guarantee against arbitrary prompt injection. Changed external evidence is not content-pinned; reviewer must re-open evidence and re-review changed content. New snapshot/schema enforcement requires a separate High-risk checkpoint. Rollback this issue's tests/docs; no migration. Host-model trials are optional and unmeasured here.
