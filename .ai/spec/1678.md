# Issue 1678: store-side attestation anchor

## Structure-Behavior Design Note

Risk: **Medium** — new sidecar file on the write path, doctor on small
vs large stores, compact verify. Not High: no new CLI tree, no live-store
walk, no backfill of history.

### Requirement summary

- 目的: 鎖の head を store ファイルの外にも残し、既存経路で照合する。
- 現状: #1677 が SQLite 内に鎖を書く。doctor / ファイル anchor は未実装。
- 期待する振る舞い:
  - 新しい attested 書き込みの commit 後、`{store}.attest` に 1 行足す
  - ファイルは append-only。同じ seq で違う head が混ざれば壊れている
  - doctor（2 GiB 未満）は鎖を Verify し、末尾行と head を照合する。
    ファイルが無い / 遅れているだけなら Verify 成功後に追記して pass
  - doctor（2 GiB 以上）は SQLite を開かない。ファイルの構文と履歴だけ見る
  - compact `VerifyPair` は candidate（と source）の鎖を Verify する
  - `traceary attest` は作らない
- 非対象: 親 #1693 の close、#1870 の close、tag、歴史 backfill。

### Conceptual model

| Concept | State | Behavior | Constraint / Invariant |
|---|---|---|---|
| Anchor file | `{storePath}.attest` JSONL | commit 後に 1 行 | 0600。rewrite しない |
| Anchor record | v, seq, head, at | 末尾が最新 published head | seq は非減少。同 seq は同 head |
| Publish | last != store head | append | 鎖の中身は書かない |
| Doctor small | file + Verify + head | 遅れは追記して pass | 不一致 / ファイル先行は fail |
| Doctor large | file only | 開かない | 30 GiB を歩かない |
| Compact verify | VerifyAttestationChain | candidate が壊れていれば拒否 | 新コマンドなし |

### Responsibility assignment

| Responsibility | Owner | Reason to change | Not owner / reason |
|---|---|---|---|
| 行の意味 | `domain/attestation` | フォーマット | I/O を持たない |
| いつ足すか | `saveEventTransaction` の commit 後 | 書き込み経路 | doctor は遅れを直すだけ |
| ファイル I/O | sqlite adapter | パス規約 | CLI は開かない |
| 照合の見せ方 | doctor / VerifyPair | 既存経路 | `traceary attest` を作らない |

### Boundaries / interfaces

| Boundary or interface | Consumer | Hidden detail | Error contract |
|---|---|---|---|

### Risks / rollback

- behind は「store が進んだ」だけでは足りない。sidecar 末尾の seq に対応する検証済み link head（seq 0 は genesis）と一致するときだけ追記する。歴史 head が違う forged-behind は mismatch で fail。
- doctor の照合と追記は Verify と同じ read snapshot の seq/head だけを使う。Verify 後の別クエリはしない。
- sidecar の read→判定→append は process mutex + `{store}.attest.lock` で直列化する。逆転した seq は後勝ちせず、後続は file-ahead として拒否する。
- 同じ seq で head が違う、またはファイルが store より先のときは追記しない（壊れたファイルを悪化させない）。
- Save / Inspect は操作開始時の storePath を snapshot し、open と sidecar の両方に同じ値を使う。
- Save 後の publish 失敗は Save を失敗させない（イベントは既に commit）。doctor が遅れを直す。
- 大店 doctor は Verify しない（#1677 と同じ「open で歩かない」）。
- compact は SQLite sidecar（-wal/-shm/-journal）だけを見る。`.attest` は拒否しない。
- rollback: ファイルを消しても store は動く。doctor が作り直す。
