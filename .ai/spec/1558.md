# #1558 Multi-GiB release evidence

## Structure-Behavior Design Note

### Requirement summary

- **Purpose:** Produce release evidence that metadata discovery, bounded event
  inspection, indexed search, and aggregate MCP responses remain bounded on a
  multi-GiB-class SQLite store without publishing event content or local
  identities.
- **Dependency:** The evidence branch is rebased onto `main` at `6641c6d7`,
  which contains the merged #1567 memory-hygiene work and the #1570 persistent
  event-metadata projection. The evidence must exercise those merged runtime
  paths rather than carrying either implementation in this PR.
- **Phase A:** Run the existing opt-in direct metadata benchmark with eight
  synthetic 256 MiB extents. Both SQLite-managed bytes and stored-body metadata
  must reach 2 GiB, all eight event rows must have matching projection rows,
  the ordered plan must read only the projection, every timed scan must return
  all eight rows without an iteration error, returned body bytes must be zero,
  25 measurements are required, and p95 must remain below 250 ms.
- **Phase B:** Create a private synthetic pre-migration store, copy it, apply
  migrations 31 through 34 on the copy, and record only migration duration,
  projection-row parity, integrity/foreign-key results, scratch extent, FTS
  progress, and whether the source stayed byte-identical. The first
  128-document backfill must remain observably incomplete before a resumed
  batch completes it.
- **Phase C:** Record 25-run p95 observations for metadata and bounded
  list/context/search projections. Search is measured separately while FTS
  backfill is incomplete and complete. Every probe uses the 130-event fixture
  with limit 20, returns exactly 20 items, and preserves identical membership
  between metadata and bounded projections. Metadata returns zero body bytes;
  bounded projections return a positive byte count. These surface observations
  have no release pass/fail latency target until the Issue fixes one; only Phase
  A's 250 ms p95 is a gate.
- **Phase D:** Exercise the MCP aggregate response with a requested limit of
  100, the 65,536-byte encoded body budget, multibyte text, canonical
  `body_blocks`, observable response-truncation metadata, and continuation
  traversal that proves no duplicate or skipped item.
- **Phase E:** Verify all six packaged hosts retain the same MCP command and
  byte-identical staged-retrieval skills whose semantic contract requires
  Discovery, bounded Inspection, and single-event Detail.
- **Tagged-release gate:** The v0.33.0 release workflow must validate the
  committed pass artifact before GoReleaser can publish the tagged release.
- **Privacy:** The durable artifact is a metrics-only `BodyFreeEvidence`
  document. It never contains bodies, prompts, responses, event/session IDs,
  workspaces, local paths, continuations, raw command output, or fixture logs.
  Verification reads at most the 1 MiB artifact limit plus one detection byte
  and rejects oversized input before JSON decoding. Scratch storage is
  owner-only and is removed on every terminal path.
- **Blocked hosts:** Disk/capability preflight produces a sanitized blocked
  evidence document instead of attempting the multi-GiB run. It contains only
  required/available byte counts and a fixed reason.
- **Out of scope:** Reading a live user store, publishing raw benchmark output,
  setting new latency targets for Phase C, or changing the merged runtime
  event/search/projection behavior.

### Conceptual model

| Concept | State | Behavior | Constraint / invariant |
| --- | --- | --- | --- |
| Synthetic extent | Eight generated, content-free 256 MiB SQLite values plus eight trigger-maintained projection rows | Makes page and stored-byte scale real without using user data | Managed and stored bytes are each at least 2 GiB; event/projection counts match; the measured plan is projection-only; each timed scan returns all eight rows without iteration error |
| Copied migration store | Private pre-31 source plus an isolated copy | Applies migrations 31 through 34 and resumable FTS backfill only to the copy | Source digest is unchanged; only the copy is mutated; projection count equals event count |
| FTS phase | `incomplete` after the first 128-document batch, then `complete` | Labels search probe series | Incomplete and complete observations are never merged into one latency sample |
| Projection probe | Operation, projection, FTS phase, run count, p95, returned item/body-byte counts, in-memory membership digest | Measures one public read shape 25 times | All eight series return 20 items from the 130-event fixture; metadata and bounded membership match; metadata bytes are zero and bounded bytes are positive; Phase-C p95 is observation-only |
| Aggregate evidence | Maximum and observed item/body-byte counts plus content-shape booleans | Proves page, truncation-metadata, and continuation invariants | At most 100 items and 65,536 encoded body bytes per page; truncation metadata is observable; all synthetic items are visited once |
| Host integration parity | Six packaged host copies | Runs the shared integration and staged-retrieval semantic verifier | MCP registration and Discovery → Inspection → Detail guidance agree across every host |
| `BodyFreeEvidence` | Versioned pass or blocked JSON document | Carries only fixed enums, booleans, counts, durations, and public runtime dimensions | Sensitive keys and arbitrary strings are rejected before write |
| Private scratch | Owner-only temporary directory | Contains synthetic stores and Go test temporary files only while the run is active | Mode is private before any fixture write and the directory is absent before pass evidence is emitted |
| Tagged-release gate | v0.33.0 tag or explicit recovery dispatch | Runs the strict artifact verifier before GoReleaser | A missing, blocked, malformed, or privacy-invalid artifact stops publication |

### Responsibility assignment

| Responsibility | Owner | Reason to change | Not owner / reason |
| --- | --- | --- | --- |
| Multi-GiB fixture, migration, query probes, and numeric phase markers | `infrastructure/sqlite` opt-in benchmarks | Query plans, migrations, FTS state, and store bytes are SQLite concerns | Repo tooling must not duplicate production SQL |
| Aggregate/body-block/continuation evidence marker | `presentation/mcpserver` integration test | It observes the actual MCP response budget and opaque continuation behavior | SQLite does not own transport aggregation |
| Preflight, child orchestration, scratch lifecycle, host parity, evidence merge/validation | `cmd/repo-tooling release` | This is maintainer-only release automation | The shipped `traceary` binary must not expose a QA command |
| Evidence interpretation and release boundary | bilingual release documentation | Operators need a stable procedure and explicit non-claims | Test logs are not durable release documentation |
| Tagged-release enforcement | `.github/workflows/release.yml` | Publication order and tag recovery are workflow concerns | Documentation cannot block GoReleaser |

### Boundaries / interfaces

| Boundary or interface | Consumer | Hidden detail | Error contract |
| --- | --- | --- | --- |
| Opt-in benchmark markers | repo-tooling runner | Store paths, synthetic IDs, SQL, raw child output | Missing/malformed markers become a fixed phase failure; captured output is not echoed |
| Aggregate test marker | repo-tooling runner | Bodies, body blocks, event IDs, encrypted cursor | Reports only counts/booleans and fails before emitting on duplicate/skip or budget breach |
| `BodyFreeEvidence` validator | release workflow/operator | Child process output and scratch location | Reads max+1 bytes, rejects input over 1 MiB before decoding, and rejects unknown fields, sensitive keys, invalid enums, failed gates, incorrect probe counts, or invalid projection byte counts |
| Disk preflight | evidence runner | Filesystem path and mount identity | Below the fixed scratch headroom returns `status=blocked` with numeric capacity only |
| Scratch directory | benchmark child | Local temporary path | Creation/privacy/cleanup failures prevent `status=pass` |

### Risks / rollback

- **Procedural-logic risk:** An orchestrator could accidentally treat Phase-C
  observations as gates. Validation applies a latency threshold only to Phase A;
  Phase C has no `passed` field.
- **Privacy risk:** Child Go output can contain local paths or synthetic IDs on
  failure. Repo tooling captures it in memory, never includes it in evidence,
  requires confirmed scratch removal before writing a validated artifact, and
  rejects artifact input over 1 MiB before parsing any valid prefix.
- **Resource risk:** A true 2 GiB SQLite fixture needs substantially more free
  space while copying and indexing. Preflight requires conservative headroom
  and emits blocked evidence rather than filling the disk.
- **Migration/compatibility:** This PR changes tests, repo tooling, and docs
  only. Migration 34 is already merged through #1570; this evidence applies it
  only to a synthetic copy and never mutates a live store.
- **Dependency/rollback:** #1567 and #1570 are merged dependencies. Any change
  to their main-branch revisions requires a complete evidence rerun. Reverting
  this PR removes only release automation/evidence; no user data rollback
  exists.
- **Rollback trigger:** Any body/ID/path/cursor in the durable artifact,
  scratch surviving termination, source-copy mismatch, Phase-A p95 failure,
  integrity/FK failure, FTS phase ambiguity, aggregate overflow, continuation
  gap/duplicate, or host parity failure blocks release.
- **Split PR plan:** Keep the schema/runner, opt-in probes, aggregate marker,
  and release documentation in this one #1558 PR because none is meaningful
  release evidence without the privacy validator and cleanup owner.

## Implementation checkpoint

Proceed with repo-tooling-owned orchestration, test-only SQLite/MCP probes, and
strict metrics-only serialization. Do not add a user-facing command, read a
live store, or assign Phase-C latency pass/fail targets.

## Historical Phase-A blocker and accepted resolution

The accepted-host run proved that the Phase-A failure is not setup time leaking
into the measurement. Fixture creation, migration, checkpointing, extent
verification, and query-plan inspection all occur before the 25 manual timers.
Each timer covers only `QueryContext`, row scanning, and `Rows.Close`.

The pre-#1570 production query plan used
`idx_events_workspace_created_at_norm_id_desc`, sought both timestamp bounds,
and creates no temporary order-by tree. It is not a covering plan. SQLite's
`events` record stores `body` before `created_at`, client/workspace metadata,
and the body-extent metadata. SQLite's documented table-lookup and linked
overflow-page mechanics, combined with the controlled result below, support
the inference that restoring those selected columns follows each 256 MiB
body's overflow chain even though `body` is absent from the SELECT list.

A local diagnostic created one temporary covering workspace index on the same
2 GiB fixture outside the measurement timer. The identical 25-run query
measured p95 0.088750 ms. Production-schema runs measured 605.756875 ms and,
under heavier host I/O pressure, 4,159.414709 ms. This diagnostic is not release
evidence because the temporary index is not part of the production schema. It
isolates the non-covering table lookup as the blocker while showing that host
I/O conditions affect the magnitude.

Issue #1569 selected a narrow, trigger-maintained metadata projection and PR
#1570 merged it as migration 34. Metadata list/context queries now read the
projection through ordered projection indexes without consulting `events`.
This evidence PR does not reimplement that decision; it makes projection-only
planning, row parity, zero returned body bytes, and the original 250 ms target
observable release gates.

### Options considered

| Option | Decision | Reason |
| --- | --- | --- |
| Change the fixture, timer, or 250 ms target | reject | The fixture and timing match the accepted #1553/#1558 contract; weakening them would hide the physical body read |
| Rebuild the five ordered indexes as covering indexes | rejected by #1569 | Wider duplicated indexes increase steady-state storage and write cost |
| Add one metadata-cover index plus explicit joins | rejected by #1569 | Query joins add another compatibility and planner boundary |
| Add a narrow maintained metadata projection | accepted in #1569/#1570 | It makes payload-free reads explicit; migration, trigger parity, lock behavior, and rollback are independently tested |

The previous blocked artifact remains historical evidence only. Release
readiness now depends on a complete rerun against merged migration 34; no
pre-#1570 latency may be reused.

## Post-#1570 evidence checkpoint

The branch was rebased onto `main` at `6641c6d7`, which contains merged PRs
#1567 and #1570. The complete runner then produced a new metrics-only artifact
with `status=pass`; no value from the pre-projection blocked artifact was
carried forward.

- Phase A recorded 2,418,774,016 managed bytes, 2,147,483,648 stored-body
  bytes, eight event/projection rows, zero missing metadata, a projection-only
  ordered plan, eight returned items per scan, zero returned body bytes, and 25
  measurements.
- Phase-A p95 was 0.074625 ms against the unchanged 250 ms target.
- Phase B applied migrations 31 through 34 to the copy, recorded 130 projection
  rows for 130 events, preserved the source byte-for-byte, passed integrity and
  foreign-key checks, and completed the resumed 128-to-130 FTS transition.
- Phase C completed all eight 25-run probes against the 130-event fixture with
  limit 20. Every probe returned exactly 20 items; metadata/bounded membership
  matched for list, context, incomplete search, and complete search; metadata
  bytes were zero; bounded bytes were positive. Its latencies remain
  observations only. Phases D and E also passed.
- The owner-only scratch directory was absent before the validated artifact was
  written.
- The tagged-release workflow verifies this committed pass artifact before
  GoReleaser when `RELEASE_TAG` is exactly `v0.33.0`.

This checkpoint satisfies the #1558 gate. It does not decide unrelated release
checks, and any change to the merged projection, migrations, FTS behavior,
aggregate budget, host manifests, or Go runtime requires a complete rerun.
