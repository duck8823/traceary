# Issue 2447: matched memory usefulness evaluation

## Requirement and model
Version a synthetic offline corpus and a reproducible comparison harness. A Task owns frozen question/options/expected answer/supporting fragments, cutoff and held-out family. An Arm owns delivered context and bounded retrieval metrics. A Response receipt binds an exact prompt digest, host/model, usage, cost and answer. Evidence coverage and task behavior are separate scores; missing responses are unmeasured, never losses or synthetic wins.

## Responsibilities / interfaces
Python stdlib experiment script prepares throwaway stores through the real CLI and builds no-history, metadata-first staged, and handoff+accepted-memory inputs. It never reads live stores or launches a model/network provider. Scoring consumes optional explicitly supplied response receipts, checks hashes/versions and matched model/budget before reporting paired outcomes. Pure unit tests own scorer/input validation; one Go wrapper runs them in normal go test. Main session may separately run a bounded authenticated host trial with tools disabled and only these synthetic prompts, preserving host guards; host failure is recorded and not replaced silently.

## Behavior / TDD
Freeze corpus before execution; keep expected answers out of model inputs. Test incorrect answers, missing/foreign evidence, stale policy, scope spill, tampered prompt hashes, invalid/missing usage, mismatched model and absent response arms. Prepare real CLI fixtures after pure tests pass and measure retrieval calls/bytes/latency, setup/consolidation overhead separately. No default retrieval changes, new schema or release threshold. Mark optional reranking unavailable. Decision-change is calibration; four separate task families remain held out from prompt/skill tuning. No reported generalization from this small convenience sample.

## Risk / rollback
Medium experimental harness; no production behavior changes. No private logs, secret access, embeddings or automatic model calls. Atomic-ish local report output contains only synthetic payloads and minimized response receipts. Rollback removes experiment files; throwaway stores are not migrated into production. Decision may be defer when host trials are unavailable or benefit/cost is uncertain.
