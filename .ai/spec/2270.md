## 1. Structure-Behavior Design Note

### 1.1 Requirement

`traceary` prints a stderr trailer after most commands telling the operator the store "can reclaim space". Today it prints that whenever the **file** is at least 1 GiB. On the operator's live store (~14 GiB, freelist 0) `traceary doctor` reports `reclaimable=0 B` and PASSes while the trailer still fires in the same session. Two surfaces of the same product contradict each other, and the one that interrupts every command is the one that is wrong.

The trailer must become a claim the product can defend: it may only fire when the store actually holds reclaimable pages, measured by the same O(1) signal `doctor` already uses.

### 1.2 Concept model

| Concept | Meaning | Where it lives today |
|---|---|---|
| **Store file bytes** | `os.Stat(path).Size()` — includes pages in use, free pages, and nothing about what a rewrite would recover. | `compact_reclaim_warning.go:35` |
| **Database bytes** | `page_size × page_count`. The SQLite-visible size of the main file. | `apptypes.StorePageMetadata.DatabaseBytes`, set at `infrastructure/sqlite/page_metadata_inspector.go:54` |
| **Reclaimable bytes (O(1))** | `page_size × freelist_count`. Pages SQLite already considers free; a rewrite returns exactly these to the filesystem. | `StorePageMetadata.ReclaimableBytes`, `page_metadata_inspector.go:55` |
| **Discardable transcript bytes** | A cutoff-dependent estimate of body text a `store compact` *would* drop. Not O(1); needs a scan of `event_metadata_projection`. | `infrastructure/sqlite/compaction_copy_filter.go` `inspectReclaimableBytes` — **explicitly out of scope, see §9** |
| **Reclaim rule** | The predicate "these reclaimable bytes are worth telling a human about". Currently duplicated as an inline expression in two places in `doctor_store_size.go`. | `doctor_store_size.go:393` and `:497` |
| **Warning marker** | `<db>.reclaim-warn`, an RFC3339Nano timestamp, rate-limits the trailer to once per 24 h. | `compact_reclaim_warning.go:66-88` |

The defect is a **missing concept**: there is no shared "reclaim rule" object. Doctor computes one from page metadata; the trailer computes an unrelated one from file size. The fix is to name the rule once and let both surfaces read it, parameterised only by the floor each surface owns.

### 1.3 Responsibility table

| Component | Responsibility | Must not |
|---|---|---|
| `reclaimableWarrantsCompact` (new, `presentation/cli/reclaimable_rule.go`) | Pure decision: given reclaimable bytes, a size to compare against, and a caller-owned floor, is this worth reporting? | Read config, touch the filesystem, or know which surface is calling. |
| `RootCLI.emitCompactReclaimWarning` | Decide whether *this invocation* should measure, measure via the injected inspector, apply the rule, print, and record the marker. | Open the store when the marker suppresses it or when the file is too small to possibly qualify. Warn on an unknown/failed measurement. |
| `application.PageMetadataInspector` (unchanged) | Produce O(1) page accounting from a path. | Change at all in this PR. |
| `evaluateStoreGrowthBudget` / `evaluateLargeStoreGrowthBudget` | Doctor's store-size verdicts. | Change their thresholds, their ratio, their reasons, or their message text. They only swap an inline expression for a call that computes the identical boolean. |
| `presentation.CompactConfig.ReclaimWarnBytes` | The warning's floor, in **reclaimable** bytes. Explicit `0` disables. Default 1 GiB. | Gain a sibling key, change its default, or change its JSON name. |

### 1.4 Boundaries and interfaces

The trailer currently runs as a package-level function attached to `rootCmd.PersistentPostRun`. It has no access to `RootCLI`, which is why it could only reach for `os.Stat`. The boundary change is small and one-directional: **`attachCompactReclaimWarning` and `emitCompactReclaimWarning` become `*RootCLI` methods**, so the closure can reach `c.pageMetadataInspector`, the same dependency `doctor` already receives (`root.go:47`, injected at `main.go:249`).

No new interface is introduced. No layer is crossed: the inspector interface already lives in `application`, its SQLite implementation in `infrastructure`, and both doctor and the trailer are `presentation/cli` callers.

### 1.5 Behaviour contract (what a test must be able to state)

1. A store whose file is large but whose freelist is empty produces **no** trailer, no matter how large the file is, and writes no marker.
2. A store whose reclaimable bytes meet both the floor and the ratio produces exactly one trailer per 24 h; the marker is written only when a trailer was printed.
3. A store smaller than the floor is never opened for inspection (a file of N bytes cannot hold ≥ N+1 reclaimable bytes).
4. While the 24 h marker suppresses the trailer, the store is never opened for inspection.
5. Any measurement failure — no inspector injected, inspector error, timeout, locked store — produces silence, never a trailer and never a marker. Unknown is not a reason to interrupt an operator.
6. `compact.reclaim_warn_bytes: 0` disables the trailer before any filesystem work.
7. Doctor's `store-size` check output is byte-identical to HEAD for every input.

### 1.6 Fail-soft rationale (why silence, not a hedged warning)

`doctor` is the surface that reports uncertainty (`unknownStoreGrowthCheck`, `doctor_store_size.go:381`) — it is on-demand and the operator asked for a diagnosis. The trailer is uninvited output appended to unrelated commands. An uninvited "I could not tell" line has negative value: it interrupts without being actionable. Therefore every unknown collapses to silence, and `doctor` remains the place where "unknown" is said out loud.

## 3. Decision

**Unify the signal; keep the floors separate.** (Owner decision on the issue, 2026-08-28. Do not reopen it.)

Both surfaces answer the same question with the same numbers:

```
reclaimable = page_size × freelist_count          (O(1) pragma read, already implemented)
worth reporting  ⇔  reclaimable ≥ floor  AND  reclaimable ≥ 10% of compareAgainst
```

- `compareAgainst = maxInt64(fileBytes, DatabaseBytes)` — identical to the O(1) doctor path at `doctor_store_size.go:493-496`.
- **Warning floor** = `cfg.Compact.ReclaimWarnBytes`, default **1 GiB**. It interrupts every CLI call, so it stays conservative. Explicit `0` disables.
- **Doctor floor** = **256 MiB**, unchanged. Doctor is on-demand and informational, so it may speak sooner.
- **Ratio** = 10 %, one constant, shared. This is the "consistent with doctor's warn ratio" the acceptance criteria asks for: the *shape* of the rule is identical and the *floor* is the only per-surface parameter.

Consequence, stated plainly for the changelog and docs: a store holding between 256 MiB and 1 GiB of free pages (that also clears 10 %) is reported by `doctor` and stays quiet in the trailer. That asymmetry is deliberate and is the answer to "how loud should each surface be", not "what is true". The contradiction the issue reports — one surface saying 0 B while the other warns — becomes structurally impossible, because both now read the same number.

### 3.1 Cost control

The inspector opens the store (`mode=ro`, one connection, `busy_timeout(0)`). Three guards keep this off the hot path:

1. **Size pre-filter first.** A file of `S` bytes cannot contain `≥ floor` reclaimable bytes when `S < floor`, because free pages are a subset of the main database file. One `os.Stat` rejects every normal small store before any marker read or DB open. This preserves the existing statement order at `compact_reclaim_warning.go:35-41` exactly, which keeps the diff minimal.
2. **Marker second.** While the 24 h window is open, return before opening the store. Costs one `os.ReadFile` of a tiny file, only for stores already past the floor.
3. **Timeout third.** Reuse `inspectLargeStorePageMetadata` (`doctor_store_size.go:458`), which bounds the read at `largeStoreO1InspectTimeout` (500 ms) and returns `errLargeStorePageMetadataUnavailable` when no inspector is injected.

So the added cost is: for stores under the floor, zero; for stores over the floor, one bounded read-only open at most once per 24 h.

## 5. Go shapes

### 5.1 `presentation/cli/reclaimable_rule.go` (new)

```go
package cli

// doctorReclaimableWarnBytes is the floor `doctor` uses before it names
// reclaimable pages as a store-growth reason. Doctor is on-demand and
// informational, so it speaks sooner than the post-run trailer, whose floor is
// the operator-visible compact.reclaim_warn_bytes (default 1 GiB).
const doctorReclaimableWarnBytes int64 = 256 << 20

// reclaimableWarnRatioPercent keeps a reclaim report proportional: free pages
// worth less than this share of the store are not worth a rewrite.
const reclaimableWarnRatioPercent = 10

// reclaimableWarrantsCompact is the single reclaim rule shared by doctor's
// store-size checks and the post-run stderr trailer. reclaimable is always
// page_size * freelist_count (the O(1) pragma signal); compareAgainst is the
// larger of the filesystem size and page_size * page_count. A floor of zero or
// less disables the rule, which is how compact.reclaim_warn_bytes: 0 turns the
// trailer off.
func reclaimableWarrantsCompact(reclaimable, compareAgainst, floor int64) bool {
	if floor <= 0 || reclaimable < floor {
		return false
	}
	return ratioAtLeast(reclaimable, compareAgainst, reclaimableWarnRatioPercent)
}
```

`ratioAtLeast` (`doctor_store_size.go:424`) is reused as-is: it is already overflow-safe with ceiling division and pinned by `TestRatioAtLeastIsOverflowSafe`.

func (c *RootCLI) attachCompactReclaimWarning(root *cobra.Command) {
	root.PersistentPostRun = func(cmd *cobra.Command, _ []string) {
		c.emitCompactReclaimWarning(cmd)
	}
}

func (c *RootCLI) emitCompactReclaimWarning(cmd *cobra.Command) {
	if shouldSkipCompactReclaimWarning(cmd) {
		return
	}
	cfg := presentation.LoadConfig()
	floor := cfg.Compact.ReclaimWarnBytes
	if floor <= 0 {
		return
	}
	path, err := resolveDBPath(lookupDBPathFlag(cmd))
	if err != nil || path == "" {
		return
	}
	info, err := os.Stat(path)
	if err != nil {
		return
	}
	// A file smaller than the floor cannot hold `floor` reclaimable bytes, so
	// the cheap stat still short-circuits before any store open. It is no
	// longer sufficient on its own: free pages, not file size, decide.
	if info.Size() < floor {
		return
	}
	now := compactReclaimNow()
	if !shouldEmitCompactReclaimWarning(path, now) {
		return
	}
	meta, err := c.inspectReclaimWarningPageMetadata(cmd, path)
	if err != nil {
		// Unknown is not a reason to interrupt: doctor is where uncertainty is
		// reported, this trailer is uninvited output on unrelated commands.
		return
	}
	if !reclaimableWarrantsCompact(meta.ReclaimableBytes, maxInt64(info.Size(), meta.DatabaseBytes), floor) {
		return
	}
	message := compactReclaimWarningMessage(path, info.Size(), meta.ReclaimableBytes)
	_, _ = fmt.Fprintf(cmd.ErrOrStderr(), "%s\n", message)
	_ = recordCompactReclaimWarning(path, now)
}

// inspectReclaimWarningPageMetadata reads the same O(1) page accounting doctor
// reads, bounded by largeStoreO1InspectTimeout. cmd.Context() is non-nil under
// cobra's Execute, but the guard keeps direct method calls in tests valid.
func (c *RootCLI) inspectReclaimWarningPageMetadata(cmd *cobra.Command, path string) (apptypes.StorePageMetadata, error) {
	ctx := cmd.Context()
	if ctx == nil {
		ctx = context.Background()
	}
	return c.inspectLargeStorePageMetadata(ctx, path)
}

### `docs/storage/README.md` — insert after the bullet list at `:174`, inside `## compact defaults`

> **Reclaim warning.** After a non-hook command, Traceary may print `TRACEARY: store can reclaim about <size>; run traceary store compact` on stderr, at most once every 24 hours per store (tracked in `<db>.reclaim-warn`). It appears only when the store's free-page list — `PRAGMA freelist_count × PRAGMA page_size`, the same O(1) signal `traceary doctor` reports as `reclaimable=` — is at least `compact.reclaim_warn_bytes` (default 1 GiB) **and** at least 10 % of the store. File size alone never triggers it: a 14 GiB store with an empty freelist stays quiet, because a rewrite would return nothing to the filesystem. `doctor` uses the same signal and the same 10 % ratio with a lower floor of 256 MiB, so it can report reclaimable pages that the trailer stays quiet about; it never reports fewer. Set `compact.reclaim_warn_bytes` to `0` to silence the trailer. When the store cannot be read cheaply (a writer holds it, or the read exceeds 500 ms) nothing is printed — `traceary doctor` is where an unknown store-growth signal is reported.
>
> Free pages are not the same as the bytes `store compact` can recover: compact also discards covered transcript bodies and re-encodes audit text, which this O(1) signal cannot see. `traceary store compact --dry-run` is the surface for that estimate.

### 8.2 Purpose-gated live check — **on a copy only**

> I could not run this: the sandbox for this design session blocks reading outside the worktree, so `~/.config/traceary/traceary.db` was never opened or copied here. Rules: copy first, never point a repo build at `~/.config/traceary/traceary.db` (an unreleased migration would be applied and the brew build could not read it back), never `SELECT` an event / audit / projection body.

```sh
# 1. Copy the store AND its WAL sidecars. A WAL-mode database copied alone can
#    fail to open with mode=ro, which would make the trailer fail-soft-silent
#    for the wrong reason and produce a false pass in step 3.
cp ~/.config/traceary/traceary.db      /tmp/tr2270.db
cp ~/.config/traceary/traceary.db-wal  /tmp/tr2270.db-wal 2>/dev/null || true
cp ~/.config/traceary/traceary.db-shm  /tmp/tr2270.db-shm 2>/dev/null || true

# 2. The O(1) facts both surfaces must agree on. Metadata only, no bodies.
sqlite3 /tmp/tr2270.db "PRAGMA query_only=1;
  SELECT page_size, page_count, freelist_count,
         page_size*freelist_count AS reclaimable,
         page_size*page_count     AS db_bytes
  FROM pragma_page_size, pragma_page_count, pragma_freelist_count;"

# 3. Trailer must be silent on the live copy (freelist 0) ...
rm -f /tmp/tr2270.db.reclaim-warn
go run . list --limit 1 --db-path /tmp/tr2270.db 2>&1 >/dev/null | grep -c 'can reclaim'   # expect 0

# 4. ... and it must be silent because reclaimable is 0, not because the read
#     failed. doctor must PASS with an explicit reclaimable=0 B, not "unknown".
go run . doctor --db-path /tmp/tr2270.db --json --warnings-ok | grep -o '"name":"store-size".*' | head -1
```

**Step 4 is the whole point of the gate.** Silence in step 3 alone proves nothing — a failed open produces the same silence. Only a `store-size` PASS reporting `reclaimable=0 B` (not `store growth signals are unknown`) shows that the trailer measured, saw zero, and chose silence.

Positive case, on a **scratch** copy of the copy (never the original):

```sh
cp /tmp/tr2270.db /tmp/tr2270-free.db
rm -f /tmp/tr2270-free.db-wal /tmp/tr2270-free.db-shm
# Manufacture free pages without reading any body text.
sqlite3 /tmp/tr2270-free.db "PRAGMA journal_mode=DELETE; DELETE FROM command_audits WHERE rowid IN (SELECT rowid FROM command_audits LIMIT 300000);"
sqlite3 /tmp/tr2270-free.db "PRAGMA query_only=1; SELECT page_size*freelist_count FROM pragma_page_size, pragma_freelist_count;"
rm -f /tmp/tr2270-free.db.reclaim-warn
go run . list --limit 1 --db-path /tmp/tr2270-free.db 2>&1 >/dev/null | grep 'can reclaim'    # expect 1 line, with a size
go run . list --limit 1 --db-path /tmp/tr2270-free.db 2>&1 >/dev/null | grep -c 'can reclaim' # expect 0 (marker)
go run . doctor --db-path /tmp/tr2270-free.db --json --warnings-ok | grep -o 'reclaimable=[^ "]*'
```

The printed figure and doctor's `reclaimable=` must be the **same number**. If the delete does not clear the floor and ratio, note the measured value in the PR rather than deleting more; the synthetic case is already covered by the unit tests, and this gate exists to prove agreement, not to force a warning.

Record in the PR body: the copy's `page_size / freelist_count / reclaimable / db_bytes`, the step-3 count, the step-4 `store-size` line, and either the positive-case figures or the reason the scratch store did not qualify.

## 9. Risks

| Risk | Assessment |
|---|---|
| **Extra store open per command** | Bounded by: size pre-filter (rejects every store under 1 GiB with one `os.Stat`), 24 h marker (at most one open per day per store), 500 ms timeout, `mode=ro` single connection. Rollback is reverting one file. |
| **`busy_timeout(0)` + a concurrent hook writer** → the open fails and the trailer is silent | Intended. A writer holding the store is exactly when an operator should not be interrupted, and the marker is not written, so the next command retries. The failure mode is a *missed* nudge, never a false one. |
| **WAL sidecar absent on a copied store** → `mode=ro` open fails → silence | A correctness trap for the §8.2 gate, not for production (the live store always has its sidecars). Mitigated by copying `-wal` / `-shm` and by the step-4 cross-check. Recorded in the project memory `ref_live_db_migration_gap`. |
| **Fewer warnings than before** | Deliberate and the point of the issue. Stores whose recoverable space is discardable transcript bodies (visible only to the cutoff-dependent `inspectReclaimableBytes` scan) lose the nudge. `doctor` and `store compact --dry-run` remain the surfaces for that estimate; called out in the changelog and both docs. |
| **Floor asymmetry (1 GiB trailer vs 256 MiB doctor)** | Owner-decided; not a defect. Documented in both language docs so an operator seeing a doctor WARN and no trailer knows why. **Do not "fix" this by unifying the floors.** |
| **`PersistentPostRun` is overwritten, not chained** (`compact_reclaim_warning.go:18`) | Pre-existing; verified to be the only `PersistentPostRun` assignment in `presentation/`. Unchanged by this PR, but a second post-run hook would silently displace this one. |
| **Message wording change breaks a consumer** | Verified: the string appears nowhere but the source and its own internal test — no golden file, contract snapshot, or doc pins it. The `store can reclaim` / `ストアに回収できる領域` prefix is kept anyway. |
| **`emitCompactReclaimWarning` now depends on `RootCLI`** | Tests that build a `RootCLI` without `WithPageMetadataInspector` get silence rather than a panic (`inspectLargeStorePageMetadata` is nil-safe, `doctor_store_size.go:459`). Pinned by `TestEmitCompactReclaimWarning_NoInspectorStaysSilent`. |
| **The extraction is not actually behaviour-preserving** | Guarded by leaving all four doctor tests untouched; if one needs an edit, the extraction is wrong. |
