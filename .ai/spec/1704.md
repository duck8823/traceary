# Issue 1704: fold session active into session latest --active

## Structure-Behavior Design Note

Risk: **Low** — public command-path fold onto an existing runner. No store schema.

### Requirement summary

- Purpose: one resolver command. `session latest --active` is the former `session active` (including stale handling).
- `session active` is removed (unknown subcommand, non-zero, no `DEPRECATED` line). Replacement is documented.
- `--stale-after` / `--allow-stale` without `--active` fail clearly.
- In-repo callers (skills, docs, golden tests, repo-tooling concept check) move in the same PR.

### Conceptual model

| Concept | State | Behavior | Constraint |
|---|---|---|---|
| latest | any matching session | existing Latest() | unchanged without `--active` |
| latest --active | non-ended only | existing Active() + freshness | same defaults as old `active` |
| stale flags | only with --active | reject if `--active` absent | use cobra Changed, not default values |

### Boundaries

- Presentation only. `session.Latest` / `session.Active` stay.
- Hidden hook commands are unchanged.

### Behavior tests

| Given | When | Then |
|---|---|---|
| root | `session active` | unknown subcommand, non-zero |
| stub active | `session latest --active` | same ID as old active |
| 48h start | `session latest --active` | stale error |
| 48h start | `session latest --active --allow-stale` | prints ID |
| latest | `--allow-stale` without `--active` | non-zero, names `--active` |
