# #2462 Bounded output, detach and reconnect

## Requirement / accepted architecture
Implement R0 output ownership independently of UI/client life: same run/generation snapshot+byte cursor reconnect without restarting native CLI. No input/stop/approval/Memory/Session lifecycle, wrapper/auth/global config/model changes, raw terminal persistence or UI adoption. Native host certification and explicit same-conversation recovery2478 stay required later. Worktree /private/tmp/traceary-2462 is main's single writer, base549cca2d. Last leaf2461 merged/reviewed/wave passed; no new human architecture decision requested.

## Concepts and responsibilities (High)
Domain ByteLog owns a fixed<=2MiB byte ring, monotonic uint64 offsets, exact retained/base/head and eviction gaps; max native append/read32KiB. No rune/TUI/escape interpretation. App Output owns immutable epoch/run/generation/worktree/profile selection, synchronization, snapshot/subscriptions, pending budgets, capture end/gap and verified resize-evidence metadata. Runtime validates selection against its current owned child, not a persisted PID or environment hint. Infrastructure PTY pump is the only producer, socket adapters encode raw bytes as base64 and CLI emits JSON, never executes terminal clipboard/link/escape content. Compare application/runtime.Runtime and Registry object services; no per-RPC usecase classes. Separate narrow output-capable child reader port preserves PID/Wait consumers and unsupported fakes/platforms without a generic command framework.

## Bounds / concurrency / memory
2MiB ring per owned run, max4 subscribers per run. No duplicated subscriber data queue: each subscription reads its cursor from shared ring and holds constant metadata. Initial retained history is replayed lazily<=32KiB per Next; concurrent live backlog is bounded separately from shared scrollback. Charge conservative pending wire bytes as base64(pending live bytes)+2048*ceil(bytes/32KiB)+2048 gap allowance, ceiling256KiB; constructor options may tighten only. Producer never blocks on subscribers. On overload detach that subscriber and report slow-consumer gap/unconfirmed delivery; other runs continue. Reader uses changed-channel notification, not polling; one concurrent Next per subscription, busy otherwise. Max32 existing management connections also bounds active network subscribers. R0 per-run2MiB and epoch1024receipt bound derive at most2GiB retained terminal payload worst case (allocation lazy), not a native performance/RAM certification; no silent metadata eviction. Exited-run retention/explicit maintenance remains2465.

## Cursor / snapshot / delivery semantics
Cursor is uint64 byte offset within explicit immutable selection, never permission. Unknown future cursor>head, old epoch/generation, target/profile mismatch or unowned run rejects. Requested offset<base produces exact evicted range before retained data, never prefix truncation presented as success. Frames snapshot/data/gap/end carry selection, base/head/start/end and optional gap {from,to,reason,delivery_unknown}. Offsets count bytes (Unicode may split), not codepoints. Reconnect from client last verified end; server handing bytes to socket is not proof client received/understood them. Slow-consumer disconnect reports unconfirmed range; no exactly-once delivery claim. Capture-ended is not process/native interaction exit; output can close while process remains owned/live.

## PTY finish / resize responsibility
Native pump keeps draining to ring while no clients. After actual owned Wait, drain remaining readable bytes before closing master; wait<=250ms/<=2MiB additional bytes if descendants hold slave/writing forever, then explicit tail-unknown gap. Never block process reconciliation indefinitely or signal descendants. IO/counter loss marks capture gap, continues discarding as needed, never invents native state. EOF/EIO without owned-root exit cannot prove future descendant silence: state capture closure/uncertainty separately. FD is read by one loop, Close only after loop ends, no reuse race.
Resize operation and receipt authorization belong to2463 (its Goal explicitly owns input/resize/stop;2462 depends only2461). This leaf fixes evidence semantics: sequence0 is verified initial24x80, monotonically applied owner resize sequence only after successful ioctl; duplicate/conflicting/out-of-order/old selection rejects or remains unknown, never infer resize ack from terminal bytes/capture reuse. Snapshot resize evidence is latest verified geometry, NOT a claim historical bytes were rendered at it. Native fixture can resize its own terminal during output storms; user-facing resize/ack control is not fabricated before2463.

## Typed transport / operator surface
Management-only named attach, fixed selection+cursor; observation role cannot subscribe or negotiate control. Reuse native root/socket/lease/peer/strict version1 frame guards, max64KiB, no shell/file/reflection. Initial handshake/attach bounded8s; streaming frames have bounded write deadlines, slow consumer closes with gap where possible. Client Close/crash is detach only; no caller cancellation propagates to child. SDK Attach returns Next(ctx)/Close stream, no auto Launch/reconnect/input. CLI runtime attach requires explicit epoch/run/generation/worktree/profile and cursor, prints JSON/base64 only. Snapshot is immediate then byte chunks/gaps/end; do not decode escapes to user's terminal. Non-Unix fails closed, existing CLI cross-build retained.

## Rollback / uncertainty
Disable new subscriptions and detach readers without signaling child or closing its PTY; preserve runs and metadata. Ring evictions always advance base/gap; any buffer removal policy is explicit and cannot erase uncertain input receipts or history. Daemon crash still loses memory-only output/PTY; old epochs do not restore it or imply safe native resume. No release/UI production operation. Design checkpoint before production code; findings reproduced/classified by main, no new human wait for accepted R0 implementation details.

Wire refinement before code: encode all potentially unbounded byte cursors/counters and resize sequence as canonical decimal strings (<=20 digits), not JSON numbers that JS could round above2^53. Selection is a nested5-field object; output/gap/resize are nested fixed schemas, each<=16keys. Streaming attach is one-way after admission: a bounded per-connection EOF/extra-byte monitor cancels only that subscription, ensuring idle disconnect releases its slot; no incoming stream bytes become another method. Read deadline cleared only after bounded handshake, per-frame writes remain deadline-bound. Client Close/context cancellation releases stream/client admission slot, never signals native child. Ended capture does not mean process exited.
