# Issue 2449: explicit lesson contrast evaluation

## Requirement and model
A versioned Candidate owns scope/prerequisites, paired attempt refs, observed outcome checks, counterexample and failure modes. It stays candidate. A held-out Task has a different family and later time than every source attempt. An Evaluation freezes candidate and corpus hashes and compares no-lesson, current summary, and candidate arms under one host/model/budget.

## Responsibilities / interfaces
Standalone Python stdlib experiment only: validate paired attempt outcomes and split; generate bounded synthetic prompts; score exact-hash response receipts and paired outcomes/costs. No production CLI/schema/skills, autonomous optimizer, permission learning, activation or Memory mutation. Existing CLI fields can carry a manually reviewed final fact and refs; host-side review template captures richer reasoning outside the schema. Source trajectory geometry is disjoint from network/queue/storage/pure/foreign-workspace evaluation tasks.

## Behavior / TDD
Pin failures as well as success, reject success-only evidence, overlapping family/time, frozen-hash mismatch, duplicate receipts, mixed models, unsupported citations, out-of-scope lesson application and wrong async acknowledgement decisions. Hold candidate fixed before model runs. Score no-lesson/current/lesson identically; count repeated mistakes and inappropriate lesson use, tokens/latency; unknown review/generation/cost is not zero. Negative or inconclusive findings are retained and may result in defer.

## Risks / rollback
Medium offline experiment; existing safety boundaries unchanged. No content from real traces or approvals/credentials. Rollback removes experiment/template/report only. No automatic adoption or smallest product follow-up unless held-out benefits justify maintenance; tied results mean defer, not failure concealment. Generic helper overlap with memory evaluation is kept small; no general evaluation framework or new production usecase.
