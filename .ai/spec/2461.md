# #2461 Generation-bound PTY launch

## Requirement and scope
Implement the launch owner for the accepted R0, using shared Registry canonical targets and fixed operator-owned host profiles. Direct real binary, controlling PTY/new session, no shell wrapper or PATH/config edits. Host owns inherited authentication and approvals. No core Session lifecycle. Same native session recovery remains mandatory #2478, not automatic replay or PID adoption. Native host certification belongs to #2474–2477; test executables certify process mechanics only.

## Conceptual model / invariants
- HostProfile: immutable profile ID, host, canonical executable identity, exact expected version result and fixed version/launch argv policy. Constructed only by explicit trusted operator registration/composition, never supplied by launch caller. Values cannot contain prompts/secrets; no arbitrary env override surface. Native profile certification is separate from process mechanics.
- LaunchRequest: epoch, canonical worktree ID, profile ID and bounded idempotency ID; no executable/argv/cwd/env. The launch owner resolves and revalidates target immediately before spawn, snapshots the profile and pins executable/cwd identity. Public IDs alone do not grant remote control; same-owner local management boundary is inherited from #2460.
- LaunchDescriptor: immutable target/profile/epoch/run/generation plus process identity. Fresh cryptographic run/generation per reservation; never rebind an existing descriptor. Persist safe metadata before claiming managed success. Never save env values/raw terminal text/native credentials.
- Runtime: object-level application service (compared with application/runtime.Registry and MemoryUsecase); owns bounded launch reservations/results and runs. Same request+same target/profile returns same outcome, concurrent duplicates share one outcome; reused request with different selection rejects. Capacity 256 active runs; 1024 launch requests per epoch; no implicit ledger eviction/replay after exhaustion. Exited runs stay bounded metadata; history retention #2465 must not delete uncertain receipts.
- OwnedChild: infrastructure keeps actual exec.Cmd/Wait ownership and PTY master; no control via stored PID. Wait is performed exactly once and reconciles the reserved generation. PID is diagnostic only. Failed/canceled spawn cannot silently lose a started child: reconcile owned child before returning known failure, otherwise report launch-unknown and preserve ownership. Cancellation AFTER committed launch does not kill/detach run; request lifetime is not process lifetime.

## Responsibility / interfaces
Domain/runtime owns Profile value invariants, LaunchDescriptor, run/generation/epoch IDs and bounded state transitions. Application/runtime.Runtime owns reserve/resolve/profile lookup/revalidate/spawn/descriptor publication and snapshots through narrow ports: TargetRegistry, ProfileCatalog, ProcessLauncher, LaunchJournal. Infrastructure owns canonical executable/version checks, native PTY/session/child Wait, private descriptor persistence. Socket/CLI DTO conversion stays at presentation/infrastructure protocol, not application. No per-RPC usecase class and no generic command-runner API.

Output must always be drained even without clients; #2462 supplies the cursor ring/subscriber contract. The initial launch owner may drain to a fixed bounded sink, but final goal cannot claim reconnect/output complete until #2462. Input/resize/stop come from #2463, lifecycle/shutdown from #2464, host binding/recovery later. Backend-only progress must not be mislabeled a usable completed daemon: profile registration, typed launch/list transport/CLI composition and safe active-run shutdown integration remain required before #2461 acceptance/overall qualification.

## Threat/error/compatibility contract
Fail closed for unknown profiles/epoch/target, changed/missing/nonregular/foreign-owned/group-world-writable executables, executable witness/version mismatch, symlink replacement after canonical resolution, invalid fixed argv, unsafe cwd/store and target changes. Do not run unregistered binary to discover versions. Version probe is explicit fixed args, ≤2s/4KiB output, no stdin/PTY and no raw output/error echo. Inherited host environment is passed directly without logging/serializing/reading auth stores. Remove ambient GIT_* overrides from target resolution as existing registry does. No implicit billing backend/model substitution. Reject unsupported platforms instead of fake PTY.

New dependency candidate github.com/creack/pty v1.1.24: direct PTY master/slave and controlling session, caller owns master close, os/exec owns Wait. Primary references https://github.com/creack/pty/releases/tag/v1.1.24 and https://github.com/creack/pty/blob/v1.1.24/run.go . Pin module/checksum, no shell-based PTY allocation. Native descriptor-relative validation before operation; same-UID hostile replacement cannot be fully isolated by Go pathname exec, explicitly not claimed.

Generic sentinel errors omit paths/argv/env/version output. Canceled pending launch, known failed launch, unknown launch, exited owned child and stale generation are distinct results. No automatic retry of unknown outcomes. Independent process instances/daemon epochs never adopt a previous PID.
