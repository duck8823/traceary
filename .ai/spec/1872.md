# Issue 1872: fold store size reduction into compact

## Structure-Behavior Design Note

Risk: **High** — public CLI surface, compaction journal protocol, verification
invariants, irreversible body discard, config fallback polarity.

### Requirement summary

- 目的: サイズ削減を `traceary store compact` の copy-filter に畳み、準備専用の
  約30コマンドを消す。実行した瞬間が同意であり、ファイルが N GiB 縮むことが
  唯一の成果物である。
- 現状: dedupe / gc / retention / payload / search-retire は手実行で、いずれも
  ファイルを縮めない。縮むのは `VACUUM INTO` だけ。plan/apply は active store
  では identity drift で窓が無い。
- 期待する振る舞い:
  - `store compact` が1コマンドで copy しながら filter し、atomic exchange する
  - 未 refine の破棄対象を捨てようとするときだけ止まり、`--force` は既存の
    mechanical summary に委譲する
  - 最古 N 件を fold したあと compact すると、その N が回収される
  - 警告は doctor と non-hook 実行に出し、hook には出さない
  - `search-projection` は残る
- 非対象: 自動 compact、`traceary attest`、#1870 の pillar 最終棚卸し、
  init / backup / archive / alias / capacity / file-retention / memory admin、
  live store での dogfood、親 #1693 の close、tag / Homebrew。

### Conceptual model

| Concept | State | Behavior | Constraint / Invariant |
|---|---|---|---|
| Source store | immutable until swap | 読み取り・gate 計測のみ | バイト不変。WAL/SHM なし |
| Work copy | cloned then filtered | drop retired index / drop non-canonical dups / discard covered bodies / encode / optional `--force` cover | source を開かない。old file が archive |
| Candidate | vacuumed from work | 検証後にだけ publish | 空ファイルへ `VACUUM INTO` |
| Rollback inode | old source after swap | `store compact rollback RUN_ID` | 自動削除しない |
| Body gate | covered / unrefined / neither | 下表 | 破棄は `select_discardable_event_bodies.sql` のみ |
| Mechanical cover | degraded=1, has_agent_reasoning=0 | `--force` だけ | 既存 agent 行を ineligible にしない（#1877） |
| Reclaim warning | below / at-or-above threshold | doctor 詳細 + non-hook 1行 | hook Hidden には出さない。壊れた config でも出す |

#### Body-gate decision table

`covered` = 破棄 allowlist に載る transcript body（ended + 期限切れ + refinement が覆う）。
`unrefined` = 同じ年齢条件だが covering refinement が無い session。
若い session はどちらにも入らない。

| covered | unrefined | `--force` | result |
|---|---|---|---|
| empty | empty | * | 進む（dedupe / encode / index drop / vacuum のみ） |
| empty | non-empty | no | **失敗**。skill と件数/量と `--force` の損失を書く。rewrite しない |
| empty | non-empty | yes | mechanical cover のあと破棄して進む |
| non-empty | empty | * | 進む。covered を破棄 |
| non-empty | non-empty | no | 進む。covered だけ破棄。unrefined body は残す。残りを報告 |
| non-empty | non-empty | yes | 残りも mechanical cover して破棄 |

これで「全部 fold するまで何も縮まない」を避けつつ、0 refinement の店では
最初の compact が止まる（#1872 の「止まることだけが効いた」）。1件でも
fold すればその分と index/dedupe/encode が回収される。

### Boundaries / interfaces

| Boundary or interface | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| `StoreCompactionUsecase.Compact(CompactInput)` | CLI `store compact` | plan+apply または in-flight resume を1 exclusive lease で | typed `UnrefinedMaterialError`; 既存 journal エラー |
| `StoreCompactionUsecase.Rollback` | CLI `store compact rollback RUN_ID` | 既存 state machine | phase 不正は失敗 |
| `StoreCompactionBuilder.Build(CompactionBuildRequest)` | use case ActionBuildCandidate | work clone → AfterClone → SQL filter → VACUUM INTO candidate → work 削除 | source sidecar 禁止。candidate は空からの VACUUM INTO |
| `CompactionBuildRequest.AfterClone` | builder | `--force` 時だけ use case が渡す | work だけを変える。source 不変 |
| `CompactPreflight.InspectBodyGate` | Compact | covered/unrefined の件数と byte | 読み取り失敗は compact 失敗 |
| `OrphanConsolidationInput.SkipMechanical` / `Unlimited` | compact `--force` | 既存 processCandidate | mechanical は force のときだけ。budget は付けない |
| stderr warning | non-hook 実行 | 安価な PRAGMA / 家族存在 / freelist | 失敗してもコマンド自体は落とさない |

`Plan` / `Apply` / `Resume` / `Status` は use case に残して既存 journal 試験を保つ。
CLI からは消す。

### Copy-filter sequence

VACUUM INTO は全テーブルをコピーする。filter は work 上で先にやる。

1. exclusive lease + sidecar 不在（現行 Plan）
2. 必要空き容量 = **2×source + 10%（下限 64 MiB）**（work + candidate）。ピークは
   source+work+candidate で約 3×。現行は candidate 分の 2× ピーク
3. 空 candidate を prepare（現行）
4. source を work（`source.compact-work-<id>`）へファイルコピー。sidecar 不在が
   前提なので WAL を巻き込まない。失敗時は VACUUM INTO work に落とさない
   （source を writer で開かない契約を守る）
5. `AfterClone`（`--force` のみ）: work を通常 Database として開き、
   Unlimited + mechanical の consolidation
6. work を RW で開き、journal_mode=DELETE:
   - DROP legacy search family（`event_search_documents` / `event_search_fts` /
     `event_search_backfill_state`）。冪等
   - 非 canonical な hook prompt/transcript 重複行を DELETE。
     `event_content_dedupe_archive` は DROP（old file が archive）
   - `CollectGarbage` 相当: 同じ discard SQL で covered body を
     `unavailable_retention` にし、sessions/memories/edges の現行 gc 対象も
     同じ work 上で片付ける（gc コマンドを消すため）
   - 残った available body を `encodeCanonicalPayload` で書き直す
7. work を閉じ、work の sidecar を除去
8. work を immutable attach して candidate へ `VACUUM INTO`
9. work を削除
10. VerifyCandidate → fence → exchange → publish rollback（現行）

中断: candidate が空/不完全なら現行どおり owned-incomplete として Build を
やり直す。work は Build 先頭で自分の path を消してよい。

`requireStaticSearchState` と Plan 時の `RejectRetiredSearchIndex(source)` は
**やめる**。家族が残っていることこそこのコマンドが直す対象。
交換直前の `RejectRetiredSearchIndex` は **candidate** を見て、filter 漏れを
拒否する（メッセージは `store search-retire` を案内しない）。

### VerifyCandidate（VerifyPair の置換）

現行 VerifyPair は source と candidate の logical digest 等価を要求する。
filter 後は必ず壊れる。

新しい契約:

1. 双方: `integrity_check=ok`、`foreign_key_check=0`、`VerifyStoreCompatibility`、
   残存 payload の codec scrub
2. candidate schema: legacy search family が無い
3. filter 不変条件（source を read-only で参照）:
   - candidate の event id ⊆ source の event id
   - 残った行の identity 列（id/kind/session/created_at/agent/client/workspace）は一致
   - candidate で `available` な body の plaintext は source の同 id と一致
     （再エンコード可）
   - source にあって candidate に無い event は、非 canonical 重複だけ
   - `--force` なし: unrefined な破棄年齢 body は candidate でも `available`
   - covered な破棄年齢 body は candidate で `unavailable_retention`
4. sidecar を検証で作らない（immutable open、#1633）

`ClassifyCandidate` は等価ではなく VerifyCandidate 成功を complete とする。

### CLI

```
traceary store compact [--db-path PATH] [--force] [--keep-days N]
traceary store compact rollback RUN_ID [--db-path PATH]
```

- 既定 `--keep-days` は 90（現行 gc）
- in-flight journal（同じ store、非 terminal）があれば resume。なければ
  Plan+Apply を同じ exclusive lease で行う
- 成功 stdout: 1行で before/after bytes と何を落としたか。`--json` は後続に
  任せ、この issue では既存 compact の JSON run を踏襲してよい
- `plan` / `apply` / `resume` / `status` は unknown command

### Command deletion (#1872 only)

| Delete | Keep |
|---|---|
| `store gc` | `store compact` |
| `store dedupe` / `content-events` | `store compact rollback` |
| `store retention plan/apply/restore`（raw body） | `store retention files`（backup 側） |
| `store payload-rehearsal` 5 leaves | `store search-projection` start/resume/abort/status/probe |
| `store payload-backfill` 4 leaves | `store init` / `backup` / `archive` / `workspace-alias` / `capacity` |
| `store search-retire` | |
| `store compact plan/apply/resume/status` | |

`retention.archive_then_gc` の自動 gc は compact を起動しない（自動 rewrite 禁止）。
archive 後の body discard は止めて log する。

### Warning

- キー: `compact.reclaim_warn_bytes`
- 既定: **1 GiB**（`DefaultCompactReclaimWarnBytes`）
- 欠席: 既定
- 明示 0: 警告オフ
- **ファイルが読めない / JSON 不正: 既定のまま警告する**。
  consolidation / wake は同じ状況で 0（機能オフ）にする。警告には副作用が
  無いので、壊れた設定で沈黙するのは逆の事故になる。理由を定数の隣に書く

概算（毎コマンドの全文スキャンはしない）:

- `freelist_count * page_size`
- legacy search family が在れば `dbstat` またはそのテーブルの
  `page_count` 相当。取れなければ「家族が残っている」こと自体で閾値超えとみなす

doctor: 内訳付き。FixCommand は `traceary store compact --db-path …`。
non-hook: stderr 1行で `traceary store compact` を指す。
Hidden hook entrypoint・`store compact` 自身・doctor の1行は出さない。

### Risks / rollback

- 手続き化リスク: Build に filter / force / encode / gc を全部直書きすると
  巨大化する。SQL 再利用と AfterClone コールバックで use case に force を残す。
- premature abstraction: filter strategy は作らない。work 上の固定手順 1本。
- migration / compatibility: schema migration なし。古い plan/apply journal は
  `store compact` が in-flight として resume。空 Operation の旧 journal も
  同じ source path なら拾う。
- ピークディスク 3×: 空き不足は現行と同じく plan で fail-closed。
- Verify 変更は既存 `TestSQLiteCompactionBuilderBuildAndVerifyPair` を壊す。
  等価は「filter が何もすることがない store」でのみ残す。
- rollback trigger: copy-filter が source を汚したら即中止。source 不変が
  崩れたテストが落ちたら merge しない。
- 分割: 1 issue = 1 PR。内部 commit は feat を機能単位で切る。
