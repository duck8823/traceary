# Issue 2206: Kimi SessionEnd is not recorded on 0.38.0 `-p`

Engine: grok 4.6 medium  
Date: 2026-08-21  
Parent: #2208  
PR: `Closes #2206` only (never #2208 / #2205)

Implementer: **kimi k3**. Isolated throwaway DB only. Never point a repo-built binary at the live home store.

## Structure-Behavior Design Note

Risk: **Medium** — coverage honesty / adapter payload. Diagnosis-first. Do not start with an adapter rewrite. Do not synthesize `session_ended`.

### Requirement summary
- Purpose: restore honesty for Kimi Code **0.38.0** + Traceary plugin **0.45.0**. Isolated `kimi -p` records `session_started` / `prompt` / `transcript` / `command_executed` but **not** `session_ended`. The packaged plugin still declares `SessionEnd` → `traceary hook kimi session-end`. The matrix still marks Kimi `session_ended` as **wired** (`● SessionEnd (reason=exit)`), last verified against **0.27.0**. Live operator store last `agent=kimi --kind session_ended` is **2026-08-05T02:03:34Z**.
- Current: `runHookKimiSessionEnd` no-ops when normalized `session_id` is empty. Same `-p` run *did* record SessionStart, so a missing host event is more likely than an empty id on Start — but a 0.38 payload rename would also be swallowed. `TRACEARY_HOOK_DEBUG=1` on the tool probe produced **no** session-end / suppressed-error lines. Leftover hook-state `kimi-<pid>` still held `session_<uuid>` after process exit 0.
- Expected (either, not both as a lie):
  1. Isolated `kimi -p` on a throwaway `TRACEARY_DB_PATH` records `session_ended`, **or**
  2. matrix/docs mark Kimi `session_ended` as `available` (or `unsupported` if there is no host signal) with probed **0.38.0** behavior — **not** `wired` if the host does not emit.
- Out of scope:
  - Synthesizing `session_ended` from `-p` process exit / TUI quit / dead PID (use `traceary session run -- kimi -p …` if a one-shot closer is required).
  - Changing Claude / Codex / Antigravity contracts.
  - Compact (not exercised; last live `compact_summary` 2026-08-01).
  - Live home store (`~/.config/traceary/traceary.db`) with a repo-built binary.
  - New hook-state accumulator. Fold leftover `kimi-<pid>` into existing `hook_state_gc` verification; do not open a sibling issue unless GC does not collect them.

### Conceptual model
| Concept | State | Behavior | Constraint / Invariant |
|---|---|---|---|
| Host `SessionEnd` signal | Kimi Code emits (or does not emit) a hook named `SessionEnd` | Plugin command `traceary hook kimi session-end` runs only if the host dispatches that event | Adapter must not invent the event from process exit 0, SIGTERM, or leftover state |
| Traceary `session_ended` | row in the store (`kind=session_ended`, `agent=kimi`, `source_hook=session_end`) | written only after a normalized payload with a non-empty `session_id` reaches `runHookKimiSessionEnd` → `runHookSession(..., "end")` | `wired` in the matrix is a **capture claim**: operators may expect a recent row. A declared-but-unfired plugin hook is not `wired` |
| Leftover `kimi-<pid>` hook-state file | per-PID file under hook-state dir, name `kimi-<pid>` / `kimi-<pid>-repo` | SessionStart (and later hooks) write `session_<uuid>` into that file; SessionEnd would mark ended and leave GC to age the residue | After `-p` exit 0 with no SessionEnd, the file remaining with `session_<uuid>` is **evidence the host did not fire SessionEnd**, not a closer. Existing `hook_state_gc` collects dead-PID files after `hookStatePIDAgeFloor` (24h). Not a new accumulator |
| Plugin declaration | `integrations/kimi-plugin/kimi.plugin.json` `event: SessionEnd` | doctor `kimiExpectedHooks` still expects this rule | Keep the declaration even if the matrix cell is demoted. Doctor checks install wiring, not live emission |
| Coverage cell | `wired` / `available` / `unsupported` | `wired` = capture today; `available` = host documents/exposes SessionEnd but Traceary must not claim DB rows; `unsupported` = no usable host signal | Grok `SessionEnd` is the honesty precedent (`available`, `live_not_emitted`). Do not keep Kimi `wired` on 0.27.0 evidence |

### Boundaries / interfaces
| Boundary or interface | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| Host stdin JSON → `normalizeKimiHookPayload` | `runHookKimiSessionEnd` | copies known snake_case fields; unknown keys stay at the host boundary | decode error wraps; empty `session_id` → **silent success no-op** (existing). Do not treat that no-op as “ended” |
| `traceary hook kimi session-end` | packaged plugin `SessionEnd` | durable wrapper `runHookDurably` | if the host never invokes the command, nothing reaches the adapter |
| Matrix `kimi.events.session_ended` | doctor event-coverage, generated host-coverage table, `TestLoad_KimiCoreEventsAreWired` | status is the capture claim | `wired` iff operators can expect a DB row from an isolated `-p` (or documented TUI) today |
| Host contract `hosts.kimi.events.SessionEnd` | `hook_kimi_contract_test.go` | `supported`/`best_effort` require live-observed fixture; `unavailable` + `live_not_emitted` is the Grok SessionEnd shape | keep SessionEnd in the documented event list; do not drop the key |
| Hook-state `kimi-<pid>` | later hooks, `hook_state_gc`, doctor `hook-state-residue` | stale = PID dead **and** mtime ≥ 24h | leftover immediately after exit 0 is expected; not an end signal |
| `TRACEARY_HOOK_DEBUG=1` | operator / probe | suppressed errors / session-end lines | absence of those lines on a run that recorded Start/Stop is missing-host-event evidence |

### Probe plan (throwaway store only)
Use Homebrew / installed Traceary **0.45.0** and Kimi **0.38.0**. Set `TRACEARY_DB_PATH` and `TRACEARY_HOOK_STATE_DIR` to temp paths. Do not use a repo-built `traceary` against the live home store.

```sh
TRACEARY_DB_PATH=/tmp/kimi-se.db TRACEARY_HOOK_STATE_DIR=/tmp/kimi-se-hooks TRACEARY_HOOK_DEBUG=1 \
  kimi -p "Reply with exactly TRACEARY_KIMI_SE. Do not call tools."
traceary list --db-path /tmp/kimi-se.db --json --fields id,ts,kind,session --limit 20
traceary list --db-path /tmp/kimi-se.db --kind session_ended --limit 5 --json --fields id,ts,kind,session
```

1. Confirm Start / prompt / transcript still land; list kinds only.
2. If `session_ended` is present → branch (1); keep `wired`; bump last_verified / label to 0.38.0; no adapter change unless a field rename was required to record it.
3. If absent: inspect debug log for session-end / suppressed-error lines; list leftover `kimi-<pid>` **names** (not session bodies). Optionally a short TUI quit on the same throwaway store. Do not infer TUI from `-p` alone.
4. If a SessionEnd payload reached stdin but was dropped: dump **keys only**, commit a sanitized fixture, extend the normalizer.
5. If the host never invoked SessionEnd: matrix `available` when official/plugin still document SessionEnd (Grok shape); `unsupported` only if there is no usable host signal. Then regenerate host-coverage. Update kimi-plugin docs so they do not claim print-mode `reason=exit` on 0.38.0.

Hook-state verification (same ticket, not a sibling): leftover `kimi-<pid>` must match `hookPerPIDStateName`. Confirm existing GC would collect it once the PID is dead and age ≥ 24h. Open a follow-up only if it would never become stale.

### Risks / rollback
- Procedural risk: treating leftover `kimi-<pid>` or `-p` exit as SessionEnd. That is a new closer and is **forbidden**.
- Premature abstraction: do not add a host-exit synthesizer, a Stop→session_ended map, or a “headless closer” flag. One-shot close already exists: `traceary session run`.
- Coverage lie: leaving `wired` + 0.27.0 after a 0.38.0 `-p` that recorded Start/Stop but not End.
- Migration / compatibility: plugin SessionEnd declaration stays. Un-ended Kimi sessions continue to close via `traceary session end` or stale GC — same as Codex/Antigravity when unsupported, and same as Grok when available-not-emitted.
- Hook-state: fresh `kimi-<pid>` after exit 0 is not a bug until GC would never collect it.
- Live store: probes and tests use throwaway `TRACEARY_DB_PATH` / `t.TempDir`. Never a repo-built binary against the operator home DB.
- Rollback trigger: revert the PR. Matrix and docs return to 0.27.0 wired; no schema / no synthesized rows to unwind.

2. Do not synthesize `session_ended` from process exit.
