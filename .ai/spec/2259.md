## 1. Requirement summary

### 1.1 What is filed

`scripts/verify-post-upgrade-live-capture.sh` claims to prove that every unskipped host really records into a throwaway store. It does not, for two hosts. Lines 249–252 hard-fail `claude` and `antigravity` with `no headless probe in this gate` before any host CLI runs, and `docs/release/post-upgrade-plugins.md:38,40` (+ `.ja.md`) instruct the operator to pass exactly that canned reason as a `--skip`. A green gate therefore proves nothing about Claude or Antigravity capture — the same defect class #2253 closed for Grok.

Deliverable, exactly as filed:

1. Add a **body-free headless probe** for Claude (`claude -p` / `--print`) and Antigravity (`agy --print` — the binary is `agy`, **not** `antigravity`) to `scripts/verify-post-upgrade-live-capture.sh`.
2. Reuse the permission-on-stderr handling from `scripts/verify-antigravity-headless-markers.sh:37–45`.
3. Required kinds stay `session_started` + `prompt`. `session_ended` is neither required nor synthesized.
4. Stop documenting `--skip claude='no headless probe in this gate'` / `--skip antigravity='no headless probe in this gate'` as the default. `--skip HOST=REASON` stays valid when a host is intentionally unused or not authenticated on that machine.
5. Gemini stays skip-with-reason on `IneligibleTierError`.
6. Fixture tests: unskipped Claude/Antigravity without a probe must no longer be the documented success path; plugin-version PASS with missing kinds must still fail.
7. Probes must never aim at the live home store.

### 1.2 Out of scope (do not touch)

- Runtime hook changes (`presentation/cli/hook_*.go`) — 0.47.1 already records.
- Gemini eligibility / `IneligibleTierError`.
- Synthesizing `session_ended`.
- A 0.47.2 patch release.
- New `store` subcommands.
- `application/hostcoverage/matrix.json` and `docs/hooks/host-coverage.md` — cells are already `wired`; no regeneration in this PR.

### 1.3 Acceptance criteria

- A1. With `claude` on PATH and authenticated, `./scripts/verify-post-upgrade-live-capture.sh --skip gemini='IneligibleTierError'` runs a real `claude --print` probe into a fresh `mktemp` store and prints `PASS claude: session_started=N prompt=M` with N,M ≥ 1.
- A2. Same for Antigravity via `agy --print`, printing `PASS antigravity: session_started=N prompt=M`.
- A3. Neither the script source nor `--help` contains the string `no headless probe`.
- A4. `--skip claude=<any non-empty operator reason>` and `--skip antigravity=<...>` still produce `SKIP <host>: <reason>` and are still counted as non-captures (`capture_passes` unchanged).
- A5. `--skip gemini='IneligibleTierError'` behavior is byte-identical to today.
- A6. A fixture list with zero kinds for `claude` or `antigravity` fails with `FAIL <host>: missing kinds: session_started, prompt`, even when the plugin-version identity gate passes.
- A7. No probe writes to `${HOME}/.config/traceary/traceary.db`; the existing throwaway-path guard (lines 265–269) still runs for the two new hosts.
- A8. No probe stdout/stderr content is ever echoed by the gate — only FAIL/PASS/SKIP lines and kind counts.

### 2.3 Deviations I require

- **D1 — Do not use `claude --working-directory`.** The issue copies `--print --model sonnet --permission-mode plan --working-directory <dir>` from `scripts/smoke_test_claude_activation.sh:166`. On this machine's installed Claude Code CLI, `claude --help` lists **no** `--working-directory` option (grep count: 0). It is either removed or hidden. A release gate must not depend on an undocumented flag. **Run the Claude probe inside a subshell that `cd`s to `${PROJECT_DIR}`** — that is correct on every CLI version. (The smoke test at `:166` is a separate, opt-in, `TRACEARY_ENABLE_CLAUDE_RUNTIME_SMOKE=1` path; whether it is stale is not this issue's problem — leave it alone.)
- **D2 — Do not pin `--model sonnet`.** Capture is model-independent; a pinned alias is a future breakage with no gate value. Use the account default.
- **D3 — Split stdout and stderr per probe.** The issue's own risk section notes that a model reply containing the word "permission" would false-positive the grep. Required, not optional: `probe_host` writes stdout to `probe.log` and stderr to `probe.err`, and the Antigravity permission grep reads **`probe.err` only**, matching `verify-antigravity-headless-markers.sh:41–42`.
- **D4 — `TRACEARY_WORKSPACE` for Antigravity is parity/attribution, not a load-bearing workaround.** The issue implies the gate would otherwise lose the events. Verified false: `traceary list` applies a workspace filter only when `--workspace` is passed (`presentation/cli/list.go:83,105`; `repoSet` is `cmd.Flags().Changed("workspace")` and has no auto-detect fallback), and the gate's list call (line 275) does not pass it. Set it anyway, for parity with the marker script and so throwaway events are attributable — but do **not** claim it is required for the kinds to be found.
- **D5 — Add inherited-env neutralization.** The gate is normally run from inside a live agent session. `TRACEARY_NO_AUDIT`, `TRACEARY_RUNTIME_MODE`, `TRACEARY_RUNTIME_SESSION_ID` (`presentation/cli/hook_runtime.go:21–24`) and `TRACEARY_WORKSPACE` leak into the child host CLI and can suppress or misattribute the probe's own events — a silent false FAIL. Unset them for the two new probes. **Do not** retrofit this onto `grok`/`kimi`/`codex`: those probe paths are the currently-green reference and stay byte-identical in this PR (follow-up, not #2259).
- **D6 — No fake-binary / third test mode.** The issue floats `TRACEARY_CAPTURE_FAKE_HOST_BIN`. Reject it: fixture mode short-circuits at line 241 before the live branch, and reaching the live branch would also require faking the plugin-version identity gate. That is a new harness, i.e. scope expansion. Cover the removal of the canned skip with (a) `--help` text assertion and (b) a source-string assertion, and state plainly in the note that the live `agy` permission-grep and timeout branches are proven by the operator run, not by fixtures.
- **D7 — Wire the fixture test into CI.** `scripts/test-verify-post-upgrade-live-capture.sh` is reachable via `scripts/smoke_test_integrations.sh post-upgrade-live-capture` (`:124–127,136,152–154`) but **`.github/workflows/ci.yml:64–65` only runs the `post-upgrade-plugin-refresh` target**. The new fixture cases would never execute in CI, so issue item 5 would have no force. Add the live-capture target to CI. This is a one-step, ~2-line change and is a deliberate deviation from the issue's file list; if the owner objects it can be dropped without touching anything else in this PR.

### 2.4 Deferred / best-effort (implement, but do not gate on it)

- `--require-command claude` / `--require-command antigravity` was unreachable before this change (both hosts died at line 250). After the change the flag becomes reachable, and without a second probe it would produce a guaranteed false `FAIL … missing kinds: command_executed`. Implement a second probe for both, mirroring `grok`/`kimi`, but treat the exact flags as **unverified** (§4.3). Not asserted by any fixture case.

## 3. Conceptual model

Four concepts, already latent in the script; the change makes two of them explicit.

| Concept | Meaning | Today | After |
|---|---|---|---|
| **Host** | A logical agent client the release must prove records: `claude codex gemini antigravity grok kimi` (line 10) | ✅ | unchanged |
| **Host binary** | The executable that launches a host headlessly. Currently assumed identical to the host name (line 258) | implicit, and **wrong for `antigravity` → `agy`** | explicit: `host_binary_for()` |
| **Probe** | One body-free headless turn that must cause the installed host package to write `session_started` + `prompt` into a throwaway store | exists for 3 of 6 hosts | exists for 5 of 6 hosts |
| **Skip** | An operator's explicit statement that a host is intentionally unused or unauthenticated **on this machine** | polluted by a fourth meaning — "this gate refuses to probe this host" | restored to the two legitimate meanings only |

The defect is that the third and fourth rows collapsed: the *script's own* missing capability was expressed as an *operator's* skip reason. Removing the string `no headless probe` from the script and both docs is the semantic fix; adding the two probes is the capability fix. Both are required — either alone leaves a lie in place.

Invariants preserved:

- **I1.** Plugin-version identity is a precondition, evaluated by the sibling gate first (lines 150–165).
- **I2.** `session_ended` is never required and never synthesized.
- **I3.** Nothing but `kind` (and `agent`) is read from the list JSON; no prompt, transcript, command output, or event body is read or emitted (lines 214–217, and the `evaluate_kinds` docstring).
- **I4.** Every probe writes to a fresh `mktemp` store; the home store is refused explicitly (lines 265–269).
- **I5.** A missing binary or failed probe is a FAIL, never a silent pass; at least one unskipped host must actually capture (lines 284–287).

## 4. Responsibility assignment

All production changes live in one file: `scripts/verify-post-upgrade-live-capture.sh`.

| Unit | Responsibility | Must not |
|---|---|---|
| `host_binary_for()` **(new)** | host name → executable name (`antigravity` → `agy`, else identity) | know anything about probes or flags |
| `run_with_timeout()` **(new)** | bound one probe's wall clock; degrade to no timeout when neither `timeout` nor `gtimeout` exists | swallow the child's exit status |
| `PROBE_ENV_COMMON` **(new, array)** | the `env -u …` prefix that neutralizes inherited Traceary runtime env | contain host-specific values |
| `probe_host()` **(extended)** | own the per-host command line, its stream files, and host-specific failure diagnosis (the Antigravity permission grep) | print PASS/SKIP, read event bodies, echo probe output |
| host loop (236–282) | skip/identity/binary/store-path/probe/list orchestration, and mapping a probe status to a FAIL line | know host CLI flags |
| `evaluate_kinds()` | required-kind contract | change at all in this PR |
| `usage()` | describe reality | keep advertising a skip for a host that is now probed |

### 4.1 New constants

```bash
PROBE_TIMEOUT_SECONDS=300
PROBE_STATUS_REPORTED=70          # probe_host already printed its own FAIL line
ANTIGRAVITY_PROBE_WORKSPACE='github.com/dogfood/post-upgrade-live-capture'
PROBE_ENV_COMMON=(-u TRACEARY_NO_AUDIT -u TRACEARY_RUNTIME_MODE -u TRACEARY_RUNTIME_SESSION_ID)
```

`300` (not the issue's 180): `claude --print` cold-start plus a model turn can exceed 180 s on a slow link, and a false timeout in a release gate is worse than 2 extra minutes. `agy` keeps its own `--print-timeout 120s` inside this outer bound.

### 4.2 New / changed helpers

```bash
host_binary_for() {
  case "$1" in
    antigravity) printf 'agy\n' ;;
    *) printf '%s\n' "$1" ;;
  esac
}

# timeout(1) is not present on a stock macOS; gtimeout is when coreutils is
# installed. Without either, agy still self-bounds via --print-timeout and the
# Claude probe is unbounded — documented, not fatal.
run_with_timeout() {
  local seconds="$1"; shift
  if command -v timeout >/dev/null 2>&1; then
    timeout "${seconds}" "$@"
  elif command -v gtimeout >/dev/null 2>&1; then
    gtimeout "${seconds}" "$@"
  else
    "$@"
  fi
}
```

`run_with_timeout` is a shell function, so it must be the **outer** call and `env` the inner one (`timeout N env -u … VAR=… claude …`). Never `env … run_with_timeout …`: `env` cannot execute a shell function.

### 4.3 `probe_host()` — exact command lines

Signature changes from `(host, db, log)` to `(host, db, log, err, state)`. Existing `grok`/`kimi`/`codex` cases keep `2>&1 >"${log}"` semantics — write them as `>"${log}" 2>"${err}"` (and `>>` / `2>>` for the second run) so all five hosts have uniform stream files; no other change to those three branches.

```bash
probe_host() {
  local host="$1" db="$2" log="$3" err="$4" state="$5"
  case "${host}" in
    claude)
      # Body-free capture probe. --permission-mode plan keeps the probe
      # read-only. Never pass --bare (skips hooks) or any permission bypass.
      ( cd "${PROJECT_DIR}" && run_with_timeout "${PROBE_TIMEOUT_SECONDS}" \
          env "${PROBE_ENV_COMMON[@]}" -u TRACEARY_WORKSPACE \
              TRACEARY_DB_PATH="${db}" TRACEARY_HOOK_STATE_DIR="${state}" \
          claude --print --permission-mode plan \
            'Reply with the single word ok.' ) >"${log}" 2>"${err}" </dev/null || return $?
      if command_required_for claude; then
        # Best-effort: plan mode forbids execution, so the second run relies on
        # an explicit allowlist instead. Unverified; not asserted by fixtures.
        ( cd "${PROJECT_DIR}" && run_with_timeout "${PROBE_TIMEOUT_SECONDS}" \
            env "${PROBE_ENV_COMMON[@]}" -u TRACEARY_WORKSPACE \
                TRACEARY_DB_PATH="${db}" TRACEARY_HOOK_STATE_DIR="${state}" \
            claude --print --allowedTools 'Bash(true)' \
              'Run the shell command true. Then reply with the single word done.' ) \
          >>"${log}" 2>>"${err}" </dev/null || return $?
      fi
      ;;
    antigravity)
      # agy can exit 0 with empty stdout when a hook is auto-denied with no TTY
      # to prompt, so permission wording on stderr is diagnosed regardless of
      # exit status (verify-antigravity-headless-markers.sh:37-45).
      local agy_status=0
      ( cd "${PROJECT_DIR}" && run_with_timeout "${PROBE_TIMEOUT_SECONDS}" \
          env "${PROBE_ENV_COMMON[@]}" \
              TRACEARY_DB_PATH="${db}" TRACEARY_HOOK_STATE_DIR="${state}" \
              TRACEARY_WORKSPACE="${ANTIGRAVITY_PROBE_WORKSPACE}" \
          agy --print --mode plan --sandbox --print-timeout 120s \
            'Reply with the single word ok.' ) >"${log}" 2>"${err}" </dev/null || agy_status=$?
      if grep -qi permission "${err}"; then
        echo "FAIL antigravity: scoped hook permission is absent or shadowed (permission prompt on stderr); grant the Traceary hook permission for Antigravity or use --skip antigravity=REASON only when this host is intentionally unused" >&2
        return "${PROBE_STATUS_REPORTED}"
      fi
      if command_required_for antigravity && [[ "${agy_status}" -eq 0 ]]; then
        # Best-effort; keeps --sandbox, drops plan so a command can run.
        ( cd "${PROJECT_DIR}" && run_with_timeout "${PROBE_TIMEOUT_SECONDS}" \
            env "${PROBE_ENV_COMMON[@]}" \
                TRACEARY_DB_PATH="${db}" TRACEARY_HOOK_STATE_DIR="${state}" \
                TRACEARY_WORKSPACE="${ANTIGRAVITY_PROBE_WORKSPACE}" \
            agy --print --sandbox --print-timeout 120s \
              'Run the shell command true. Then reply with the single word done.' ) \
          >>"${log}" 2>>"${err}" </dev/null || agy_status=$?
      fi
      return "${agy_status}"
      ;;
    grok) … unchanged apart from the split stream files … ;;
    kimi) … same … ;;
    codex) … same … ;;
  esac
}
```

**Unverified, confirm before merge** (run `claude --help` / `agy --help` on the implementation machine and record the result in the PR body): `--allowedTools 'Bash(true)'` acceptance, and whether `agy --print` without `--mode plan` prompts rather than auto-denying. If either is wrong, keep the *first* probe (which is what the issue actually requires) and make `--require-command claude` / `--require-command antigravity` a `exit 64` usage error with a message naming the limitation. Do not leave a path that produces a false `missing kinds: command_executed`.

**Never** add `--bare`, `--dangerously-skip-permissions`, `--allow-dangerously-skip-permissions`, `--settings`, or `--plugin-dir` to the Claude probe: the gate exists to prove the *installed, user-scope* package records, so overriding hook/plugin discovery defeats it.

`HOME` is **not** isolated. The probe needs the operator's real auth and real installed plugins. Only `TRACEARY_DB_PATH` and `TRACEARY_HOOK_STATE_DIR` are redirected.

## 5. Boundaries / interfaces

### 5.1 External process boundary

| Host | Binary | Probe command (stdin `</dev/null`, cwd `${PROJECT_DIR}`) | Bound |
|---|---|---|---|
| claude | `claude` | `claude --print --permission-mode plan 'Reply with the single word ok.'` | outer `run_with_timeout 300` |
| antigravity | `agy` | `agy --print --mode plan --sandbox --print-timeout 120s 'Reply with the single word ok.'` | host `--print-timeout 120s` + outer 300 |
| gemini | — | no probe; `--skip gemini=REASON` required | — |
| grok / kimi / codex | unchanged | unchanged | unchanged |

### 5.2 Environment boundary (per probe)

| Variable | claude | antigravity | Why |
|---|---|---|---|
| `TRACEARY_DB_PATH` | `${capture_dir}/traceary.db` | same | I4 — throwaway store only |
| `TRACEARY_HOOK_STATE_DIR` | `${capture_dir}/state` | same | keeps wake-injection/session markers out of the operator's real state dir, where they could collide with a live session of the same client (`hook_runtime.go:21`) |
| `TRACEARY_WORKSPACE` | unset (`env -u`) | `github.com/dogfood/post-upgrade-live-capture` | D4 — attribution parity with the marker script; not load-bearing |
| `TRACEARY_NO_AUDIT`, `TRACEARY_RUNTIME_MODE`, `TRACEARY_RUNTIME_SESSION_ID` | unset | unset | D5 — the gate is run from inside a live agent session |
| `HOME`, `PATH` | inherited | inherited | the gate must exercise the operator's real auth and installed packages |

### 5.3 Exit contract (unchanged shape, extended messages)

- stdout: `PASS <host>: session_started=N prompt=M[ command_executed=K]`, `SKIP <host>: <reason>`, final `PASS: post-upgrade live capture contract is complete`.
- stderr: `FAIL …` lines only. **Probe stdout/stderr files are never echoed** (they can contain the model reply).
- exit `0` all good; `1` first FAIL; `64` usage error.
- New FAIL strings (exact):
  - `FAIL claude: claude binary not found; install it or use --skip claude=REASON only when this host is intentionally unused`
  - `FAIL antigravity: agy binary not found; install it or use --skip antigravity=REASON only when this host is intentionally unused`
  - `FAIL antigravity: scoped hook permission is absent or shadowed (permission prompt on stderr); grant the Traceary hook permission for Antigravity or use --skip antigravity=REASON only when this host is intentionally unused`
  - `FAIL <host>: headless probe timed out after 300s; investigate the host CLI or use --skip <host>=REASON only when this host is intentionally unused`
- Removed FAIL string: `FAIL <host>: no headless probe in this gate; use --skip <host>='no headless probe in this gate'`.

### 5.4 Fixture-mode boundary (unchanged)

`TRACEARY_CAPTURE_TEST_MODE=1` short-circuits at line 241 before any live branch. Fixture cases therefore exercise argument/skip semantics and the required-kind contract; they cannot reach `probe_host`. This limitation is stated in the note and in the PR body — it is not hidden behind a new harness (D6).
