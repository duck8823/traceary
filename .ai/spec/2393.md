# Issue #2393 lifecycle compatibility design checkpoint

Risk: Medium. Hidden CLI adapters and hook manifests; no public domain schema, DB migration, or provider permission changes.

Requirement: audit all seven supported hosts against official lifecycle contracts as of 2026-09-27, adopt proven gaps, and explicitly defer source-only/unobserved signals. Keep existing observed evidence distinct from documentation-derived adapter tests.

Concept model: session start/end governs session aggregate; Stop is a turn completion; Interrupt/StopFailure is a passive turn observation, not session end; compaction and child boundaries have separate identity. Host events enter presentation adapters, durable delivery/spool remains the infrastructure reliability boundary, existing event logging/usecases own persistence.

Responsibilities/interfaces:
- Shared passive lifecycle adapter logs a fixed minimal note with source_hook=interrupt or stop_failure. No raw error details, assistant error strings, model/provider credentials, transcript scan, AI extraction, consolidation continuation, GC, or permission decisions.
- Codex SessionEnd observes physical runtime shutdown via a bounded fixed note (source_hook=session_end), leaving resumable logical session/state open. No maintenance, extraction or backlog drain. Native event IDs only; session_id is not close-delivery identity. Preserve wrapper-owned one-shot termination; missing identity does not attach to another session. Logical terminal redesign is deferred to #2394.
- Manifest generators are authoritative; regenerate/check packages rather than hand-maintaining generated JSON. New Codex/Claude passive subscriptions use a strict 3s host timeout. Compatibility exception: Kimi Interrupt retains the existing 10s host timeout with a 2.5s internal context. Non-context-aware I/O may consume the host budget; no universal 3s wall-clock bound or wall-clock certification is claimed.
- Antigravity Stop fullyIdle=false must not issue consolidation continuation or schedule extraction as if the turn were fully idle. Preserve prompt/transcript best-effort capture if useful; fullyIdle=true and absent retain existing backward-compatible behavior. Do not invent executionNum idempotency across false->true phases: same execution can become idle later, and dedup must not discard the final idle transition. Only add identity if proven safe; otherwise document deferred.
- Do not create synthetic session ends for Grok/Kimi/Muse from process/turn exits.

Host decisions:
Codex: adopt SessionEnd + Interrupt, keep Stop a turn boundary. Official current hook reference https://developers.openai.com/codex/hooks; latest CLI 0.157.1 dated 2026-09-26, no claim every new hook was introduced in that release. SessionEnd synchronous advisory, timeout default1/max3s; Interrupt passive, main thread only.
Claude: adopt StopFailure as passive observation, not assistant transcript or session closure. https://code.claude.com/docs/en/hooks and https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md (StopFailure introduced2.1.78; newest listed2.1.283). PostModelSwitch introduced2.1.251 but is model telemetry, not mandatory session boundary: do not instrument model switch or permission/task lifecycle without product need. Existing PreToolUse child handling stays intact; native child start migration is independent work.
Kimi: adopt Interrupt passive observation (official replaces Stop), through host normalizer. Retain the existing 10s host timeout with 2.5s internal context as a compatibility exception; strict 3s host timeout applies only to new Codex/Claude passive subscriptions, and non-context-aware I/O prevents a wall-clock certification. Leave StopFailure unobserved/unwired unless independently justified within scope. No heartbeat/task/queued-prompt adoption: these would duplicate existing session/prompt/child boundaries and increase writes. https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html ; latest2.1.0 dated2026-09-23. Do not change historical observed flags.
Antigravity: adopt idle guard. Latest CLI1.2.11 dated2026-09-25. https://antigravity.google/docs/hooks and https://github.com/google-antigravity/antigravity-cli/blob/main/CHANGELOG.md . JSON events only Pre/PostInvocation, Pre/PostToolUse, Stop; SDK compaction must not be copied into JSON.
Gemini: no event expansion. Latest stable0.61.0 dated2026-09-23 https://geminicli.com/docs/changelogs/ and https://geminicli.com/docs/hooks/reference/ . SessionEnd best effort no wait; PreCompress async advisory marker, no post-compress. Add lifecycle contract regressions if absent.
Grok: consider regression for prompt before start/repeated start retaining identity, but do not assert async SessionStart release guarantee without evidence. Official main source1.0.41 (release date unknown): https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/10-hooks.md and https://raw.githubusercontent.com/xai-org/grok-build/main/crates/codegen/xai-hooks-plugins-types/src/lib.rs . StopCancelled/Failure main-source DTO documented but release/live dispatch unproven, do not wire guessed signals. Keep contract gaps explicit.
Muse: publishedmanual1.2.1 vs nextSDK1.3.0 inconsistency; no new event wiring from SDK-only facts. Keep old1.0.3 live evidence and unsupported/unobserved contracts explicit. https://dev.meta.ai/docs/muse-code/changelog and https://meta-models.github.io/muse-code-sdk/next/guides/extend/hooks/ . Next SDK inline last_assistant_message/turn_id is not evidence existing CLI transcript capture works.

Behavior/TDD plan: write regressions first for passive interruptions/failures keeping session open and no control stdout; runtime-close note with native delivery retry identity, repeated closes without fabricated dedup, bounded/no maintenance and unchanged logical session/state; manifest/generator parity; Antigravity false/true/missing fullyIdle and transition to final idle; Gemini marker-only/AfterAgent-no-end and Grok async ordering. Then minimal adapters, regenerate manifests and bilingual docs, run focused affected tests, integration/doc validators, full build/lint and fresh CI.

Rollback: revert the single issue PR to restore event subscriptions; no irreversible data/schema changes. Historical new fixed note events are harmless records. Unknown/source-only contracts remain deferred with reasons, not marked live-tested. No auth, installed host config, release publishing, or production mutation.

## Approved design amendment (2026-09-27)

Independent design review and orchestrator triage identified native Codex SessionEnd as physical runtime shutdown of a resumable thread, not a permanent logical aggregate end. Adopt SessionEnd as a bounded fixed note with source_hook=session_end; keep aggregate/state open and unchanged, including one-shot ownership. EndBoundary proposal and terminal cleanup changes are withdrawn. Existing explicit CLI end/GC remain terminal owners. Follow-up https://github.com/duck8823/traceary/issues/2394 owns logical close/resume redesign. Allowlist errors away before spooling; preserve only established native delivery IDs. No body hash identity. Antigravity false→false→true phases must reach final-idle continuation without executionNum dedup.

## Delivery prerequisites and host compatibility

Prerequisite #2395 / merged PR #2396 isolates budget wall-clock tests from parallel load and starts attestation deadlines after fixture setup; production SQLite retries and timing thresholds remain unchanged. New subscriptions require current official host contract support, checked before hook refresh; historical Codex 0.145.0 fixtures are not a minimum-version guarantee or live certification. New passive commands belong to HEAD/next release, not installed Traceary 0.52.0; no installed host/binary mutation is authorized.
