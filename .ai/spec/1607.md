## Structure-Behavior Design Note

### Requirement summary
- Purpose: attribute SQLite capacity without exposing stored content, and produce reproducible pre-migration query evidence.
- Current state: store maintenance has no capacity report or safe, repeatable benchmark workflow.
- Expected behavior: `store capacity` emits aggregate JSON; a benchmark tool only operates on a synthetic store or an explicit copy, reports warm/cold p50/p95 and query plans, and never clears host caches or modifies the source store.
- Non-goals: schema/codec migration, compression, compaction, query rewrites, or live-store mutation.

### Conceptual model
| Concept | State | Behavior | Constraint / invariant |
|---|---|---|---|
| Capacity snapshot | page counts, WAL bytes, aggregate objects and payload classes | describes storage attribution | contains no raw values or identifiers |
| Attribution evidence | complete / partial / unavailable with reason | makes `dbstat` capability explicit | fallback never claims object-level accuracy |
| Benchmark case | stable name, SQL, timing samples, plan details | measures copied/synthetic data | SQL is fixed by the harness; output has no bound values |
| Benchmark fixture | synthetic shape metadata | creates small, large, WAL, and free-page pressure | uses generated non-private payloads only |

### Responsibility assignment
| Responsibility | Owner | Reason to change | Not owner / reason |
|---|---|---|---|
| SQLite metadata collection | `infrastructure/sqlite` capacity inspector | SQLite pragmas, `dbstat`, filesystem sidecars | CLI: must not know schema/query details |
| Stable diagnostic DTO/port | `application` | consumer-facing capability boundary | domain: operational evidence is not a domain rule |
| JSON/text protocol and path resolution | `presentation/cli` | command contract | datasource: must not format user output |
| Safe fixture/benchmark orchestration | `cmd/store-benchmark` | standalone operator tooling | production read use cases: benchmark lifecycle is not runtime behavior |

### Boundaries / interfaces
| Boundary or interface | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| `CapacityInspector.InspectCapacity` | CLI | PRAGMA/dbstat queries and file stats | store-open errors fail; unavailable dbstat returns explicit evidence |
| `traceary store capacity --json` | operator/automation | database connection | JSON schema is stable and metadata-only |
| `store-benchmark --synthetic/--copy-from` | release engineer | fixture SQL and sampling | rejects unsafe input combinations and never opens source read-write |

### Behavior tests
| Behavior | Given | When | Then | Level |
|---|---|---|---|---|
| Metadata privacy | rows containing sentinel secrets and identifiers | inspect and encode | sentinel values are absent | integration |
| dbstat fallback | dbstat query unavailable | inspect | status is partial/unavailable and page totals remain present | adapter |
| synthetic shape | empty destination | generate | many small rows, large rows, WAL bytes, and free pages exist | integration |
| benchmark evidence | fixture/copy | benchmark | four named cases include cold/warm p50/p95 and plans | integration |
| live-store safety | source path supplied | run copy mode | source remains unchanged and benchmark targets a temporary copy | integration |

### TDD plan
| Behavior | Red | Green | Refactor target |
|---|---|---|---|
| capacity DTO/privacy | assert aggregate schema and sentinel exclusion | implement inspector and JSON CLI | centralize status/object scanning |
| safe fixture | assert page/WAL/free-list shape | implement deterministic generator | isolate fixture lifecycle |
| benchmark metrics | assert named measurements and percentile ordering | implement bounded runner | isolate sampling/plan capture |

### Risks / rollback
- Procedural risk: a benchmark script could accidentally mutate a live store; require either synthetic destination or explicit copy and benchmark only the copied path.
- Premature abstraction: use one SQLite inspector and one fixed benchmark suite; do not add plugin/query strategy interfaces.
- Migration / compatibility: no schema change; diagnostics tolerate missing tables and missing `dbstat`.
- Rollback trigger: any raw-content projection, source-store write, or runtime regression; remove the new command/tool without data migration.
