## Structure-Behavior Design Note

### Requirement summary

- **目的**: `session_workspace_observations` を event 数に線形成長させない。live store で 846,713 行
  (events 614,864 行より多い) / 0.37 GiB / +11.8k rows・day を、`(session, workspace, relationship,
  source, hook, kind)` あたり 1 行へ畳む。
- **現状** (HEAD で確認):
  - writer は INSERT のみ。primary 1 行/永続 event (`infrastructure/sqlite/event_delivery_store.go:153`)、
    supplemental 1 行/exact redelivery (`:114`)、backfill 1 行/未 cover event
    (`infrastructure/sqlite/workspace_observation_backfill.go:167`)。
  - DELETE 経路なし。FK / cascade なし (`schema/sqlite/migrations/000022_add_hook_delivery_identity.sql:28-45`
    — `session_workspace_aliases` だけが `REFERENCES sessions(...) ON DELETE CASCADE` を持つ)。
  - `collectGarbageInTx` (`infrastructure/sqlite/store_management_datasource.go:493`) に observation の
    step がない。compact / dedupe / session GC が orphan を残す (migration 72 の冒頭コメントが自認)。
  - catch-up は per-event anti-join (`workspace_observation_backfill.go:32-42`) なので、
    「1 event = 1 primary 行」という形そのものを要求している。
- **期待する振る舞い**:
  1. 同一 aggregate key の 2 件目以降の観測は行を増やさず `observation_count` を増やす。
  2. exact redelivery (`delivery_record_id` + `attribution_fingerprint` が同一) は count を増やさない。
     attribution が変われば増やす。
  3. catch-up は anti-join をやめ、high-water (frontier) mark で進む。busy retry は維持。
  4. reader (count / distinct pair / GROUP BY source / most-recent listing) が畳んだ形から再現できる。
  5. session が消えた observation は `collectGarbageInTx` が削除する。
  6. 既存行の collapse は data-dependent offline migration として `doctor --fix` が **copy** に適用する。
- **非対象** (issue の Out of scope をそのまま維持):
  - `hook_deliveries` / `hook_delivery_attempts` の bounding。
  - `session_workspace_aliases` / alias review UX の変更。
  - conflict sample から `observed_event_id` を完全に落とすこと。
  - 2 GiB metadata-only doctor gate 自体の変更。
  - **新しい store subcommand の追加は禁止** (hard constraint)。

### Conceptual model

| Concept | State | Behavior | Constraint / Invariant |
|---|---|---|---|
| Workspace observation aggregate | 6-tuple key + `observation_count` + `first/last_observed_at` + newest `observed_event_id` / `raw_workspace` / `delivery_record_id` / `attribution_fingerprint` / `diagnostic_reason` / `observation_origin` | 観測ごとに UPSERT で count を進め、newest 属性を差し替える | 1 key = 1 row。`observation_count >= 1`。`ts_norm(first_observed_at) <= ts_norm(last_observed_at)` |
| Aggregate key | `(session_id, workspace, observed_relationship, source_client, source_hook, observation_kind)` | 不変。owner 決定でこの 6 列に固定 | 列の追加・削除は AC の変更にあたるので禁止 |
| Exact redelivery | 直前と同じ `(delivery_record_id, attribution_fingerprint)` | count を進めず、newest 属性も据え置く | 「内部 retry で volume が増えない」を維持 |
| Catch-up frontier | `(frontier_created_at_norm, frontier_event_id)` = 走査済みの最古 event。`''` = 未走査 | 新しい方から古い方へ降順に 1 batch/Initialize で後退 | 単調減少。`exhausted=1` になったら以後 skip (HEAD と同じ) |
| Backfill 観測 | origin=`backfill` | 既存 key には count を足さず first/last だけ広げる | frontier 再走査が **冪等** であること |
| Orphan observation | session 行も event 行も残っていない `session_id` | GC が物理削除する | orphan range (session 行なし・event 行あり) は **削除しない** |
| Coverage figure | `CoveredEvents` / `MissingEvents` | frontier から導出する bookkeeping | もはや per-event の監査ではない (§7 で明示) |

## 3. Write path — UPSERT

### 3.1 現状 (HEAD)

`insertWorkspaceObservation` (`event_delivery_store.go:347`) は素の INSERT で、`observation_id` は
`evidence.ObservationID()` もしくは `"event:"+observedEventID`。unchanged redelivery は
`idx_session_workspace_observations_delivery_attribution` (partial unique,
`000022:51-53`) 違反を `isSQLiteUniqueOrPKConflict` で握り潰して no-op にしている (`:396-401`)。

### 3.2 変更後の SQL (正確な形)

`tableExistsInTransaction(ctx, tx, "session_workspace_observations")` の既存 guard はそのまま残し、
その直後に **column probe** を足す (§3.3)。集約形のときだけ以下を実行する。

```sql
INSERT INTO session_workspace_observations (
    session_id, workspace, observed_relationship, source_client, source_hook, observation_kind,
    observation_count, first_observed_at, last_observed_at,
    observed_event_id, raw_workspace, delivery_record_id,
    attribution_fingerprint, diagnostic_reason, observation_origin
) VALUES (?, ?, ?, ?, ?, ?, 1, ?, ?, ?, ?, ?, ?, ?, ?)
ON CONFLICT (session_id, workspace, observed_relationship, source_client, source_hook, observation_kind)
DO UPDATE SET
    observation_count  = session_workspace_observations.observation_count + 1,
    first_observed_at  = CASE
                           WHEN ts_norm(excluded.first_observed_at) < ts_norm(session_workspace_observations.first_observed_at)
                           THEN excluded.first_observed_at
                           ELSE session_workspace_observations.first_observed_at
                         END,
    last_observed_at   = CASE
                           WHEN ts_norm(excluded.last_observed_at) >= ts_norm(session_workspace_observations.last_observed_at)
                           THEN excluded.last_observed_at
                           ELSE session_workspace_observations.last_observed_at
                         END,
    observed_event_id  = CASE
                           WHEN ts_norm(excluded.last_observed_at) >= ts_norm(session_workspace_observations.last_observed_at)
                           THEN excluded.observed_event_id
                           ELSE session_workspace_observations.observed_event_id
                         END,
    raw_workspace      = CASE
                           WHEN ts_norm(excluded.last_observed_at) >= ts_norm(session_workspace_observations.last_observed_at)
                           THEN excluded.raw_workspace
                           ELSE session_workspace_observations.raw_workspace
                         END,
    delivery_record_id      = excluded.delivery_record_id,
    attribution_fingerprint = excluded.attribution_fingerprint,
    diagnostic_reason       = excluded.diagnostic_reason,
    observation_origin      = CASE
                                WHEN excluded.observation_origin = 'runtime' THEN 'runtime'
                                ELSE session_workspace_observations.observation_origin
                              END
WHERE excluded.observation_origin = 'runtime'
  AND (
        COALESCE(excluded.delivery_record_id, '') = ''
     OR COALESCE(excluded.delivery_record_id, '') <> COALESCE(session_workspace_observations.delivery_record_id, '')
     OR excluded.attribution_fingerprint <> session_workspace_observations.attribution_fingerprint
      );
```

規則:

- **必ず `session_workspace_observations.<col>` で修飾する。** SQLite の `DO UPDATE SET x = x + 1` は
  右辺の裸の `x` を更新前の列として解決するが、修飾したほうが読み手にも review にも曖昧さがない。
  `ts_norm` は Go 側で driver に登録されたスカラ関数 (`infrastructure/sqlite/database.go:26,40`) なので、
  migration も runtime も同じ driver 経由で使える。**`sqlite3` CLI では使えない** (§11 の検証コマンドは
  `ts_norm` を使わない)。
- `WHERE ... excluded.observation_origin = 'runtime'`: **backfill は既存行の count を増やさない**。
  これは HEAD の挙動 (`workspace_observation_backfill.go:174-181` の INSERT は primary-event unique index に
  弾かれて no-op) を保存し、frontier を巻き戻した再走査を冪等にする。新規 key の場合は通常どおり 1 行
  count=1 で挿入される。
- redelivery 述語は「**直前の** delivery とその fingerprint」との比較になる。partial unique index が
  持っていた「全履歴にわたる exact 一意性」は集約形では表現できない (key ごとに newest しか残らない)。
  → §10 の意味変化 R3 に明記。
- `isSQLiteUniqueOrPKConflict` を使った握り潰し分岐 (`:396-401`) は削除する。
  `isSQLiteUniqueOrPKConflict` 自体は他所 (`:129`) で使われているので関数は残す。
- 引数シグネチャは変えない。呼び出し側 (`:114`, `:153`) は無変更。

`first_observed_at` / `last_observed_at` に渡す値はどちらも `formatTimestamp(event.CreatedAt())`。

### 3.3 legacy-shape fallback

migration 22 だけを入れた focused fixture が既存テストにいる (`event_delivery_store.go:353-360` の
コメントが根拠)。offline migration 未適用の store も同じ形になる。よって:

```go
aggregated, err := columnExistsInTransaction(ctx, tx, "session_workspace_observations", "observation_count")
```

を追加し、`false` のときは **HEAD の INSERT 文をそのまま**実行する (`isSQLiteUniqueOrPKConflict` の
握り潰しごと)。`columnExistsInTransaction` は `PRAGMA table_info` を使う小さな helper として
`event_delivery_store.go` に置く (既存の `tableExistsInTransaction` の隣)。

## 4. Migration `000076` — SQL outline

`applyMigration` (`infrastructure/sqlite/migrate.go:236-261`) は **本文全体を 1 トランザクションの
1 回の `ExecContext`** で流す。したがって table rebuild は atomic であり、途中失敗は完全に巻き戻る。
複文は許される。

```sql
-- 000076_collapse_session_workspace_observations.sql
--
-- session_workspace_observations was append-only: one row per delivered event
-- plus supplemental redeliveries plus backfill rows, and nothing deleted them.
-- Live store 2026-08-28: 846,713 rows / 0.37 GiB against 614,864 events,
-- +82,554 rows per 7 days. Collapse to one row per
-- (session_id, workspace, observed_relationship, source_client, source_hook,
--  observation_kind) with a volume counter, so the family grows with distinct
-- attribution keys instead of with events (#2269).
--
-- Measured on a copy of the operator store before this migration was written:
--   rows=<fill in>  keys=<fill in>  ratio=<fill in>
--
-- Data-dependent: this rewrites the whole family. Registered
-- MigrationDataDependentOffline in prepared_migration_catalog.go; it is applied
-- by `traceary doctor --fix`, never implicitly on live open.

CREATE TABLE session_workspace_observations_collapsed (
    session_id TEXT NOT NULL,
    workspace TEXT NOT NULL,
    observed_relationship TEXT NOT NULL
        CHECK (observed_relationship IN ('exact', 'descendant', 'ancestor', 'explicit_alias', 'conflict', 'unknown')),
    source_client TEXT NOT NULL DEFAULT '',
    source_hook TEXT NOT NULL DEFAULT '',
    observation_kind TEXT NOT NULL
        CHECK (observation_kind IN ('primary', 'supplemental')),
    observation_count INTEGER NOT NULL DEFAULT 1 CHECK (observation_count >= 1),
    first_observed_at TEXT NOT NULL,
    last_observed_at TEXT NOT NULL,
    observed_event_id TEXT,
    raw_workspace TEXT,
    delivery_record_id TEXT,
    attribution_fingerprint TEXT NOT NULL,
    diagnostic_reason TEXT NOT NULL DEFAULT '',
    observation_origin TEXT NOT NULL
        CHECK (observation_origin IN ('runtime', 'backfill')),
    PRIMARY KEY (session_id, workspace, observed_relationship, source_client, source_hook, observation_kind)
) WITHOUT ROWID;

-- One ordered pass with window ranks, not a correlated subquery per key.
-- first/last observed_at keep the original stored strings selected in
-- ts_norm order (do not MIN()/MAX() RFC3339 text). Correlated first/last
-- subqueries stalled for >20 min on an 856k-row copy.
INSERT INTO session_workspace_observations_collapsed
WITH ranked AS (
    SELECT session_id, workspace, observed_relationship, source_client, source_hook, observation_kind,
           observed_at, observed_event_id, raw_workspace, delivery_record_id,
           attribution_fingerprint, diagnostic_reason,
           COUNT(*) OVER (
             PARTITION BY session_id, workspace, observed_relationship, source_client, source_hook, observation_kind
           ) AS observation_count,
           CASE WHEN MAX(CASE WHEN observation_origin = 'runtime' THEN 1 ELSE 0 END) OVER (
             PARTITION BY session_id, workspace, observed_relationship, source_client, source_hook, observation_kind
           ) = 1 THEN 'runtime' ELSE 'backfill' END AS observation_origin,
           ROW_NUMBER() OVER (
             PARTITION BY session_id, workspace, observed_relationship, source_client, source_hook, observation_kind
             ORDER BY ts_norm(observed_at) DESC, observation_id DESC
           ) AS rn_desc,
           ROW_NUMBER() OVER (
             PARTITION BY session_id, workspace, observed_relationship, source_client, source_hook, observation_kind
             ORDER BY ts_norm(observed_at) ASC, observation_id ASC
           ) AS rn_asc
      FROM session_workspace_observations
)
SELECT last.session_id, last.workspace, last.observed_relationship, last.source_client, last.source_hook, last.observation_kind,
       last.observation_count, first.observed_at, last.observed_at,
       last.observed_event_id, last.raw_workspace, last.delivery_record_id,
       last.attribution_fingerprint, last.diagnostic_reason, last.observation_origin
  FROM ranked last
  JOIN ranked first
    ON first.rn_asc = 1
   AND last.rn_desc = 1
   AND first.session_id = last.session_id AND first.workspace = last.workspace
   AND first.observed_relationship = last.observed_relationship
   AND first.source_client = last.source_client AND first.source_hook = last.source_hook
   AND first.observation_kind = last.observation_kind;

DROP TABLE session_workspace_observations;
ALTER TABLE session_workspace_observations_collapsed RENAME TO session_workspace_observations;

CREATE INDEX idx_session_workspace_observations_relationship
    ON session_workspace_observations(observed_relationship, last_observed_at DESC, session_id);

-- Catch-up frontier. Descending sweep: everything strictly newer than the
-- frontier has already been examined; '' means no sweep has started.
ALTER TABLE workspace_observation_catchup_state
    ADD COLUMN frontier_created_at_norm TEXT NOT NULL DEFAULT '';
ALTER TABLE workspace_observation_catchup_state
    ADD COLUMN frontier_event_id TEXT NOT NULL DEFAULT '';
```

**Deliberate points** (review でここを見ること):

1. `first_observed_at` / `last_observed_at` は `MIN()/MAX()` の **文字列比較を使わない**。
   `formatTimestamp` は可変長の小数秒を出すので RFC3339Nano の辞書順比較は壊れる (#1185、
   `docs/storage/README.md:236` が同じ罠を記述している)。`ts_norm` 順で選んだ実値を入れる。
   `first_norm` / `last_norm` は診断用に計算しているだけで列には入れない。捨ててよい。
2. 旧 index (`idx_session_workspace_observations_relationship`,
   `idx_session_workspace_observations_delivery_attribution`,
   `idx_session_workspace_observations_primary_event`) は `DROP TABLE` で**まとめて消える**。
   relationship index だけ新しい形で作り直す。他の 2 つは**意図的に復活させない** — 集約形では
   `observed_event_id` も `(delivery_record_id, attribution_fingerprint)` も一意ではない。
   これを migration 本文のコメントに書くこと。
3. `observation_id` 列は消える。conflict sample の tie-break は `(session_id, workspace)` に移る (§7)。
4. `exhausted` は **触らない**。旧 anti-join が既に埋め終えていた store は `exhausted=1` のままで、
   frontier `''` は参照されない。`exhausted=0` の store は frontier `''` から新しい方に向かって
   走査をやり直すが、backfill UPSERT が非加算なので count は歪まない (§3.2)。
5. `WITHOUT ROWID` + 6 列 PK。`dbstat` はこの形でも per-object の bytes を返す。

## 6. Catch-up — frontier (high-water) mark

### 6.1 HEAD の実態

```
 WHERE NOT EXISTS (SELECT 1 FROM session_workspace_observations o
                    WHERE o.observed_event_id = e.id AND o.observation_kind = 'primary' ...)
 ORDER BY e.created_at_norm DESC, e.id DESC
 LIMIT ?
```
(`workspace_observation_backfill.go:32-42`) — **降順 (新しい順)** で、SELECT する列は
`id, session_id, workspace, created_at, agent, source_hook, s.workspace` の **7 列**。
`created_at_norm` は選択していない。

### 6.2 変更後

frontier は「走査済みの最古 event」。走査は今と同じ **降順**を保つ (新しい event が先に cover される
という現行の性質を壊さないため)。

```go
const workspaceObservationCatchUpBatchQuery = `
	SELECT e.id, e.session_id, e.workspace, e.created_at, e.created_at_norm, e.agent,
	       COALESCE(e.source_hook, ''), COALESCE(s.workspace, '')
	  FROM events e
	  LEFT JOIN sessions s ON s.session_id = e.session_id
	 WHERE ? = '' OR (e.created_at_norm, e.id) < (?, ?)
	 ORDER BY e.created_at_norm DESC, e.id DESC
	 LIMIT ?`
```

- 列は **8 列**になる (`created_at_norm` を足す)。scan 側の struct も 1 フィールド増やす。
- `idx_events_created_at_norm_id_desc` (`000031:97-98`, `events(created_at_norm DESC, id DESC)`) が
  そのまま効く。
- row-value 比較 `(a,b) < (?,?)` は SQLite ≥ 3.15。`go.mod:20` は `modernc.org/sqlite v1.56.0` で
  十分新しい。**推測に頼らず EXPLAIN QUERY PLAN テストで確認する** (§9)。
- 1 回の tx の中で: batch を UPSERT → 最後の (= 最古の) 行の `(created_at_norm, id)` を
  `frontier_created_at_norm` / `frontier_event_id` に UPDATE → commit。batch が空なら frontier は
  動かさない。
- `exhausted` の扱いは **HEAD と同一**: `Selected == 0` かつ `EXISTS(SELECT 1 FROM events)` の
  ときだけ `markWorkspaceObservationCatchUpExhausted`。`exhausted=1` なら `Skipped:true` で即戻る。
  reset 経路は今も無いので**追加しない** (scope 外)。
- busy retry (`workspaceObservationCatchUpMaxAttempts` = 3、`workspaceObservationCatchUpRetryDelay`)、
  「SELECT snapshot を writer に昇格させない」コメントと構造、`Inserted` は durable commit のみ数える、
  `isSQLiteBusy` / `isSQLiteFull` — **すべて維持**。
- backfill の書き込みは §3.2 の UPSERT を `observation_origin='backfill'` で呼ぶ。既存 key には
  count を足さない。`Inserted` は「新規 key として挿入された行数」を意味するようになる
  (`RowsAffected` ではなく、UPSERT 前後の判定でよい。単純には `INSERT ... ON CONFLICT` の
  `RowsAffected()` が 1 か 0 かで足りる)。
- `catchUpWorkspaceObservationsOnce` が `batchSize+1` 件取って `MorePending` を立てる既存ロジックは維持。

### 6.3 state テーブルの読み書き

`workspace_observation_catchup_state` は singleton (`000072`)。frontier 列の追加は `ALTER TABLE ADD
COLUMN ... NOT NULL DEFAULT ''` なので既存行に既定値が入る。読み出しは 1 クエリ:

```sql
SELECT exhausted, frontier_created_at_norm, frontier_event_id
  FROM workspace_observation_catchup_state WHERE singleton = 1
```

state テーブルが無い store (migration 72 未満の fixture) では今と同様に frontier なしで扱う
= `''` として全走査。`sqliteTableExists` の既存分岐を活かす。

## 8. GC — 到達不能行の削除

`infrastructure/sqlite/sql/delete_unreachable_workspace_observations.sql`:

```sql
-- An observation is unreachable once neither its session row nor any event of
-- that session survives. Compact's copy filter, content dedupe, and empty-session
-- GC all leave such rows behind; migration 000072 documents the orphan case.
-- The events clause is not optional: events have no FK to sessions (000001), so
-- a recorded orphan range is session-row-less but still live data.
DELETE FROM session_workspace_observations
 WHERE NOT EXISTS (
       SELECT 1 FROM sessions s
        WHERE s.session_id = session_workspace_observations.session_id
   )
   AND NOT EXISTS (
       SELECT 1 FROM events e
        WHERE e.session_id = session_workspace_observations.session_id
   );
```

- `go:embed sql/delete_unreachable_workspace_observations.sql` を
  `store_management_datasource.go:20-40` の embed 群に追加し、
  `deleteUnreachableWorkspaceObservationsQuery` とする。
- `collectGarbageInTx` (`:493`) の `GarbageCollectionTargetSessions || All` ブロックで、
  `deleteEmptySessionsQuery` の **直後**に実行し、件数を `total` に足す。
  順序は重要 — 空 session を先に消してから observation を判定する。
  ```go
  count, err = execRowsAffected(ctx, tx, deleteUnreachableWorkspaceObservationsQuery)
  if err != nil {
      return 0, xerrors.Errorf("failed to delete unreachable workspace observations: %w", err)
  }
  total += count
  ```
- **時間窓を掛けない**。他 family の `before` 窓は「最近の生きたデータを守る」ためにあるが、
  この述語は session 行も event 行も無い行だけを選ぶので、窓が守るものが存在しない。
  この判断は review 対象として明記する。
- `previewGarbage` 側 (`:440-475` 付近の count 分岐) にも対応する
  `count_unreachable_workspace_observations.sql` を足し、`--dry-run` の件数を合わせる。
  既存 family がすべて count クエリを持っているので同型にする。
- `store compact` からも自動的に走る: `compaction_copy_filter.go:88-101` が
  `filter.Cutoff` 非ゼロのとき `collectGarbageInTx(..., GarbageCollectionTargetAll, ...)` を呼ぶ。
  既定 `--keep-days` は 90 (`application/compact.go:166`) なので cutoff は常に設定され、
  既定 compact でも orphan は掃除される。
- index: `sessions` は PK 検索、`events` は `idx_events_session_created_at_norm_id_desc` の
  先頭列で引ける。全走査は集約後の行数 (数千〜数万オーダー想定) のみ。

| R2 | per-event provenance 喪失 | `observation_id` と個々の `observed_at` が消え、key ごと最新 event だけ残る | option (a) が受け入れた代償。`docs/operations/workspace-identity-contract.md` の「append-only provenance」記述を更新 |
| R3 | redelivery 抑止の弱化 | partial unique index が持っていた全履歴の exact 一意性が失われる。**失敗シナリオ**: 同一 key に delivery A → delivery B → delivery A(exact 再送) と来ると、HEAD では 3 件目は no-op、変更後は `observation_count` が +1 する | 行数は増えない (count だけ)。CHANGELOG と docs に明記。より厳密にしたい場合の代案 = `hook_delivery_attempts` に既存の `exact_redelivery` があるかを事前に数える。**今回は採用しない** (redelivery ごとに追加クエリが増え、bounding の目的に寄与しない) |
| R4 | coverage の意味変化 | `CoveredEvents` / `MissingEvents` が frontier 由来の bookkeeping になる | §7.1 の表を docs と CHANGELOG に転記 |
| R5 | offline migration のコスト | 846k 行の rebuild。1 トランザクション内なので peak で旧 + 新の両方を持つ | prepared recipe が run-owned copy で走り、free-space headroom を見る。§11 で copy 上の所要時間を計測して PR に記録。遅すぎる場合は window 版 (§4 の JOIN 形) のままで良いはず — 相関サブクエリ版は使わない |
| R6 | **upgrade 中の書き込み停止** | 76 を含むバイナリでは、`doctor --fix` を打つまで events を持つ store の `Initialize` が `OfflineMigrationsRequiredError` を返す (`migrate.go:61-69`) → hook 書き込みが通らない | release note / CHANGELOG に「upgrade 後 `traceary doctor --fix` が必要」と明記。035 / 045 と同じ運用 |
| R7 | 旧バイナリ + 新スキーマ | pre-76 バイナリは `observation_id` 列へ INSERT しようとして失敗する | offline class は「先にバイナリを上げる」を前提にする。release note に明記 |
| R8 | 並行性 | UPSERT は単一文。lock 順序は増えない | catch-up の busy retry を維持 |
| R9 | premature abstraction | 「observation store」抽象を新設したくなる | 作らない。既存の datasource 関数の中で完結させる |

**Rollback**

- コード: PR revert。migration 76 が適用済みの store は 76 のバイナリ以降でしか開けないので、
  revert する場合は **同時に store を pre-fix の backup から戻す**。
- prepared candidate: recipe は source を書き換えないので、候補を破棄すれば live store は無傷
  (`prepared_migration_recipe.go`)。
- purpose-gate は copy に対して行うので、live store は最後まで触らない。
- **rollback trigger**: (a) collapse 後に `rows != keys`、(b) `doctor --json` の
  `workspace_identity.sources` の volume 合計が collapse 前後で不一致、(c) copy 上の
  migration が 10 分を超える、(d) 1 日 replay 後の行増分が新規 session 数を大きく超える。
