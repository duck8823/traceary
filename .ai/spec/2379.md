# #2379 Codex prompt-only consolidation delivery

## Structure-Behavior Design Note

### Requirement summary
- 目的: opt-in Codex Stop を主成果物を妨げない durable prompt handoff にする。
- 現状: `prompt_delivered_at` を stdout 前に設定し、保存失敗時に Stop exit 2 に戻る。
- 期待する振る舞い: enabled Codex Stop は ledger、usecase、latest-event、duplicate persistence の失敗でも exit 0。prompt は pending → claimed → delivered → fulfilled を durable に遷移し、stdout 成功後だけ delivery を確認する。
- 非対象: 他 client の consolidation route、prompt payload 本文の保存・出力。

### Conceptual model
| Concept | State | Behavior | Constraint / Invariant |
|---|---|---|---|
| Prompt request | pending/claimed/delivered/fulfilled | claim, release, confirm, refine | stable request ID; one active lease winner |
| Prompt lease | claimed with expiry | stale claim is reclaimable | token comparison protects another claimant |
| Stop handoff | due / not recorded | attempt pending persistence | enabled Codex always returns success |

### Responsibility assignment
| Responsibility | Owner | Not owner |
|---|---|---|
| State transition and lease token | application/domain port | CLI and SQL callers |
| Atomic compare-and-set persistence | SQLite adapter | application |
| stdout and non-blocking diagnostics | CLI | repository |

### Boundaries / interfaces
| Boundary | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| Claim/Release/Confirm prompt port | CLI | SQL, state columns | errors are logged and prompt emits no extra artifact |
| Record request port | Stop CLI | duplicate detection | enabled Codex turns all errors into success |

### Behavior tests
| Behavior | Given | When | Then |
|---|---|---|---|
| Stop failures | enabled Codex due Stop and persistence/read failure | Stop | exit 0 and no primary artifact replacement |
| concurrent claim | one pending request | parallel prompts | one bounded notice |
| pre-output failure | claim acquired, writer fails | prompt | release then later retry |
| confirm failure/crash | stdout succeeds, confirmation absent | lease expires | later prompt may redeliver (at least once) |
| fulfilled/new work | accepted refinement then new due event | Stop/prompt | no old repeat; new work is deliverable |

### TDD plan
1. Add observable lifecycle/Stop failure tests.
2. Add lifecycle port and SQLite CAS transition queries.
3. Switch CLI to claim → stdout → confirm with release on writer failure.
4. Update migration fixtures and bilingual docs; run scoped then SQLite/full checks.

### Risks / rollback
- Migration is additive and old binaries ignore lifecycle columns.
- Crash after stdout before confirmation is deliberately at-least-once, bounded by a durable lease.
- A migration rollback is the existing database backup/upgrade path; disabling config makes pending rows inert.
