# #1610 payload migration rehearsal design

## Requirement summary

- Build a resumable, bounded identity-to-zstd **rehearsal** against an explicit copied/shadow SQLite target.
- Keep the configured live canonical store and every v0.34 canonical writer identity-only.
- Prove dry-run performs zero writes, kill/resume has no loss or duplication, scrub is byte/checksum bounded, and rollback restores the copied target.
- Record WAL, lock, batch, ratio, time, byte, disk-headroom, and rollback evidence without payloads or identifiers.
- Do not ship a live activation command, raise the live store format, delete canonical history, cut over search, compact, or replace the live store.

## Conceptual model

| Concept | State | Behavior | Invariant |
|---|---|---|---|
| Rehearsal target | unresolved, verified-copy, rejected-live, unavailable | No-follow path validation, compare `os.FileInfo` identities, fingerprint DB/sidecars | Target must be a regular single-link copied DB and must not alias the configured live DB or sidecars |
| Run | planned, running, paused, completed, failed, scrubbed, rolled-back | Freeze source high-water marks and immutable configuration hash | One target/config owns one run; terminal state never silently resumes |
| Field checkpoint | pending, advancing, complete | Keyset by table/field/PK; store frozen high-water and last committed PK | Checkpoint advances in the same transaction as successful/CAS-reconciled writes |
| Shadow payload | absent, encoded, scrubbed, corrupt | Store zstd bytes and integrity metadata keyed by run/lane/source ID | Canonical events/audits remain identity plaintext; shadow PK prevents duplication |
| Batch | selected, encoded, committed, conflicted | Select bounded canonical rows, decode/verify, encode outside write transaction, atomically insert shadow rows/checkpoint | Canonical source is frozen; a shadow row is inserted at most once |
| Scrub | pending, running, passed, failed | Decode and checksum rows under row/byte/time caps | `passed` means the declared frozen range was completely verified |
| Rollback artifact | missing, verified, restored | Physical SQLite backup/copy plus digest and integrity result | Logical archive is not a byte-exact codec rollback artifact |
| Activation preconditions | report-only booleans | Report reader, process, backup, headroom, scrub, rollback readiness | v0.34 cannot change activation state or write compressed canonical live rows |

## Boundaries and interfaces

| Boundary | Consumer | Hidden detail | Error contract |
|---|---|---|---|
| `Inspect/Plan` | CLI, tests | immutable/read-only schema inspection, frozen high-water, stat snapshots | Typed unsafe-target, unsupported-schema, cap/config errors |
| `ApplyBatch/Resume` | Use case | keyset SQL, zstd, CAS, short transaction, checkpoint | Typed conflict/retry, lock timeout, integrity, interrupted state |
| `ScrubBatch/ResumeScrub` | Use case | bounded stored/decode allocation and checksum | Row/field integrity error without payload/identifier leakage |
| `SnapshotTarget` | Use case | DB/WAL/SHM existence, size, mtime, identity | Dry-run mutation error contains component class only |
| `ActivationReadiness` | CLI | read-only report | Always refuses activation in v0.34 |

Preview and apply are distinct methods/commands. A boolean `dryRun` must not control writes inside one procedural implementation.

## Migration 37 proposal

Migration 37 adds rehearsal bookkeeping and dormant source-freeze guards only. It must not add canonical codec mutation triggers, canonical zstd writes, search cutover, or activation state.

- `payload_rehearsal_runs`: run id, target fingerprint (salted/opaque), config hash, state, lease owner/expiry, frozen event/audit high-water keys, counters, started/updated/completed timestamps, rollback artifact digest/status.
- `payload_rehearsal_checkpoints`: run id, table kind, field kind, last primary key, state, scanned/changed/conflicted rows, stored/plain/compressed byte counters, scrub counters; primary key `(run_id, table_kind, field_kind)`.
- `payload_rehearsal_rows`: run id, lane, source id, zstd BLOB, codec/version/plaintext/stored length/SHA-256 and source logical SHA; primary key `(run_id, lane, source_id)`. It has no cascading foreign key to canonical events/audits.
- Dormant freeze triggers reject canonical event/audit INSERT/DELETE or payload mutation only while a nonterminal rehearsal run exists. With no active run, normal writers are unchanged.
- CHECK constraints enumerate states/table/field and require nonnegative counters.
- Normal migration installation may create empty bookkeeping tables on a live v0.34 store, but no normal writer reads or mutates them. Dry-run never invokes `Initialize`; it reports migration-required when absent.

## State transitions

```text
plan -> running -> paused -> running -> completed -> scrubbed
             \-> failed (resumable only when configuration/target identity match)
scrubbed -> rolled-back (copied target only)
```

- Freeze high-water independently for event body and audit command/input/output.
- Selection is keyset ordered and capped by rows, stored bytes, decoded bytes, and deadline before materialization.
- Decode/verify and zstd encode outside the write transaction.
- Commit uses a short write transaction. Shadow inserts and checkpoint/counters commit atomically; canonical rows are never rewritten.
- A crash before commit changes neither shadow row nor checkpoint. A crash after commit observes both. Source identity/freeze drift marks the run conflicted and stops writes.
- Resume requires target file identity, config hash, frozen high-water, schema/format compatibility, and rollback artifact to match.

## Dry-run zero-write proof

1. Resolve and validate the copied target before opening SQLite.
2. Snapshot DB, `-wal`, and `-shm`: existence, file identity, size, and nanosecond mtime.
3. Require a clean operator-created single-file copy with no `-wal` or `-shm`; open `mode=ro&immutable=1&query_only=1`. Never call `Initialize`, `PRAGMA wal_checkpoint`, or a writable DSN.
4. Inspect schema, estimate rows/bytes/batches/time/disk, and close all handles.
5. Snapshot the three components again. Any existence/identity/size/mtime change makes dry-run fail; the result must not claim success.

## Target safety

- Require both explicit `--target` and configured `--live-db`/resolved live path.
- Apply no-follow checks to the target and ancestors, then `Abs`/`Clean`; compare configured/resolved live identities with device/inode.
- Reject target or ancestor symlinks, hardlinks (`nlink != 1`), same inode/device as live, non-regular files, missing/unstatable identities, and target sidecars aliasing live sidecars.
- Recheck file identities immediately before every write batch and before rollback.

## Caps and concurrency

- Required positive caps: batch rows, stored bytes, decoded bytes, wall duration, lock duration, and scrub bytes/time.
- Use the codec's stored/decode caps before allocation; never rely only on context cancellation.
- Keep write transactions short; record begin-to-commit duration and fail when lock budget is exceeded.
- Measure DB/WAL/SHM before/peak/after. WAL checkpoint is a separate explicit phase and its mutation is included in evidence.
- Bounded readers must continue to use metadata/index paths; rehearsal may return paused/conflicted instead of starving readers.

## Copied 21.4 GiB rehearsal and rollback evidence

- Input is the operator-created `/private/tmp/traceary-v034-baseline.db` copy, never raw rows in logs or AI packets.
- Preflight records aggregate size, free space, required temporary bytes, rollback artifact digest, target fingerprint, and same-head commit.
- Evidence records rows/bytes/ratio, batch and lock duration distributions, WAL peak, interruption point/resume result, scrub coverage, and rollback digest/integrity.
- If headroom is insufficient, stop before writes; cleanup only regenerateable caches/synthetic artifacts as already authorized.
- Canonical rows in the copied target remain v0.33-readable identity plaintext; rehearsal-only shadow tables may be ignored by older readers. The live store remains untouched and independently verified.

## Security and privacy

- Logs/evidence contain aggregate counters, opaque run/config hashes, table/field enum, durations, and error classes only.
- Never print payloads, commands, IDs/PKs, workspaces, raw target rows, or credentials. Errors identify row class/field without identifier.
- Bound stored and decoded allocation; unknown/partial codec metadata fails closed.
- SQL is parameterized; path errors do not echo sensitive full paths in machine evidence.

## Rollback and release boundary

- Rollback trigger: integrity mismatch, target identity change, cap violation, lock/WAL budget breach, scrub failure, or evidence drift.
- Rollback restores the verified physical backup to the copied rehearsal target only and rechecks digest plus SQLite integrity.
- v0.34 has no activation verb, no compressed-only canonical live write, no live backfill, no search cutover, no compaction/swap, and no canonical deletion.
- v0.35 owns activation after explicit minimum-reader, old-process shutdown, backup, headroom, scrub, and rollback gates.

## Design checkpoint

- Claude Fable 5 was invoked twice with sanitized read-only packet SHA-256 `955b29b833cfdcb16475a7ccb4dd91b2febee8f45ab209e429c6468b786a043a`; both attempts produced empty output after timeout (`empty_output`).
- GPT-5.6 Sol architect and repository explorer were used as the documented Fable alternative. Their design adopts a dedicated rehearsal use case, shadow payload rows that never mutate canonical history, infrastructure-owned codec/checkpoint state, dormant source-freeze triggers, short atomic shadow/checkpoint transactions, a physical rollback artifact, and fail-closed target identity checks.
- Implementation must not narrow these invariants to an in-memory benchmark or a live-store-capable command.

## Post-review safety invariants

- The composition root binds the adapter to the configured canonical live path. `--live-db` is a confirmation value, not a trust root; it must resolve to the configured file identity.
- A run persists device/inode identity and owns a renewable single-writer lease. Resume compares both identity fields, and batch/checkpoint commits require the current lease token.
- `completed` remains source-frozen. Only a cardinality-complete, checksum-valid scrub transitions to `scrubbed` and releases the dormant freeze guards.
- Stored/decoded batch caps commit a non-empty bounded prefix before considering the next row. A single row larger than a hard cap fails explicitly rather than claiming resumable progress.
- WAL bytes have an explicit hard cap. Readiness is a report-only structured result whose `activation_allowed` remains false in v0.34.
- Rollback requires the exact digest recorded by the scrubbed run, rejects target aliases, and verifies integrity plus absence of residual active rehearsal state after restore.
- Preview of an unmigrated raw copy succeeds without mutation and reports `migration_required`; migration installation remains a Run-only target operation.
- Scrub owns the same exclusive persisted lease discipline as Run. A verified prefix is checkpointed before returning at a cumulative cap, and finalization compares scrubbed/changed/shadow counts plus each lane's maximum key.
- Physical rollback is a recovery operation from unleased paused, completed, failed, or scrubbed states; it is not restricted to successful scrub completion.
- The application use case owns preflight sequencing and validates every observable state transition/readiness invariant. SQLite collaborators own only persistence, filesystem identity, codec paging, leases, and atomic progress primitives.
- The configured live path is a mandatory constructor dependency; no production adapter can be created with only an operator-supplied confirmation path.
- DB/WAL/SHM snapshot identities hash device, inode, link count, size, and nanosecond mtime; raw filesystem identifiers are not emitted.
- New-run high-water reads, active-run insertion, and checkpoint creation execute under the adapter's immediate write transaction so the freeze boundary is atomic.
- Readiness gates use explicit unknown/passed/failed status with an evidence timestamp; minimum-reader and old-process shutdown are separate gates.
- Run revalidates configured live identity, target/ancestor identity and sidecars immediately before migration initialization and again before atomic StartRun. Resume permits only regular, non-aliased recovery sidecars and still requires the persisted target inode.
- The adapter constructor rejects an empty/invalid canonical-live dependency; operator `--live-db` is never a fallback trust root.
- Rollback readiness reports scrub as passed only when the recovered run actually reached `scrubbed`; recovery from paused/completed/failed leaves the scrub gate unknown.
- Every persistence boundary revalidates the DB/WAL/SHM component identities immediately before writing. Component files must be regular, non-symlink files with a single hard link; an identity failure returns without attempting a state update through the already-open handle.
- Mutation primitives require a target guard parameter; pause and deferred scrub-lease release fail closed after identity loss, leaving the lease to expire rather than writing through a stale open handle.
