## Requirement and existing boundaries

Existing native hook capture must continue to work without a daemon. Optional live delivery carries derived, redacted metadata only; it cannot carry prompt, code, audit or memory bodies, credentials, terminal input, approval decisions, stop requests or resume instructions. Successful queue admission does not authenticate native origin or establish input readiness.

The current `ObservationMetadata` and `Daemon.Observe` ports in `application/runtime/daemon.go` are untrusted metadata transport. Existing owner-private Unix transport and launch identities are reusable boundaries, not proof that a native hook belongs to a run. `launchEnvironment` in `infrastructure/runtime/pty_unix.go` strips ambient runtime variables and supplies run/generation/epoch hints; matching those values, cwd or a native session ID alone must not create a bound observation.

The earlier [observation ADR](../adr/2026-10-18-desktop-runtime-observations.md#launch-and-binding) proposes per-invocation native hook arguments carrying a descriptor path. It does **not** establish universal native support or adopt a host configuration mechanism. Each host/version must independently demonstrate unique propagation and non-destructive hook composition. A descriptor path is correlation data, not a capability granting input or process control. Unsupported propagation leaves observations unbound and native interaction unknown; a wrapper or cwd/PID fallback is not allowed.

## Conceptual model and responsibility

| Concept | Owner | Invariant |
| --- | --- | --- |
| Derived observation | Domain value | Closed, bounded metadata with no body or effect arm; native source claims remain untrusted |
| Managed binding descriptor | Existing Runtime and immutable execution snapshot | Exact store/worktree/profile host/version/run/generation/epoch and physical source witnesses; never saved-PID authority |
| Native hook context | Existing host CLI adapter | Consume the native payload once; preserve original capture, receipt/spool and stdout/exit decisions |
| Optional delivery | Application port | One total monotonic deadline, bounded in-flight work, no replay or primary-result override |
| Local transport | Existing daemon adapter | Observations endpoint only; no daemon auto-start or management operation |
| Native causal evidence | Versioned adapter and reducer | Descriptor correlation alone cannot reconcile native state or approval visibility |

Domain code owns identity and bounds, not JSON/files/sockets. Application code orchestrates the optional delivery without formatting host decisions or accessing SQL directly. Infrastructure owns no-follow descriptor reads, root locks, atomic publication and wire deadlines. Existing CLI hooks remain responsible for primary capture and host stdout/exit formatting. This adds a capability to the existing object-level services, not a new class per hook or another target Registry.

## Concrete v1 contract for corrected before-code review

This section supersedes the earlier open representation/schema alternatives for the corrected checkpoint; it is not an implementation or native certification claim. It stays within accepted R0, introduces no host configuration installation, and does not accept product-wide architecture changes.

### Descriptor and receiver ownership

Use the immutable full launch snapshot already owned by `application/runtime.Runtime` and persisted in `execution.json`. The explicit selection is exactly the existing `OutputSelection`: epoch/run/generation/worktree/profile. The client never opens a descriptor file. The runtime must match all five selection components, profile host/version and a live, successfully published owned run in this epoch. A saved record, reserved/exited/uncertain run, a persisted PID, or matching environment/native IDs cannot satisfy this check. Before admission, use only the immutable in-memory owned snapshot under Runtime.mu: no file, Registry or subprocess lookup. At consumption, validate the original target with existing `TargetRegistry.Revalidate` outside Runtime.mu under a bounded worker context, then recheck the same owned-run identity/state before retaining the sample. Failure or timeout drops the sample and marks degraded; queued never promised consumption. No file/Registry lookup runs while holding the owner mutex. Unsupported native propagation still yields unbound telemetry, not native evidence.

The new selected intake is owned by the existing Runtime, not the constructor's optional legacy `ObservationReceiver`. It validates before admission and again at consumption, using the existing single daemon observation queue and worker. Production composition already supplies a RuntimeFactory, so the selected intake must work with the real main composition; legacy `observe` with nil receiver remains explicitly unsupported. No second queue, drainer or per-epoch ring is added. Retain at most one bounded last-arrival, **untrusted** sample per live owned run, inside that run's owner, at most 256 samples of 4 KiB each (1 MiB total). Clear it on actual Wait completion, uncertainty, owner shutdown or epoch loss. Replaced/duplicate/out-of-order samples never promote native state and never change input readiness or the core Session. The later reducer may extend this same owner boundary; it must not replay this last-arrival sample as fresh causal evidence.

### Wire schema and version skew

Keep outer protocol version 1 and legacy `observe` unchanged. Add a distinct operation `observe_selected_v1` and one request arm `selected_observation`; never fall back to legacy observe. The closed selected schema is `{selection:{epoch,run,generation,worktree,profile}, metadata:{host,host_version,event_id,kind,native_session_id?,native_turn_id?}}`. The operation name is its version discriminator; do not add a redundant nested version field. Every required field must be present; null, duplicate keys, trailing JSON, unknown fields and mixed arms are invalid. All protocol-1 frames retain the existing non-null/closed-field contract. An unsupported operation (for example observe_selected_v2 with otherwise valid protocol-1 fields) returns unsupported; unknown fields, null or malformed JSON remain invalid. A future operation is never parsed as selected-v1 or replayed as legacy observe. Do not weaken or special-case the common outer decoder. Selection uses canonical domain IDs, not a guessed `target_id`; do not send `TargetID` in the new schema. Host/version must equal the pinned profile. Kinds are exactly `prompt_boundary`, `tool_boundary`, `turn_boundary`, `session_boundary`. Event/native IDs are bounded correlation identifiers, not raw payload/body fields. The encoded selected value is at most 4 KiB, inside the existing 64 KiB frame. Older daemons reject the unknown arm with an uncorrelated invalid response; the new client reports invalid through its unchanged protocol-error mapping, never replays under another schema, and never weakens request-ID validation. No extra capability pre-check is performed outside the total budget.

Only the observations endpoint accepts it. Status advertises `observe_selected_v1` only when a live runtime intake exists; this capability is not native-host certification. The correlated successful ACK is `queued`, with no data/effect/approval arm. It means admission only, not consumption, core commit, native association or visible wait. Validate the entire one-of request and reject mixed response arms across existing SDKs, including the separate lifecycle branch when integrated. Queue pressure preserves existing frame/byte caps and degraded status. Error mapping reuses fixed payload-free invalid/unsupported/changed/not_found/rejected/busy codes; no reply includes submitted identifiers or bodies.

### Operator and hook surface

Public `traceary runtime observe` takes no stdin and no positional arguments. Required flags are `--runtime-dir` (explicit absolute existing root), `--epoch`, `--run`, `--generation`, `--worktree`, `--profile`, `--host`, `--host-version`, `--event-id`, `--kind`; optional native-session/native-turn ID flags are correlation only. No default root, environment selection or native association is inferred. Unknown/malformed flags are operator misuse and nonzero; valid optional delivery outcomes print one closed JSON object `{schema_version:1,outcome,binding:"unbound",authority:"admission_only"}` with zero exit. Outcomes are queued/unavailable/unsafe/unsupported/busy/rejected/changed/not_found/invalid/timeout. No elapsed time is an authority input, no automatic daemon/core bootstrap occurs, and output-write failure remains a CLI error.

Add explicitly opt-in `--observe-runtime-dir`, `--observe-epoch`, `--observe-run`, `--observe-generation`, `--observe-worktree`, `--observe-profile`, `--observe-host-version` to the existing hidden hook group. These flags supply correlation context only; missing/partial/invalid context silently skips optional telemetry without breaking the original hook. Derive host and boundary kind only from the existing supported hook client/action, event correlation from the already acquired spool receipt, and native IDs only from the already consumed payload's supported allowlisted fields. Do not add another stdin consumer. Unsupported clients/actions skip delivery. No flag changes packaged global/per-run settings, argv policy, auth, model or PATH; actual versioned native propagation/composition remains in host leaves.

Run optional delivery only after successful primary capture **and** current spool clearance, before opportunistic backlog drain. The existing no-spool fallback may deliver after the primary succeeds, without creating a new spool. Deferred/failed capture, replayed backlog, and failed spool clear never trigger new optional delivery. Before starting, require remaining packaged-hook time greater than 250 ms plus the existing drain reserve; otherwise skip. The optional path writes nothing to hook stdout/stderr and cannot replace the primary return value, receipt or event IDs.

### Total deadline and failure containment

The single 250 ms monotonic budget starts before optional metadata derivation/root validation and covers connect, handshake, write and ACK. Do not start another full budget per phase. Use the existing bounded transport worker slots; retained work keeps its slot until actual exit. The hook's optional derivation+delivery additionally has one retained slot per process/service, panic containment, immutable borrowed input and cancellation checks. A callback ignoring cancellation cannot spawn unlimited replacements or delay primary completion beyond the caller budget. No automatic retry, delayed background replay or durable observation spool. Server physical target revalidation occurs only at consumption, outside its owner lock under the existing bounded management context; existing connection/queue/worker caps remain effective even when a dependency ignores cancellation.

### Proof and rollback

Test each selection/profile/host/version/state mismatch and physical target exchange, dequeue-time exit/epoch invalidation, bounded latest samples and cleanup without changing core Session or control state. Test new/old mixed-version sockets, every known request/response arm, future operation/null/duplicate/unknown cases, real phase deadlines, blocked callbacks with retained slot, queue pressure, panic/cancel and no replay. Assert metadata inventory/digest/export/forget prefixes stay unchanged after observations because no persisted representation changes. Test hook byte-identical stdout/exit/receipt/core/spool across absent/slow/unsafe/oversize/failure paths, explicit flags only, unsupported propagation unknown, one payload read, no backlog re-delivery and preserved drain reserve. Disable only selected optional delivery on rollback; legacy capture/history/spool/native sessions remain intact. ### Corrected-checkpoint dispositions

Independent round 2 confirmed all prior representation/schema/ownership findings resolved and required no human-gated architecture exception. It identified the admission-time physical lookup as an avoidable latency risk; the contract above now moves physical revalidation to consumption. Queue admission checks only the in-memory exact descriptor; a failed physical revalidation never creates a retained sample or native authority. `queued` is not a validation-success claim. The literal old-daemon outcome is invalid, not a guessed unsupported value.

A new owner-only published marker must be set only after initial SaveLaunch succeeds, because runs currently enter the map before that write finishes. Admission requires this marker; every owned-run uncertainty site clears the marker and sample. Tests must hold SaveLaunch in-flight, then succeed/fail it, and prove no premature admission. The marker and last sample are volatile, never serialized or used to adopt a saved run.

Hook derivation is a closed table: supported canonical clients codex/claude/antigravity/grok only; prompt→prompt_boundary, audit→tool_boundary, transcript→turn_boundary, session start/end→session_boundary, session stop→turn_boundary. Unsupported command/action/client combinations (including gemini/kimi/muse) skip optional delivery, without changing existing capture. Host-specific extension leaves may add proven mappings; a telemetry boundary is never a process-exit fact. Final corrected source-contract adoption belongs to the main author with the raw CHANGES_REQUIRED report and explicit finding triage retained; no third automatic design-review loop or implementation approval is implied. Final independent implementation review remains mandatory.

## Current implementation evidence boundary

Implemented in source: the immutable metadata value and four closed kinds; exact in-memory owned selection/profile admission; post-SaveLaunch publication marker; physical consumption revalidation outside the owner lock; one untrusted sample per live run; clearing on Wait, uncertainty, disable and failed/canceled validation. Observable tests exercise an actually blocked initial journal, owner exit while physical validation is blocked, and a validator that ignores cancellation before returning. The last case reproduced retained stale telemetry and now clears it without changing process/control metadata.

Implemented wire/SDK: closed `observe_selected_v1`, exact names and raw 4 KiB value bounds, all-arm request/ACK guards, actual RuntimeFactory consumption on the shared queue, honest degraded status and one total client budget. Actual socket/finite-PTY tests verify positive delivery, mismatches, old-peer invalid responses, a physically replaced store, a blocked physical metadata lock and queue pressure.

Public CLI and optional hook flags/delivery are now implemented. Not yet certified or complete: host-native association, lifecycle integration qualification, full leaf delivery. The owner capability alone does not make production transport delivery available. The full original leaf scope and remaining independent implementation/CI/security/wave gates remain required.

Unicode long-s aliases were accepted by Go's case folding despite the existing lowercase-key check. The new selected request variant now checks exact names, and bare queued ACKs require exact canonical headers; common version/null/duplicate handling and persisted metadata codecs remain unchanged. These are protocol checks, not native-origin authentication.

## Implemented CLI and opt-in hooks

`traceary runtime observe` requires explicit absolute `--runtime-dir` and epoch/run/generation/worktree/profile/host/host-version/event-id/kind flags; native-session-id/native-turn-id are optional. It reads no stdin/positional payload and infers no environment/default root. Valid optional delivery prints exactly schema_version/outcome/binding/authority JSON, always unbound and admission_only; operator misuse and output failure remain errors. Separate-process actual main/daemon tests with a finite fixture verify queued output, no HOME/core creation and preserved original PTY output/exit.

The hidden hook group accepts explicit observe-runtime-dir/epoch/run/generation/worktree/profile/host-version flags. These only append context to an existing invocation: no packaged/global/per-run configuration, auth/model/PATH or second handler is installed. Actual native composition/propagation remains unverified. Source argument-composition fixtures verify one original handler/capture and unchanged stdout/exit/spool; they do not certify host configuration merging.

Delivery follows primary success and current spool clearance, before backlog drain. Failure/defer/clear failure/replay do not deliver; insufficient 250 ms plus drain reserve skips telemetry. Existing no-spool fallback delivers only after primary success. One process-wide slot retains derivation and client work through actual return, including cancellation-ignoring dependencies; panic/error/timeout cannot replace the primary result/output or create replacement workers. The already-acquired immutable payload is borrowed, not read from stdin again. Event correlation is the acquired spool receipt. Optional native IDs are untrusted string claims from codex thread_id or other supported hosts' session_id and optional turn_id; invalid values are omitted, never treated as native association evidence.
