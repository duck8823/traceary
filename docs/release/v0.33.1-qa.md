# v0.33.1 release-candidate verification boundary

[日本語](./v0.33.1-qa.ja.md)

## Scope

v0.33.1 is a patch release for collision-safe hook delivery identity, deterministic one-shot exit behavior, exclusive and bounded usage evidence, explicit unavailable-observation reporting, Kimi platform policy, and report lineage documentation. It includes #1576, #1577, #1578, #1579, #1580, #1581, and #1582. It does not change the privacy boundary: Traceary does not enable network interception, billing-dashboard scraping, or prompt/response-body capture for this release.

## Feature QA summary

Each merged feature PR was verified with `go build ./...`, `go test ./...`, `go tool golangci-lint run`, CI, and an independent Codex verifier review. Any FAIL findings were fixed and the affected changes were re-verified to PASS.

- **Hook identity and one-shot behavior (#1576):** regression coverage exercised delimiter-bearing delivery identities, persisted-ledger separation, clean and failed child exits, signals, cancellation and timeout races, start and stream failures, and nested session-end suppression.
- **Codex and bundle exclusivity (#1580, #1581):** rollout coverage exercised filename boundaries, conflicting metadata, and ambiguous matches. Bundle coverage exercised additive claims, replay, conflict policies, malformed metadata, and attempts to re-key an existing observation.
- **Kimi capture and platform policy (#1577, #1579):** bounded-source coverage exercised oversized wire files, indexes, and JSONL lines without content leakage. Platform coverage verified the Unix implementation and the explicit fail-closed unsupported-platform adapter.
- **Unavailable reporting and lineage documentation (#1578, #1582):** report, CLI, MCP schema, schema-budget, and bilingual documentation checks exercised unavailable-observation classification, source lineage, coverage, supersession, run-fact deduplication, and one-shot terminal contracts.

#1576 and #1579 also passed `GOOS=windows` cross-build verification for their fallback and build-tag boundaries. These results are bounded feature checks. They do not establish live host availability or convert unavailable or conflicting evidence into zero usage.

## Candidate checks

Release preparation must verify the version and every supported host manifest, bilingual documentation, the Go build/test/lint suite, packaged integrations, release-manifest consistency, and whitespace errors. It must also repeat the hook identity, one-shot exit, rollout and bundle exclusivity, Kimi bounds and platform, unavailable-reporting, and documentation checks above when the release candidate changes their implementation. The tagged workflow repeats release-manifest verification before building artifacts.

The candidate checks do not assert live availability for every host. Unavailable, conflicting, ambiguous, oversized, or unsupported-platform evidence remains explicitly classified or fails closed; it is not converted into a zero counter, fabricated sample, or inferred completion.

## Artifact and Formula ownership

`Formula/traceary.rb` is generated from tagged release artifacts by the release workflow. This release-preparation PR updates neither Formula URLs nor checksums: before the tag, those artifact values do not exist. The workflow owns generation, checksum verification, and the follow-up Formula commit.

## Post-merge release gate

Before creating `v0.33.1`, run the release QA checks against the merged candidate, file and resolve any release-blocking follow-ups, then create the tag only with explicit release authorization.
