# v0.33.0 リリースQA

[English](./v0.33.0-qa.md)

## 対象

このリリースでは、live user storeを読まず、event body、prompt、response、cursor、workspace、spool payloadを公開せずに、bounded retrievalとscalable local-history accessを検証します。

## 証跡

- [multi-GiB evidence artifact](./v0.33.0-multigib-evidence.json) は
  `go run ./cmd/repo-tooling release verify-body-free-evidence --input docs/release/v0.33.0-multigib-evidence.json` に合格します。
- private synthetic probeは、固定250 msのrelease gateに対してPhase-A p95
  0.079708 msを記録しました。
- artifactはcopy上のmigration 31–34、projection rollback互換性、FTS progress、bounded huge-body retrieval、MCP aggregate response behaviorも記録します。

## リリース準備の検証

release candidateでは次を実行しました。

```sh
go run ./cmd/repo-tooling release verify-changelog
python3 scripts/verify_release_manifests.py
go run ./cmd/repo-tooling integrations verify
go run ./cmd/repo-tooling docs verify-i18n
go run ./cmd/repo-tooling docs verify-landing
go run ./cmd/repo-tooling docs verify-antigravity-status
go test ./presentation/cli -run 'TestCockpitDogfood' -count=1
go build ./...
go tool golangci-lint run
```

full suiteはCIでgreenです。#1586で対象hook-runtime testを隔離するまでは、localのfull suiteをtest専用の`TRACEARY_HOOK_STATE_DIR`なしで実行してはいけません。未隔離のtestがreal queueのhook deliveryをreplayする可能性があります。

## リリース境界

migration 31–34はadditiveであり、既存event/session dataを削除せずにmetadata access pathを維持します。tagged workflowはartifact公開前にstrict evidence verifierを実行し、GitHub Release成功後にだけ#1550をcloseしなければなりません。

syntheticなmigration fixtureは130 event（256 MiBのrowを8件を含む）です。そのため任意の実store row数に対するbackfill throughputではなく、correctnessとbounded behaviorを証明します。bounded-hugeのPhase-C p95は観測値でありrelease thresholdを持ちません。
