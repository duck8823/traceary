# v0.33.1 release candidate の検証境界

[English](./v0.33.1-qa.md)

## 対象

v0.33.1 は、衝突しないフック配信 ID、決定的な one-shot 終了動作、排他的で境界付きの使用量 evidence、利用不能 observation の明示的なレポート、Kimi platform policy、report lineage の文書化を対象とする patch release です。#1576、#1577、#1578、#1579、#1580、#1581、#1582 を含みます。このリリースでは privacy boundary を変更しません。Traceary はネットワーク傍受、billing dashboard のスクレイピング、prompt/response body の capture を有効化しません。

## 機能 QA 概要

merge 済みの各 feature PR は、`go build ./...`、`go test ./...`、`go tool golangci-lint run`、CI、独立した Codex verifier review で検証しました。FAIL の指摘はすべて修正し、影響する変更を再検証して PASS を確認しました。

- **フック ID と one-shot 動作 (#1576):** 区切り文字を含む delivery identity、永続化 ledger 上の分離、子プロセスの正常終了と異常終了、signal、cancel と timeout の競合、start と stream の失敗、ネストした session-end の抑止を回帰テストで確認しました。
- **Codex と bundle の排他性 (#1580, #1581):** rollout のテストでファイル名境界、競合する metadata、複数候補の一致を確認しました。bundle のテストで加算型 claim、replay、conflict policy、不正な metadata、既存 observation の re-key 試行を確認しました。
- **Kimi capture と platform policy (#1577, #1579):** bounded-source のテストで、内容を露出せずにサイズ超過の wire file、index、JSONL 行を処理することを確認しました。platform のテストで Unix 実装と、未対応 platform で明示的に fail closed する adapter を確認しました。
- **利用不能レポートと lineage 文書 (#1578, #1582):** report、CLI、MCP schema、schema budget、日英文書の検証で、利用不能 observation の分類、source lineage、coverage、supersession、run-fact deduplication、one-shot の終了契約を確認しました。

#1576 と #1579 では、fallback と build-tag の境界について `GOOS=windows` cross-build verification も PASS しました。これらは境界付きの feature check です。live host の可用性を立証するものではなく、利用不能または競合する evidence を使用量ゼロへ変換するものでもありません。

## Candidate check

リリース準備では、version、対応する全 host manifest、日英文書、Go の build/test/lint suite、packaged integration、release manifest の整合性、whitespace error を検証する必要があります。release candidate が実装を変更した場合は、上記のフック ID、one-shot 終了、rollout と bundle の排他性、Kimi の境界と platform、利用不能レポート、文書の各検証も再実行する必要があります。tagged workflow は artifact を build する前に release manifest の検証を再実行します。

candidate check は、すべての host が live で利用可能だとは主張しません。利用不能、競合、曖昧、サイズ超過、未対応 platform の evidence は、明示的に分類されるか fail closed します。ゼロ counter、捏造された sample、推測による完了状態には変換しません。

## Artifact と Formula の所有者

`Formula/traceary.rb` は、release workflow が tag 付き release artifact から生成します。この release-preparation PR は Formula の URL も checksum も更新しません。tag の作成前には、それらの artifact value は存在しないためです。生成、checksum verification、その後の Formula commit は workflow が所有します。

## マージ後の release gate

`v0.33.1` を作成する前に、merge 済み candidate に対して release QA check を実行し、release を block する follow-up を起票して解決します。その後、明示的な release authorization がある場合に限って tag を作成します。
