## Scope

v0.32.1 is a patch release for post-upgrade host-plugin readiness, large-store safeguards, and body-free usage diagnostics. It includes #1519, #1521, #1522, #1523, #1532, #1539, #1540, and #1542. It does not change the privacy boundary: Traceary does not enable network interception, billing-dashboard scraping, or prompt/response-body capture for this release.

## Large-store and Grok refresh QA

The merged feature QA recorded the following bounded feature-test evidence:

- **Bounded doctor (#1539):** a sparse large-store fixture exercised the completed `metadata_only_large_store` result without SQLite, event, payload, or spool reads. Operators must use the [bounded doctor guide](../operations/large-store-doctor.md) for the 2 GiB threshold, contention handling, and follow-up boundary.
- **Bounded metadata list (#1542):** 4 GiB sparse-store, query-plan, busy/lock, and metadata-projection coverage exercised `traceary list --limit 1 --fields ts,kind --color never`. Operators must use the [bounded metadata-list guide](../operations/large-store-list.md); other list shapes intentionally remain on the normal read path.
- **Grok local-repository refresh (#1540):** clean-home installation, migration-contract, and doctor coverage exercised the canonical package path and the explicit source-bounded migration. Follow the [Grok plugin guide](../integrations/grok-plugin.md#local-repository-identity-migration) rather than removing an ambiguous legacy identity manually.

These results are bounded feature checks. They do not establish live-store latency under active use, claim that a live store is free of writer contention, or show that every installed host is currently available.

## Candidate checks

Release preparation must verify the version and every supported host manifest, bilingual documentation, the Go build/test/lint suite, packaged integrations, release-manifest consistency, and whitespace errors. It must also repeat the bounded doctor, bounded metadata-list, and Grok refresh operating checks above when the release candidate changes their implementation. The tagged workflow repeats release-manifest verification before building artifacts.

The candidate checks do not assert live availability for every host. A host with unavailable or partial body-free evidence remains explicitly classified by doctor and report output; it is not converted into a zero counter or inferred completion.

## Artifact and Formula ownership

`Formula/traceary.rb` is generated from tagged release artifacts by the release workflow. This release-preparation PR updates neither Formula URLs nor checksums: before the tag, those artifact values do not exist. The workflow owns generation, checksum verification, and the follow-up Formula commit.

## Review limitation

The contributing PRs received deterministic validation and independent local review. The requested external independent reviewer topology did not return a valid final result; the maintainer explicitly accepted that residual risk for the merged PRs. This record does not represent external-review coverage as complete.

## Post-merge release gate

Before creating `v0.32.1`, run refreshed-host dogfooding and the release QA checks against the merged candidate, file and resolve any release-blocking follow-ups, then create the tag only with explicit release authorization.
